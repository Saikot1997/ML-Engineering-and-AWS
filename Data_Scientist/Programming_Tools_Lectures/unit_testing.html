🧪 Unit Testing, TDD ও GDPR

কোড পরীক্ষার পদ্ধতি এবং ডেটা সুরক্ষার আইন — সব কিছু বাংলায়, উদাহরণ ও ডায়াগ্রামসহ

🧪
অংশ ক: Unit Testing
কোডের প্রতিটি অংশ সঠিকভাবে পরীক্ষা করা
🔬 Unit Testing কী?

Unit Testing মানে আপনার কোডের ছোট ছোট অংশ (unit) — সাধারণত একটি function বা class — আলাদাভাবে পরীক্ষা করা যে সেটি সঠিকভাবে কাজ করছে কিনা।

🔑 মূল ধারণা: একটি unit-কে নির্দিষ্ট input দাও → দেখো সে সঠিক output দিচ্ছে কিনা।

Unit Testing vs Integration Testing

🔬

Unit Testing

একটি function/class আলাদাভাবে পরীক্ষা। শুধু নিজের ডেটা। দ্রুত ও সহজ।

উদাহরণ: গাড়ির বাল্ব একা কাজ করছে কিনা

🔗

Integration Testing

একাধিক অংশ একসাথে কাজ করে কিনা। Real database/network। ধীর ও জটিল।

উদাহরণ: বোতাম চাপলে হেডলাইট জ্বলে কিনা

🚗 গাড়ির উদাহরণ:
Unit test: বাল্ব ভালো? বোতাম কাজ করছে? তার সঠিক? ব্যাটারি ঠিক আছে?
Integration test: বোতাম চাপলে কি আলো জ্বলে?

Unit Testing-এর সুবিধা ও অসুবিধা

✅ সুবিধা

  • সময় বাঁচায়: Bug শুরুতেই ধরা পড়ে, পরে খুঁজতে হয় না
  • কোড পরিবর্তন নিরাপদ: নতুন কিছু যোগ করলে পুরনোটা ঠিক আছে কিনা জানা যায়
  • Documentation: unit test পড়লে function কী করে বোঝা যায়
  • কোড মান উন্নত: test লিখতে গেলে ভালো করে ভাবতে হয়

❌ অসুবিধা

  • সব ক্ষেত্র cover করা অসম্ভব
  • Integration সমস্যা ধরে না
  • প্রতিটি function-এর জন্য test লিখতে হয়
  • অতিরিক্ত সময় লাগে
⚗️ pytest দিয়ে Automated Testing

pytest হলো Python-এর একটি জনপ্রিয় testing framework যা স্বয়ংক্রিয়ভাবে test run করে বিস্তারিত report দেয়।

মূল নিয়মগুলো:

  • Test file-এর নাম: test_কিছু.py বা কিছু_test.py
  • Test function শুরু হবে test_ দিয়ে — নইলে pytest দেখবে না!
  • Check করতে assert ব্যবহার করুন

Fixtures — বারবার একই object তৈরি না করা

Fixture হলো একটি helper function যা প্রতিটি test-এর আগে দরকারি object তৈরি করে দেয়। Code duplicate হয় না।

wallet.py class Wallet(object): def __init__(self, initial_amount=0): self.balance = initial_amount # ব্যালেন্স সংরক্ষণ def spend_cash(self, amount): if self.balance < amount: raise InsufficientAmount('ব্যালেন্স কম!') self.balance -= amount def add_cash(self, amount): self.balance += amount class InsufficientAmount(Exception): pass # Custom exception — নিজস্ব error type

🔄 TDD কী এবং কেন?

TDD (Test Driven Development) মানে হলো আগে test লিখুন, তারপর সেই test pass করানোর জন্য code লিখুন। Kent Beck ৯০-এর দশকে এটি জনপ্রিয় করেন।

সাধারণ কোডিং: Code লিখি → Test করি → Bug পাই → Fix করি

TDD: Test লিখি (fail) → Code লিখি (pass) → Code সুন্দর করি → পরবর্তী feature

TDD চক্র: Red → Green → Refactor → Repeat

🔴

Red

Test লিখুন। এখনো code নেই তাই test fail করবে।

→
🟢

Green

Minimum code লিখুন শুধু test pass করাতে।

→
🔵

Refactor

Code সুন্দর ও দক্ষ করুন। Test pass রাখুন।

→
🔁

Repeat

নতুন feature-এর জন্য আবার শুরু থেকে।

TDD উদাহরণ: Sorting Function

🔴
Step 1 — Red: আগে test লিখুন (code এখনো নেই!)
# test_sort.py — sort.py এখনো বানাইনি, তবুও test লিখছি import sort # এই module নেই → ImportError → RED ✓ def test_ascending_sorting(): assert sort.sorting([3, 1, 4, 1, 5]) == [1, 1, 3, 4, 5] def test_sorting_decreasing(): assert sort.sorting([3, 1, 4], ascending=False) == [4, 3, 1]
এখন pytest চালালে fail হবে কারণ sort.py নেই — এটাই expected!
🟢
Step 2 — Green: Minimum code লিখুন শুধু test pass করাতে
# sort.py — সর্বনিম্ন implementation, elegant হতে হবে না def sorting(list_test, ascending=True): return sorted(list_test) if ascending else sorted(list_test, reverse=True)
test_ascending_sorting PASSED test_sorting_decreasing PASSED 2 passed ✅
🔵
Step 3 — Refactor: Code উন্নত করুন (test pass রেখে) এই উদাহরণে function এত সহজ যে refactor দরকার নেই। জটিল code-এ এখানে comments, error handling, optimization করা হয়। Test চালিয়ে নিশ্চিত করুন সব ঠিক আছে।

⚖️ GDPR কী?

GDPR = General Data Protection Regulation। ইউরোপীয় ইউনিয়নের ডেটা সুরক্ষা আইন, ২০১৮ সালের ২৫ মে থেকে কার্যকর। এটি বিশ্বের সবচেয়ে কঠোর ডেটা সুরক্ষা আইন।

🌍 এই আইন কাদের জন্য?
EU-এর ২৭টি দেশের সব সংস্থা — ছোট-বড়, সরকারি-বেসরকারি। এমনকি EU-এর বাইরে থেকে EU নাগরিকদের ডেটা ব্যবহার করলেও GDPR মানতে হবে!

GDPR-এর তিনটি মূল স্তম্ভ

Personal Data কী? Sensitive Data কী?

🔵 Personal Data (ব্যক্তিগত তথ্য)

যা দিয়ে একজনকে চিহ্নিত করা যায়:

  • নাম, ছবি, ইমেইল
  • ফোন নম্বর, IP address
  • জাতীয় পরিচয় নম্বর
  • Location data

🔴 Sensitive Data (বিশেষ সুরক্ষা)

অতিরিক্ত আইনি সুরক্ষা পায়:

  • স্বাস্থ্য ও চিকিৎসা তথ্য
  • ধর্মীয় বিশ্বাস
  • রাজনৈতিক মত
  • জাতিগত পরিচয়, যৌন অভিমুখিতা
  • বায়োমেট্রিক ডেটা
🛡️ GDPR-এ ব্যক্তির ৮টি অধিকার
① জানার অধিকার (Art. 15)

কোম্পানি আমার কী তথ্য রাখছে, কেন, কার সাথে শেয়ার করছে — জানার অধিকার।

② অ্যাক্সেসের অধিকার (Art. 15)

চাইলে ১ মাসের মধ্যে আমার সব ডেটার কপি পাওয়ার অধিকার।

③ সংশোধনের অধিকার (Art. 16)

ভুল তথ্য সংশোধন বা আপডেট করতে বলার অধিকার।

④ মুছে দেওয়ার অধিকার (Art. 17)

"ভুলে যাওয়ার অধিকার" — database থেকে আমার ডেটা মুছতে বলার অধিকার।

⑤ সীমিত ব্যবহারের অধিকার (Art. 18)

ডেটা মুছার আগে ব্যবহার সীমিত করতে বলার অধিকার।

⑥ ডেটা বহনের অধিকার (Art. 20)

আমার ডেটা নিয়ে অন্য service-এ যাওয়ার অধিকার (data portability)।

⑦ আপত্তির অধিকার (Art. 21)

নির্দিষ্ট উদ্দেশ্যে আমার ডেটা ব্যবহারে "না" বলার অধিকার।

⑧ স্বয়ংক্রিয় সিদ্ধান্তের বিরুদ্ধে (Art. 22)

শুধু Algorithm-এর সিদ্ধান্তে অস্বীকৃতি জানাতে মানুষের হস্তক্ষেপ চাওয়ার অধিকার।

🏗️ Privacy by Design ও GDPR-এর মূলনীতি

Privacy by Design মানে product বা service তৈরির শুরু থেকেই ডেটা সুরক্ষা মাথায় রাখা — পরে add করা নয় (GDPR Article 25)।

GDPR-এর ৬টি মূলনীতি — Privacy by Design-এর কেন্দ্রে

Pseudonymization বনাম Anonymization

🔄 Pseudonymization (ছদ্মনামকরণ)

  • পরিচয় লুকানো হয়, মূলটা থাকে
  • Reversible — ফেরানো সম্ভব
  • GDPR এখনো প্রযোজ্য
  • উদাহরণ: "রহিম" → "User_2234"
  • Hash function, Encryption

🗑️ Anonymization (বেনামীকরণ)

  • পরিচয় সম্পূর্ণ মুছে দেওয়া
  • Irreversible — ফেরানো অসম্ভব
  • GDPR আর প্রযোজ্য নয়!
  • উদাহরণ: জন্মসাল শুধু বছর রাখা
  • Randomization, Generalization

British Airways (UK, 2018) — Cyberattack-এ গ্রাহকদের ডেটা চুরি। মৌলিক নিরাপত্তা ব্যবস্থা না রাখায় জরিমানা।

প্রতিষ্ঠানের বাধ্যবাধকতা

  • সম্মতি সংগ্রহ: ১৬ বছরের বেশি ব্যক্তির স্পষ্ট সম্মতি লাগবে। অপ্রাপ্তবয়স্কের ক্ষেত্রে অভিভাবকের।
  • Processing Register: কোন ডেটা কীভাবে ব্যবহার হচ্ছে — সব রেকর্ড রাখতে হবে।
  • ৭২ ঘণ্টার নিয়ম: ডেটা লঙ্ঘন হলে ৭২ ঘণ্টার মধ্যে নিয়ন্ত্রক সংস্থাকে জানাতে হবে।
  • DPO নিয়োগ: বড় প্রতিষ্ঠানে Data Protection Officer রাখতে হবে।
  • DPIA: উচ্চ-ঝুঁকির processing-এ প্রভাব মূল্যায়ন করতে হবে।
⚠️ DPO-এর কাজ: ডেটা নিয়ন্ত্রক, প্রসেসর ও কর্মীদের পরামর্শ দেওয়া → GDPR মেনে চলা হচ্ছে কিনা তদারক করা → DPIA-তে সহায়তা → নিয়ন্ত্রক সংস্থার সাথে যোগাযোগ।
🤖 AI ও নৈতিকতা

Deepfake কী?

Deepfake শব্দটি এসেছে "deep learning" + "fake" থেকে (২০১৭)। এটি AI দিয়ে কারও মুখ বা কণ্ঠ অন্য ভিডিওতে বসানোর প্রযুক্তি। GDPR-এর সরাসরি লঙ্ঘন যদি সম্মতি ছাড়া তৈরি হয়।

Algorithm Bias (পক্ষপাতমূলক সিদ্ধান্ত)

🎯 উদাহরণ: একটি কোম্পানি AI দিয়ে CV বাছাই করে। যদি কোম্পানির ৯০% কর্মী পুরুষ হয়, AI শিখবে পুরুষ = ভালো candidate। ফলে নারী বা সংখ্যালঘুদের CV বাদ পড়বে — এটাই Algorithm Bias। একটি biased database → biased result।

Self-driving Car — নৈতিক দ্বিধা

Self-driving Car-এর Trolley Problem — কে বাঁচাবে? AI কীভাবে সিদ্ধান্ত নেবে?

CNRS ও MIT-এর গবেষকরা moralmachine.net ওয়েবসাইট তৈরি করেছেন এই নৈতিক প্রশ্নে মানুষের মতামত সংগ্রহ করতে।

💡 GDPR ও AI:
  • AI সিদ্ধান্তে প্রভাবিত ব্যক্তির মানব পর্যালোচনার অধিকার আছে (Art. 22)
  • Algorithm-এর bias বিশ্লেষণ ও প্রকাশ করতে হবে
  • AI-এর সিদ্ধান্ত ব্যাখ্যাযোগ্য (Explainable AI) হওয়া দরকার

প্রশ্ন ১: একটি JWT token expire হয়ে গেছে — সার্ভার কী করবে?
উত্তর দেখুন

401 বা 403 error দেবে। Client-কে নতুন করে login করতে বলবে — নতুন token নিতে হবে।

প্রশ্ন ২: TDD-র Green phase-এ কী করা হয়?
উত্তর দেখুন

শুধু test pass করানোর জন্য সর্বনিম্ন code লেখা। সুন্দর না হলেও চলবে — optimization এখানে নয়।

প্রশ্ন ৩: HTTPS ছাড়া Basic Auth কতটা বিপজ্জনক?
উত্তর দেখুন

অত্যন্ত বিপজ্জনক। Base64 এনক্রিপশন নয় — যে কেউ সহজে decode করতে পারে। নেটওয়ার্কে intercept হলে password সাথে সাথে চুরি।

প্রশ্ন ৪: Anonymization ও Pseudonymization-এর পার্থক্য কী?
উত্তর দেখুন

Pseudonymization reversible — মূল ডেটায় ফিরে যাওয়া সম্ভব, GDPR প্রযোজ্য। Anonymization irreversible — পরিচয় বের করা অসম্ভব, GDPR আর প্রযোজ্য নয়।

প্রশ্ন ৫: GDPR লঙ্ঘনে সর্বোচ্চ কত জরিমানা?
উত্তর দেখুন

€২০ মিলিয়ন অথবা কোম্পানির বার্ষিক বৈশ্বিক টার্নওভারের ৪% — দুটির মধ্যে যেটি বেশি সেটি।

প্রশ্ন ৬: pytest-এ test function-এর নাম কী দিয়ে শুরু হতে হবে?
উত্তর দেখুন

test_ দিয়ে — যেমন test_total(), test_login()। নইলে pytest সেই function চালাবে না।
