🔥 Spark কী এবং কেন দরকার?

💡

গল্প দিয়ে বুঝি: তোমার কাছে ১ কোটি রেকর্ডের ডেটা আছে। সাধারণ Python (Pandas) দিয়ে কাজ করলে সব ডেটা একটা কম্পিউটারের RAM-এ লোড হবে। RAM কম থাকলে কম্পিউটার হ্যাং করবে। Spark এই সমস্যার সমাধান করে — অনেক কম্পিউটার একসাথে কাজ করে।

Apache Spark হলো একটি open-source distributed computing framework। এটা এমন একটা সিস্টেম যেখানে অনেকগুলো কম্পিউটার একসাথে কাজ করে বড় ডেটা প্রসেস করতে পারে।

Hadoop বনাম Spark

Hadoop: পুরনো প্রযুক্তি। ডেটা ডিস্কে সংরক্ষণ হয়। প্রতিটা অপারেশনের পর ডিস্কে লেখা হয় — তাই ধীর।

Spark: ডেটা RAM-এ রাখে। RAM অনেক দ্রুত। Spark Hadoop-এর চেয়ে ১০০ গুণ পর্যন্ত দ্রুত হতে পারে!

🏗️ Spark Architecture — ভিতরে কী আছে?

🎯

সহজ উপমা: ধরো একটা রেস্তোরাঁ। Driver = ম্যানেজার (নির্দেশ দেয়, রান্না করে না)। Executorগুলো = রাঁধুনি (আসল কাজ করে)। Cluster Manager = সুপারভাইজার (কে কোথায় কাজ করবে ঠিক করে)।

Driver

  • আমাদের কোড চালায়
  • সব Executor-দের নির্দেশ দেয়
  • কোন Executor কোন কাজ করবে ঠিক করে (task scheduling)
  • SparkSession/SparkContext এখানে থাকে

Executor

  • Driver-এর নির্দেশ অনুযায়ী আসল কাজ করে
  • ডেটার একটা অংশ নিজের কাছে রাখে (partition)
  • কাজ শেষে Driver-কে জানায়

অনুশীলন ১.১ — SparkSession Factory (MLOps Best Practice)
মাঝারি

বাস্তব MLOps প্রজেক্টে SparkSession একটি utility function-এ রাখা হয়। get_spark_session(app_name, master, log_level) function তৈরি করো যা:

  1. আগে থেকে session থাকলে সেটাই return করে (নতুন তৈরি করে না)
  2. Executor memory 2GB সেট করে
  3. Adaptive Query Execution চালু রাখে
💡 সমাধান দেখো
from pyspark.sql import SparkSession
import logging

def get_spark_session(
    app_name: str,
    master: str = "local[*]",
    log_level: str = "ERROR"
) -> SparkSession:
    """Configured SparkSession তৈরি অথবা বিদ্যমানটা return করো।"""
    existing = SparkSession.getActiveSession()
    if existing is not None:
        return existing
    spark = (SparkSession.builder
        .appName(app_name)
        .master(master)
        .config("spark.executor.memory", "2g")
        .config("spark.driver.memory", "2g")
        .config("spark.sql.adaptive.enabled", "true")
        .getOrCreate()
    )
    spark.sparkContext.setLogLevel(log_level)
    return spark

spark = get_spark_session("PredictiveMaintenance-MLOps", "local[4]")
print(f"Session: {spark.conf.get('spark.app.name')}")

Data Structures in Spark — RDD
Spark-এর সবচেয়ে মৌলিক data structure — বিতরণকৃত ডেটার ভিত্তি

📦 RDD কী? — Resilient Distributed Dataset

🧩

RDD-র পূর্ণ অর্থ:
Resilient — মজবুত (কোনো কম্পিউটার বিকল হলে নিজে ঠিক হয়)
Distributed — বিতরণকৃত (অনেক কম্পিউটারে ছড়িয়ে আছে)
Dataset — ডেটার সংগ্রহ

RDD হলো Spark-এর সবচেয়ে মৌলিক data structure। Python-এর list-এর মতোই, কিন্তু একটা নয় অনেক কম্পিউটারে ভাগ হয়ে থাকে। ডেটার প্রতিটা অংশকে Partition (পার্টিশন) বলে।

চিত্র ২.১ — Python List থেকে RDD: ডেটা কীভাবে ভাগ হয়
from pyspark import SparkContext, SparkConf

conf = SparkConf().setAppName("RDD শিক্ষা").setMaster("local[*]")
sc = SparkContext(conf=conf)

# পদ্ধতি ১: List থেকে RDD
rdd1 = sc.parallelize([1, 2, 3, 4, 5])

# পদ্ধতি ২: Range থেকে, নির্দিষ্ট Partition সংখ্যায়
rdd2 = sc.parallelize(range(50), 3)   # 50টা সংখ্যা, 3 partition-এ

# পদ্ধতি ৩: ফাইল থেকে RDD
rdd3 = sc.textFile("data.txt")

# Partition সংখ্যা
print(rdd2.getNumPartitions())  # 3

# ডেটা দেখো (সব ডেটা Driver-এ আনে — বড় ডেটায় বিপদজনক!)
print(rdd1.collect())          # [1, 2, 3, 4, 5]

# নিরাপদ পদ্ধতি — প্রথম কয়েকটা দেখো
print(rdd2.take(5))            # [0, 1, 2, 3, 4]

# Partition অনুযায়ী ডেটা দেখো
print(rdd2.glom().collect())   # [[0..15], [16..32], [33..49]]
⚠️

collect() সতর্কতা: collect() সব ডেটা Driver machine-এ নিয়ে আসে। ১ কোটি রেকর্ডের ডেটায় Driver-এর RAM ফুরিয়ে যাবে। সবসময় take(n) ব্যবহার করো।

🗺️ MapReduce — Spark-এর হিসাব করার পদ্ধতি

🍕

সহজ উপমা: ৩টা পিৎজার দোকান, প্রতিটায় আলাদা রাঁধুনি।
Map Phase: প্রতিটা রাঁধুনি তার নিজের পিৎজা কাটে (একই কাজ আলাদাভাবে)।
Reduce Phase: সব পিৎজার টুকরো গুনে মোট বের করে।

চিত্র ২.২ — Map Phase: সব Executor একসাথে কাজ করে
# ── map: প্রতিটা element-এ function চালাও ──
rdd = sc.parallelize([1, 2, 3, 4, 5])
squared = rdd.map(lambda x: x ** 2)
print(squared.collect())  # [1, 4, 9, 16, 25]

# ── flatMap: function list return করলে সেটা সমতল করো ──
rdd2 = sc.parallelize([1, 2, 3])
# map দিয়ে: [[1, 2], [2, 4], [3, 6]] — list of lists
print(rdd2.map(lambda x: [x, x*2]).collect())
# flatMap দিয়ে: [1, 2, 2, 4, 3, 6] — একটা flat list
print(rdd2.flatMap(lambda x: [x, x*2]).collect())

# ── mapPartitions: পুরো partition-এ function চালাও ──
rdd3 = sc.parallelize(range(9), 3)

def partition_sum(partition):
    return [sum(partition)]

print(rdd3.mapPartitions(partition_sum).collect())
# partition 0:[0,1,2]→3, partition 1:[3,4,5]→12, partition 2:[6,7,8]→21
# Output: [3, 12, 21]

# ── mapValues / flatMapValues (PairRDD-তে) ──
pair_rdd = sc.parallelize([("a", 1), ("b", 2), ("c", 3)])
print(pair_rdd.mapValues(lambda x: x * 2).collect())
# [('a', 2), ('b', 4), ('c', 6)]

# ── reduce: পুরো RDD একটা value-তে পরিণত করো ──
rdd_nums = sc.parallelize(range(10))
total = rdd_nums.reduce(lambda x, y: x + y)
print(total)  # 45

# ── reduceByKey: key অনুযায়ী reduce ──
fruit_rdd = sc.parallelize([
    ("আম", 3), ("কলা", 5), ("আম", 2), ("কলা", 1)
])
result = fruit_rdd.reduceByKey(lambda x, y: x + y)
print(result.collect())  # [('আম', 5), ('কলা', 6)]
📐

Reduce function-এর নিয়ম: অবশ্যই commutative (f(a,b)=f(b,a)) ও associative (f(f(a,b),c)=f(a,f(b,c))) হতে হবে। যোগ (+) ও গুণ (×) এই শর্ত পূরণ করে। বিয়োগ (-) ও ভাগ (÷) করে না।

🔗 Shared Variables — Accumulator ও Broadcast

⚠️

সমস্যা: Cluster-এ কাজ করার সময় Driver-এর variable আর Executor-এর variable আলাদা! সাধারণ Python variable Executor-এ পরিবর্তন করলে Driver জানে না।

# ❌ এটা কাজ করে না!
count = 0
rdd = sc.parallelize([1, 2, 3])
rdd.foreach(lambda x: None)  # count কখনো বদলাবে না Driver-এ
print(count)  # 0 — Executor-এ চেঞ্জ হয়, Driver-এ না

# ✅ Accumulator: Executor থেকে Driver-এ মান পাঠাও
count = sc.accumulator(0)

def add_count(x):
    count.add(x)

rdd = sc.parallelize([1, 2, 3, 4, 5])
rdd.foreach(add_count)
print(count.value)  # 15

# ✅ Broadcast: বড় ডেটা একবার সব Executor-এ পাঠাও
# যেমন: বড় lookup table, model weights
lookup = {"BDT": 120, "USD": 1, "EUR": 1.08}
bc_lookup = sc.broadcast(lookup)

currencies = sc.parallelize([("BDT", 1000), ("USD", 50)])
in_usd = currencies.map(
    lambda x: (x[0], x[1] / bc_lookup.value[x[0]])
)
print(in_usd.collect())

# ধাপ ২: ছোট শব্দ সরাও

🔥 Architecture ও Core Concepts
Q1: Spark-এ Driver এবং Executor-এর পার্থক্য কী? উভয়ের কাজ ব্যাখ্যা করো।
উত্তর: Driver হলো conductor — code পড়ে, task plan করে, executor-দের নির্দেশ দেয়, final result collect করে। Driver একটাই। SparkContext ও SparkSession Driver-এ থাকে। Executor হলো worker — driver-এর নির্দেশে actual computation করে। ডেটার partition নিজের কাছে রাখে। একাধিক executor থাকে। কাজ শেষে status Driver-কে জানায়।
Q2: RDD, DataFrame এবং Dataset-এর পার্থক্য কী? Production-এ কোনটা ব্যবহার করবে?
উত্তর: RDD: Low-level, untyped, schema নেই, manual optimization। DataFrame: High-level, schema আছে, Catalyst Optimizer স্বয়ংক্রিয়ভাবে optimize করে, SQL support। Dataset: Java/Scala-এ strongly typed DataFrame; Python-এ Dataset আলাদা নেই (DataFrame = Dataset[Row])। Production-এ সবসময় DataFrame — দ্রুত, পরিষ্কার কোড, automatic optimization।
Q3: Lazy Evaluation কী? কেন এটা performance-এর জন্য ভালো?
উত্তর: Transformation-গুলো সাথে সাথে চালায় না — DAG (Directed Acyclic Graph) তৈরি করে রাখে। Action দেখলেই সব execute করে। ভালো কারণ: Catalyst Optimizer পুরো execution plan দেখে unnecessary computation বাদ দিতে পারে, predicates আগে push করতে পারে, পুরো pipeline optimize করতে পারে।
Q4: Narrow Transformation ও Wide Transformation-এর পার্থক্য? কোনটা expensive?
উত্তর: Narrow: একটা input partition থেকে একটা output partition (map, filter) — network transfer নেই, দ্রুত। Wide: অনেক input partition merge হয়ে নতুন partition তৈরি হয় — Shuffle লাগে, network transfer হয়, disk write হয় (groupByKey, join, sortBy)। Wide অনেক expensive, minimize করা উচিত।
Q5: reduceByKey বনাম groupByKey — কোনটা ভালো এবং কেন?
উত্তর: সবসময় reduceByKey ভালো। reduceByKey প্রতিটা partition-এ locally আগে reduce করে তারপর shuffle করে — network-এ অনেক কম data যায়। groupByKey সব value shuffle করে Driver-এ আনে — network-এ বেশি data, memory সমস্যা হতে পারে। Example: word count-এ groupByKey-এর চেয়ে reduceByKey ১০x দ্রুত হতে পারে।
⚡ Performance Optimization
Q6: Spark performance optimize করার ৫টা উপায় বলো।
উত্তর:
  1. Partition সংখ্যা ঠিক রাখো — CPU cores × 2-3, বা spark.sql.shuffle.partitions adjust করো
  2. Broadcast Join — ছোট DataFrame (<10MB) broadcast করো: broadcast(small_df)
  3. Cache/Persist — বারবার ব্যবহৃত DataFrame cache করো: df.cache()
  4. Parquet format — CSV-এর বদলে Parquet ব্যবহার করো (column-based, compressed)
  5. Wide Transformation কম করো — join, groupBy-এর আগে filter করো (Predicate Pushdown)
Q7: Spark caching কখন করবে? cache() ও persist()-এর পার্থক্য?
উত্তর: যখন একটা DataFrame বারবার ব্যবহার হবে (multiple model training, multiple join)। cache() = persist(MEMORY_AND_DISK) — RAM-এ রাখে, পূর্ণ হলে disk-এ। persist(StorageLevel.MEMORY_ONLY) — শুধু RAM, কিন্তু যদি পূর্ণ হয় তাহলে পুনরায় compute করে। Production-এ MEMORY_AND_DISK নিরাপদ।
Q8: Data skew কী? কীভাবে handle করবে?
উত্তর: Data skew হলো যখন কিছু partition-এ অনেক বেশি data থাকে — কিছু Executor অনেক বেশি কাজ করে, বাকিরা idle থাকে। সমাধান: (1) Salting — key-এর সাথে random prefix যোগ করো; (2) repartition() দিয়ে redistribute করো; (3) AQE (Adaptive Query Execution) চালু রাখো।
🤖 MLlib ও ML Engineering
Q9: MLlib Pipeline কেন ব্যবহার করবে? কী সমস্যা সমাধান করে?
উত্তর: Pipeline নিশ্চিত করে training ও inference-এ একই preprocessing steps চলে। Data leakage ঠেকায় — Scaler training data দিয়ে fit হয়, test data দিয়ে নয়। Code reusable ও maintainable হয়। Model deployment সহজ হয় — পুরো Pipeline একটাই artifact হিসেবে save/load করা যায়।
Q10: Data leakage কী? PySpark Pipeline-এ কীভাবে এড়াবে?
উत्तर: Data leakage হলো training-এ test data-র তথ্য ঢুকে যাওয়া — model artificially ভালো দেখায় কিন্তু production-এ ব্যর্থ হয়। এড়ানোর উপায়: Pipeline ব্যবহার করো — Pipeline.fit(train) করলে সব Estimator শুধু train data দেখে। তারপর Pipeline.transform(test) করলে শুধু transform হয়, fit হয় না।
Q11: Overfitting কী? MLlib-এ কীভাবে ঠেকাবে?
উত্তর: Overfitting = model training data মুখস্ত করে ফেলে, নতুন data-তে ভুল করে। MLlib-এ সমাধান: (1) regParam — L1/L2 regularization; (2) maxDepth কম রাখো decision tree-তে; (3) CrossValidator দিয়ে proper validation; (4) train/test split — সবসময় আলাদা test set; (5) Feature selection — অপ্রয়োজনীয় feature বাদ দাও।
Q12: SparkContext ও SparkSession-এর পার্থক্য কী?
উত্তর: SparkContext পুরনো API — শুধু RDD কাজের জন্য। SparkSession নতুন (Spark 2.0+) — DataFrame, SQL, Streaming, ML সব কিছুর জন্য। SparkSession-এর ভেতরে SparkContext থাকে (spark.sparkContext)। Production-এ সবসময় SparkSession ব্যবহার করো।

Challenge ৫: Penguin dataset-এ একটা complete ML pipeline তৈরি করো — missing value imputation, encoding, scaling, logistic regression, 5-fold CV
from pyspark.ml import Pipeline
from pyspark.ml.feature import Imputer, StringIndexer, OneHotEncoder, VectorAssembler, StandardScaler
from pyspark.ml.classification import LogisticRegression
from pyspark.ml.tuning import CrossValidator, ParamGridBuilder
from pyspark.ml.evaluation import MulticlassClassificationEvaluator

imputer = Imputer(strategy="mean",
    inputCols=["bill_length_mm","bill_depth_mm","flipper_length_mm","body_mass_g"],
    outputCols=["bl_f","bd_f","fl_f","bm_f"])
sp_idx = StringIndexer(inputCols=["species","sex","island"],
    outputCols=["label","sex_f","island_f"], handleInvalid="keep")
enc = OneHotEncoder(inputCol="island_f", outputCol="island_ohe")
va = VectorAssembler(inputCols=["bl_f","bd_f","fl_f","bm_f","sex_f","island_ohe"], outputCol="feat_raw")
sc = StandardScaler(inputCol="feat_raw", outputCol="features")
lr = LogisticRegression(featuresCol="features", labelCol="label", maxIter=50)
pipe = Pipeline(stages=[imputer, sp_idx, enc, va, sc, lr])

grid = ParamGridBuilder().addGrid(lr.regParam,[0.01,0.1]).addGrid(lr.maxIter,[50,100]).build()
ev = MulticlassClassificationEvaluator(labelCol="label")
cv = CrossValidator(estimator=pipe, estimatorParamMaps=grid, evaluator=ev, numFolds=5)

df = spark.read.option("header",True).option("inferSchema",True).csv("penguins.csv")
train, test = df.randomSplit([0.8,0.2], seed=42)
cv_model = cv.fit(train)
preds = cv_model.transform(test)
print(f"Accuracy: {ev.evaluate(preds,{ev.metricName:'accuracy'}):.4f}")

Q13: PySpark Model production-এ deploy করার steps কী?
