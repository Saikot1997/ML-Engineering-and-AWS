AI Bias কী এবং কেন গুরুত্বপূর্ণ?
Introduction to AI Fairness

কল্পনা করো, তুমি একটি ব্যাংকে ঋণ চাইতে গেছ। ব্যাংক একটি কম্পিউটার প্রোগ্রাম (AI মডেল) ব্যবহার করে সিদ্ধান্ত নেয় — তোমাকে ঋণ দেওয়া হবে কিনা।

এখন যদি এই AI মডেল পুরুষদের সবসময় ঋণ দেয় কিন্তু নারীদের প্রায়ই ঋণ না দেয় — যদিও উভয়ের আর্থিক অবস্থা একই — তাহলে এটাই হলো AI Bias বা পক্ষপাত।

এই Bias কখনও ইচ্ছাকৃত নয়। এটি ডেটা থেকে আসে — যে ডেটায় মডেল শিখেছে সেই ডেটাতেই যদি আগে থেকে বৈষম্য থাকে, তাহলে মডেলও সেই বৈষম্য শিখে নেয়।

রিকশাওয়ালার উদাহরণ: ধরো তুমি একজন বাচ্চাকে শেখাচ্ছ "কারা ভালো মানুষ?" আর তুমি প্রতিদিন তাকে দেখাচ্ছ শুধু ধনীদের "ভালো মানুষ" বলে আর গরিবদের "সন্দেহজনক" বলে। বাচ্চাটি এই পক্ষপাতটাই শিখে নেবে। AI মডেলও ঠিক তাই করে — সে যে ডেটায় শেখে, সেই ডেটার পক্ষপাতটাই শিখে নেয়।

AI Bias-এর উৎস ও প্রভাব

Bias কোথা থেকে আসে?

১. Historical Bias (ঐতিহাসিক পক্ষপাত): আগে থেকেই সমাজে যে বৈষম্য ছিল সেটা ডেটায় রয়ে যায়। যেমন: অতীতে নারীরা কম ঋণ পেত কারণ তাদের চাকরি কম ছিল।

২. Representation Bias (প্রতিনিধিত্ব পক্ষপাত): ডেটাসেটে এক দলের তুলনায় আরেক দলের উপস্থিতি অনেক বেশি বা কম।

৩. Measurement Bias (পরিমাপ পক্ষপাত): ডেটা সংগ্রহের সময় ভুল বা অসম পদ্ধতি ব্যবহার।

৪. Algorithmic Bias (অ্যালগরিদম পক্ষপাত): মডেলটি নিজেই পক্ষপাতমূলক সিদ্ধান্ত তৈরি করে।

Data Scientist-এর দায়িত্ব: মডেল যেন শুধু statistical correlation শিখে, causal relationship না তৈরি করে। অর্থাৎ "নারীরা কম ঋণ পায়" এই সম্পর্ক শেখা ঠিক আছে পর্যবেক্ষণের জন্য — কিন্তু মডেল যেন না শেখে "নারী হওয়ার কারণে ঋণ পাবে না।"

AI Bias হলো যখন একটি মডেল কোনো নির্দিষ্ট গ্রুপের প্রতি অন্যায্য বা পক্ষপাতমূলক সিদ্ধান্ত নেয় — যেমন লিঙ্গ, বয়স, বা জাতিসত্তার ভিত্তিতে। এটি সমস্যা কারণ: (১) এটি বৈষম্যমূলক, (২) মানুষের ক্ষতি করতে পারে (ঋণ, চাকরি অস্বীকার), (৩) আইনি সমস্যা তৈরি করতে পারে।

Correlation এবং Causation-এর পার্থক্য AI Fairness-এ কেন গুরুত্বপূর্ণ?
Correlation মানে দুটি জিনিস একসাথে পরিবর্তিত হয়, Causation মানে একটির কারণে আরেকটি হয়। AI Fairness-এ: মডেল হয়তো দেখবে "নারীরা কম ঋণ পেয়েছে" (correlation) কিন্তু সিদ্ধান্ত নিতে পারবে না "নারী হওয়ার কারণেই ঋণ পাবে না" (causation)। মডেলকে অর্থনৈতিক কারণগুলো দেখতে হবে, লিঙ্গ নয়।

df = pd.read_csv("german_credit.csv", index_col=0)

# personal_status থেকে gender বের করা
mapping = {'A91': 1, 'A93': 1, 'A94': 1,
'A92': 0, 'A95': 0}

# নতুন কলাম বানানো: পুরুষ=1, নারী=0
df['gender'] = df['personal_status'].replace(mapping)

# পুরনো কলাম সরিয়ে ফেলা
df = df.drop(["personal_status"], axis=1)

# telephone ও foreign_worker কলাম binary করা

"telephone": {"A191":0, "A192": 1},

কেন index_col=0? CSV ফাইলের প্রথম কলাম হলো row number (1, 2, 3...). আমরা এটাকে DataFrame-এর index হিসেবে ব্যবহার করি, অতিরিক্ত কলাম হিসেবে নয়।
কেন A201=1, A202=0? A201 মানে বিদেশি কর্মী (foreign=1), A202 মানে বিদেশি নয় (foreign=0)। Telephone-এর ক্ষেত্রে: A191 = ফোন নেই (0), A192 = ফোন আছে (1)।

• Unprivileged = নারী (কম সুযোগ পাচ্ছে)
• Favorable Outcome = চাকরি পাওয়া

def outcome_by_class(df, sensitive_attribute_name, favorable, privileged_group, target_feature_name):

# Unprivileged (নারী) AND favorable (ঋণ পেয়েছে)
is_unprivileged_favorable = (df[sensitive_attribute_name] != privileged_group) & \
(df[target_feature_name] == favorable)

# Privileged (পুরুষ) AND favorable (ঋণ পেয়েছে)
is_privileged_favorable = (df[sensitive_attribute_name] == privileged_group) & \
(df[target_feature_name] == favorable)

# Unprivileged (নারী) AND unfavorable (ঋণ পায়নি)
is_unprivileged_unfavorable = (df[sensitive_attribute_name] != privileged_group) & \
(df[target_feature_name] != favorable)

# Privileged (পুরুষ) AND unfavorable (ঋণ পায়নি)
is_privileged_unfavorable = (df[sensitive_attribute_name] == privileged_group) & \
(df[target_feature_name] != favorable)

return is_unprivileged_favorable, is_privileged_favorable, is_unprivileged_unfavorable, is_privileged_unfavorable

Parity Metrics — Bias পরিমাপ
Selection Rate, SPD, Disparate Impact

Bias আছে সেটা বোঝা গেল। কিন্তু "কতটুকু bias" সেটা পরিমাপ করতে হবে সংখ্যায়। এর জন্য আমরা তিনটি metric ব্যবহার করব।

১. Selection Rate (নির্বাচন হার)

একটি গ্রুপের মধ্যে কতজন favorable outcome পেয়েছে তার শতাংশ।

Selection Rate
P(Y=1 | A=s) = সেই গ্রুপে favorable outcome সংখ্যা / সেই গ্রুপের মোট সংখ্যা
• পুরুষের selection rate = ৫১২/৬৯০ = ০.৭৪২ = ৭৪.২%
• নারীর selection rate = ১৯০/৩১০ = ০.৬১৩ = ৬১.৩%

সহজ উদাহরণ: তোমার ক্লাসে ১০০ জন পুরুষ এবং ৪০ জন নারী বৃত্তির জন্য আবেদন করেছে। ৮০ জন পুরুষ এবং ২৪ জন নারী পেয়েছে।
পুরুষের selection rate = ৮০/১০০ = ৮০%
নারীর selection rate = ২৪/৪০ = ৬০%
এখানেও ২০% পার্থক্য — bias স্পষ্ট!

২. Statistical Parity Difference (SPD)

দুটি গ্রুপের selection rate-এর পার্থক্য। এটা যত কাছে ০-এর, তত বেশি ন্যায্য।

Statistical Parity Difference (SPD)
SPD = |P(Y=1|A=privileged) − P(Y=1|A=unprivileged)|
SPD = |০.৭৪২ − ০.৬১৩| = ০.১২৯ = ১২.৯%

• SPD = 0 → Perfect Fairness (সম্পূর্ণ ন্যায্য)
• SPD কাছে 0 → ভালো
• SPD দূরে 0 → বেশি bias

৩. Disparate Impact (DI)

Unprivileged group-এর selection rate কে Privileged group-এর selection rate দিয়ে ভাগ করো। এটা ratio।

Disparate Impact (DI)
DI = P(Y=1|A=unprivileged) / P(Y=1|A=privileged)
DI = ০.৬১৩ / ০.৭৪২ = ০.৮২৬

• DI = 1.0 → Perfect Fairness
• DI ≥ 0.8 → সাধারণত গ্রহণযোগ্য (80% Rule)
• DI < 0.8 → বৈষম্যের সতর্কতা! ⚠️
Disparate Impact — 80% Rule বোঝা
আমাদের DI = ০.৮২৬ — এটা ০.৮-এর উপরে, তাই "আইনগতভাবে" গ্রহণযোগ্য। কিন্তু Data Scientist হিসেবে আমরা এটা কমাতে চাই। কারণ context অনুযায়ী এমনকি ৮২% ratio-ও গুরুতর প্রভাব ফেলতে পারে।
fairness_metrics.py
# Selection rate ফাংশন
def selection_rate(is_privileged_favorable, is_unprivileged_favorable,
privileged_count, unprivileged_count):
# পুরুষের মধ্যে কতজন ঋণ পেয়েছে / মোট পুরুষ
priv_rate = is_privileged_favorable.sum() / privileged_count
# নারীর মধ্যে কতজন ঋণ পেয়েছে / মোট নারী
unpriv_rate = is_unprivileged_favorable.sum() / unprivileged_count
return priv_rate, unpriv_rate

# Fairness metrics ফাংশন
def calculate_fairness_metrics(privileged_selection_rate, unprivileged_selection_rate):
# Disparate Impact: নারী rate / পুরুষ rate
di = unprivileged_selection_rate / privileged_selection_rate

# Statistical Parity Difference: পুরুষ rate - নারী rate
spd = privileged_selection_rate - unprivileged_selection_rate

return di, spd # (0.826, 0.129)

Modeling — তিনটি মডেল তৈরি
Logistic Regression · SVM · Random Forest · GridSearchCV

আমরা তিনটি ভিন্ন ML মডেল তৈরি করব এবং তুলনা করব। প্রতিটির ভালো-মন্দ আছে — শুধু accuracy নয়, fairness-ও দেখব।

Model 1
Logistic Regression (LR)
সরল linear মডেল। একটি সরল রেখা (hyperplane) দিয়ে ভালো/খারাপ ঋণ আলাদা করে। দ্রুত, interpret করা সহজ। কিন্তু complex pattern ধরতে পারে না।
Model 2
Support Vector Machine (SVM)
দুটি class-এর মধ্যে সবচেয়ে চওড়া "margin" খোঁজে। Kernel trick দিয়ে non-linear pattern ধরতে পারে। Computationally expensive।
Model 3
Random Forest (RF)
অনেকগুলো decision tree মিলিয়ে একটি "forest"। প্রতিটি tree vote দেয়, বেশিরভাগ যা বলে সেটাই final সিদ্ধান্ত। Non-linear, robust, সাধারণত সেরা performance।
তিনটি মডেল কীভাবে সিদ্ধান্ত নেয়

GridSearchCV — সেরা Hyperparameter খোঁজা

প্রতিটি মডেলের কিছু "knobs" আছে যেগুলো আমরা নিজে set করি — এগুলোকে বলে Hyperparameter। যেমন Random Forest-এ কতটি tree থাকবে? কত deep হবে?

GridSearchCV সমস্ত সম্ভাব্য combination চেষ্টা করে সেরাটা খোঁজে।

রান্নার উদাহরণ: ধরো তুমি মসলা দিয়ে রান্না করছ। GridSearchCV মানে সব combination চেষ্টা করা:
• লবণ: ১ চামচ, ২ চামচ, ৩ চামচ
• মরিচ: কম, মাঝারি, বেশি
মোট ৩×৩ = ৯ combination — সবগুলো test করে সবচেয়ে ভালো স্বাদেরটা বেছে নাও!

Decision Function — Performance ও Fairness-এর ভারসাম্য

শুধু একটা মেট্রিক দিয়ে সেরা মডেল বেছে নেওয়া কঠিন। তাই একটা combined score তৈরি করা হয়েছে:

Decision Function (Cost)
cost = (1 − weight_dp) × perf + weight_dp × parity
• perf = accuracy (১ হলে সেরা, তাই (1-accuracy) করা হয়)
• parity = selection_rate_difference (০ হলে সেরা)
• weight_dp = fairness কতটা গুরুত্বপূর্ণ (০.৭ মানে ৭০% গুরুত্ব fairness-এ)
• cost যত কম, মডেল তত ভালো (performance ও fairness উভয় মিলিয়ে)
Random Forest সবচেয়ে কম cost পায় — তাই এটাই আমাদের সেরা মডেল। কিন্তু তবুও ৩.৮% bias আছে — পরবর্তী অংশে আমরা এটা কমাব।

# সমস্ত মডেলের পরিমাপ একসাথে দেখা
def metrics_summary(mf_dict, metrics_names):

# গ্রুপ অনুযায়ী metrics — multi-index DataFrame
metrics_by_group = pd.concat(
[mf_dict[mf].by_group for mf in mf_dict],
keys=mf_dict.keys() # মডেলের নাম key
)

# সামগ্রিক metrics — একটি DataFrame
global_metrics = pd.DataFrame(
[mf_dict[mf].overall for mf in mf_dict],
index=mf_dict.keys()
)

# পার্থক্য DataFrame
metrics_difference = pd.DataFrame(
[mf_dict[mf].difference() for mf in mf_dict],
index=mf_dict.keys()
)
metrics_difference.columns = [m + "_difference" for m in metrics_names]

# দুটো DataFrame merge করা
global_metrics = global_metrics.join(metrics_difference)

return metrics_by_group, global_metrics

Reweighting Strategy
Sample Weights দিয়ে Bias কমানো (Kamiran & Calders, 2012)

Reweighting মানে কী? ডেটার প্রতিটি row-কে একটা "ওজন" (weight) দেওয়া হয়। Model training-এর সময় বেশি weight-এর rows বেশি মনোযোগ পায়।

শিশু উদাহরণ: পরীক্ষায় Math-এ ৩০ নম্বর আর English-এ ১০। Math-এর গুরুত্ব বেশি করতে Math-এর নম্বর ২ দিয়ে গুণ করো। এটাই Reweighting!

🎛️ gender=female ও target=1 (ঋণ পেয়েছে) — এই ধরনের ডেটা কম আছে। এদের weight বাড়িয়ে দাও, যাতে model এই minority case থেকে বেশি শিখতে পারে।

Weight for Privileged + Favorable (α penalty)
W = (|favorable| × |privileged|) / (|all| × |priv_fav|) × α
α = 0.5 → Privileged + Favorable group সবচেয়ে সুবিধাপ্রাপ্ত, তাই weight কমানো হয়।
reweighting_strategy.py 
import numpy as np

weights = np.ones_like(y_train, dtype=float)
alpha = 0.5

sum_fav   = (y_train == 1).sum()
sum_unfav = (y_train == 0).sum()
total     = len(df_train)

# গ্রুপ 1: পুরুষ + ঋণ পেয়েছে → weight কমাও (α)
weights[privileged_favorable_train] = (
    sum_fav * privileged_count / (total * privileged_favorable_train.sum())
) * alpha

# গ্রুপ 2: পুরুষ + ঋণ পায়নি → normal
weights[privileged_unfavorable_train] = (
    sum_unfav * privileged_count / (total * privileged_unfavorable_train.sum())
)

# গ্রুপ 3: নারী + ঋণ পেয়েছে → normal (underrepresented)
weights[unprivileged_favorable_train] = (
    sum_fav * unprivileged_count / (total * unprivileged_favorable_train.sum())
)

# গ্রুপ 4: নারী + ঋণ পায়নি → weight কমাও (α)
weights[unprivileged_unfavorable_train] = (
    sum_unfav * unprivileged_count / (total * unprivileged_unfavorable_train.sum())
) * alpha

# Weighted model training
weighted_models = {}
for model in best_unfitted_models:
    clf = clone(best_unfitted_models[model]).fit(
        X_train_ftu, y_train,
        sample_weight=weights  # এখানে weights দিই
    )
    preds = clf.predict(X_test_ftu)
    mf = MetricFrame(y_true=y_test, y_pred=preds,
                      sensitive_features=A_test, metrics=fairness_metrics)
    weighted_models[model] = {"fitted_model": clf, "pred_test": preds, "mf": mf}

# ফলাফল: rf_weighted সবচেয়ে ভালো cost score ✅
best_estimators["lr_weighted"]  = weighted_models["LR"]["mf"]
best_estimators["rf_weighted"]  = weighted_models["RF"]["mf"]
best_estimators["svc_weighted"] = weighted_models["SVC"]["mf"]

Agarwal et al. (2018) প্রস্তাবিত। প্রতিটি iteration-এ:

১. বর্তমান model দিয়ে fairness constraint কতটা লঙ্ঘিত দেখো

# Best estimator function
def calculate_estimator(X_test, y_test, predictors):
    scores   = [accuracy_score(y_test, p.predict(X_test)) for p in predictors]
    dp_diffs = [demographic_parity_difference(
                    y_true=y_test, y_pred=p.predict(X_test),
                    sensitive_features=A_test) for p in predictors]
    pairs = list(zip(scores, dp_diffs))
    # minimum dp_diff, maximum accuracy
    sorted_pairs = sorted(pairs, key=lambda x: (x[1], -x[0]))
    best = sorted_pairs[0]
    best_idx = pairs.index(best)
    return scores, dp_diffs, best, best_idx

Naive Bayes কীভাবে কাজ করে? প্রতিটি শব্দ কতবার spam ও non-spam-এ আছে গণনা করো। তারপর conditional probability calculate করো।

Conditional Probability
P(word | spam) = (spam-এ word count) / (spam-এর মোট শব্দ)
উদাহরণ: P("please" | not_spam) = 0.3 → non-spam-এ "please" এর probability 0.3
উদাহরণ: P("please" | spam) = 0.06 → spam-এ "please" এর probability 0.06
"Naive" Assumption — শব্দগুলো Independent
P(w1, w2, ...) = P(w1) × P(w2) × ...
"please" থাকলে "tomorrow" থাকার probability বদলায় না — এটাই naive assumption।
বাস্তবে এটা সবসময় সত্য নয়, কিন্তু text classification-এ surprisingly ভালো কাজ করে।
Feature Importance (Log-Probability Difference)
I(word) = abs(LogP(word|not_spam) − LogP(word|spam))
বড় I(word) মানে word বেশি discriminative।
Log use করি কারণ অনেক features গুণ করলে numerical underflow হয়।

def detect_biased_features(model, vectorizer, threshold=1.0):
    rel_importance = model.feature_log_prob_[0] - model.feature_log_prob_[1]
    biased = vectorizer.get_feature_names_out()[rel_importance >= threshold]
    return biased

def retrain_clean(X_train, X_test, y_train, spam_indicators):
    vec = CountVectorizer(vocabulary=spam_indicators)
    X_tr = vec.fit_transform(X_train)
    X_te = vec.transform(X_test)
    model = MultinomialNB().fit(X_tr, y_train)
    return model, vec, X_tr, X_te

def shap_comparison(X_tr_b, X_te_b, X_tr_a, X_te_a, y, vec_b, vec_a):
    lgb_b = lgb.LGBMClassifier(n_estimators=100, verbosity=-1).fit(X_tr_b, y)
    lgb_a = lgb.LGBMClassifier(n_estimators=100, verbosity=-1).fit(X_tr_a, y)
    sv_b = shap.TreeExplainer(lgb_b).shap_values(X_te_b)
    sv_a = shap.TreeExplainer(lgb_a).shap_values(X_te_a)
    top5_b = vec_b.get_feature_names_out()[np.abs(sv_b).mean(0).argsort()[-5:][::-1]]
    top5_a = vec_a.get_feature_names_out()[np.abs(sv_a).mean(0).argsort()[-5:][::-1]]
    return pd.DataFrame({'Before': top5_b, 'After': top5_a})

biased = detect_biased_features(model, vectorizer)
spam_ind = list(set(vectorizer.get_feature_names_out()) - set(biased))

                      Xtr_c.toarray(), Xte_c.toarray(),

# ===== MLOps: SHAP-based drift monitoring =====
def check_shap_drift(shap_ref, shap_prod, threshold=0.1):
    # Reference SHAP values vs Production SHAP values compare
    drift = np.abs(shap_ref.mean(axis=0) - shap_prod.mean(axis=0))
    drifted = np.where(drift > threshold)[0]
    return drifted, drift  # drifted features alert করো!
