CHAPTER 01
Jenkins পরিচিতি

Jenkins কী?

Jenkins হলো Java-তে লেখা একটি open-source automation server। Software development-এর বিভিন্ন কাজ — code build করা, test চালানো, server-এ deploy করা — এগুলো automatically করে দেয়।

সহজ কথায়: তুমি code লেখো → Jenkins বাকি সব করে দেয়।

💡

বাস্তব উদাহরণ: তুমি একটি web app বানাচ্ছো। প্রতিদিন নতুন code লেখো। প্রতিবার কোড লেখার পরে manually: ① build করো → ② সব tests চালাও → ③ server-এ deploy করো।

এটা অনেক সময় নষ্ট করে। ভুলও হয় — হয়তো test চালাতে ভুলে গেলে। Jenkins এই পুরো কাজটা automatically করে। তুমি শুধু git push করো।

CI/CD কী? — Jenkins বোঝার আগে এটা জানতে হবে

Termমানেউদাহরণ
CI — Continuous IntegrationCode push হলেই auto build ও testGitHub-এ push → Jenkins unit test চালায়
CD — Continuous DeliveryTest pass হলে release-ready artifact তৈরিTest pass → Docker image build হয়
CD — Continuous DeploymentAutomatically production server-এ deployImage ready → server-এ auto deploy হয়

Jenkins কেন এত জনপ্রিয়?

🔌 ১৮০০+ Plugins

Git, Docker, Kubernetes, AWS, Azure — প্রায় সব tool-এর সাথে integrate করা যায়। Plugin মানে browser extension-এর মতো।

🆓 Open Source ও Free

সম্পূর্ণ বিনামূল্যে। Community actively maintain করে। GitHub-এ regularly update হয়।

🖥️ Web UI + CLI

Browser-এ graphical interface দিয়ে সব কাজ। /cli route-এ terminal commands-ও আছে।

🔗

Jenkins শুধু Data Engineer-দের জন্য নয়! Web app, mobile app, ML pipeline — সব জায়গায় কাজে আসে। এটা আধুনিক software development-এর একটি মূল হাতিয়ার।

CHAPTER 02
Installation ও First Use Case

Docker দিয়ে Jenkins Install করা

🐳

Docker কী? Application-কে isolated "container"-এ চালানোর platform। Container = mini virtual machine। Jenkins-কে container-এ চালালে তোমার computer-এ কোনো পরিবর্তন হবে না।

Docker Volume কী? Container-এর data computer-এ permanently রাখার ব্যবস্থা। Container বন্ধ করলেও data থাকে। jenkins-data volume-এ Jenkins-এর সব jobs ও config save হয়।

Docker Network কী? একাধিক container একে অপরের সাথে কথা বলার জন্য virtual network। আমরা jenkins নামের একটি network তৈরি করবো।

ধাপে ধাপে Installation

  • ১
    Images ও Network তৈরি করো
    bash
    docker pull jenkins/jenkins   # Jenkins-এর official image download করো
docker pull docker:dind        # Docker-in-Docker image — Jenkins যেন Docker চালাতে পারে
docker network create jenkins  # দুটি container-এর জন্য shared virtual network তৈরি করো
  • ২
    DinD Container চালাও (jenkins-docker)
    bashপ্রতিটি \ মানে পরের line-এ command continue হচ্ছে — একটাই command
    docker run \
  --name jenkins-docker \        # container-এর নাম — পরে stop/start করতে এই নাম লাগবে
  --rm \                          # container বন্ধ হলে automatically delete করো
  --detach \                      # background-এ চালাও (terminal free থাকবে)
  --privileged \                  # DinD চালাতে host kernel-এর special access দরকার
  --network jenkins \             # "jenkins" network-এ যোগ করো
  --network-alias docker \        # network-এ এই container-কে "docker" নামে ডাকা যাবে
  --env DOCKER_TLS_CERTDIR=/certs \   # TLS certificate কোথায় রাখবে
  --volume jenkins-docker-certs:/certs/client \  # Certificate volume-এ রাখো
  --volume jenkins-data:/var/jenkins_home \       # Jenkins data persistent করো
  --publish 2376:2376 \           # host:container port। তোমার 2376 = container-এর 2376
  docker:dind \                   # কোন image ব্যবহার করবে
  --storage-driver overlay2       # Modern Linux-এর Docker storage driver
  • ৩
    Custom Dockerfile তৈরি করো

    এই Dockerfile Jenkins-এ Docker CLI এবং Blue Ocean plugin যোগ করে। "Dockerfile" নামে file তৈরি করো (কোনো extension নেই!)।

    dockerfile
    FROM jenkins/jenkins:2.361.4-jdk11
# Java 11 সহ Jenkins 2.361.4 image থেকে শুরু করো
USER root
# Package install করতে root permission দরকার
RUN apt-get update && apt-get install -y lsb-release
# lsb_release = Linux distribution info command (Docker repo যোগ করতে লাগবে)
RUN curl -fsSLo /usr/share/keyrings/docker-archive-keyring.asc \
    https://download.docker.com/linux/debian/gpg
# Docker-এর GPG key download (package authenticity verify করতে)
RUN echo "deb [arch=$(dpkg --print-architecture) \
    signed-by=/usr/share/keyrings/docker-archive-keyring.asc] \
    https://download.docker.com/linux/debian \
    $(lsb_release -cs) stable" > /etc/apt/sources.list.d/docker.list
# Docker-এর package repository যোগ করো apt-এ
RUN apt-get update && apt-get install -y docker-ce-cli
# Docker CLI install করো (Jenkins যাতে docker commands চালাতে পারে)
# docker-ce-cli = শুধু command line tool, full Docker daemon নয়
USER jenkins
# Security-র জন্য normal jenkins user-এ ফিরে যাও
RUN jenkins-plugin-cli --plugins "blueocean:1.25.6 docker-workflow:1.29"
# blueocean = সুন্দর modern UI
# docker-workflow = Jenkins pipeline-এ Docker ব্যবহার করতে
    bash
    docker build -t myjenkins-blueocean:2.361.4-1 .
# -t = tag দাও (নাম:version format)
# . = current folder-এর Dockerfile ব্যবহার করো
  • ৪
    Jenkins Container চালাও
    bash
    docker run \
  --name jenkins-blueocean \
  --restart=on-failure \          # crash হলে auto restart (manually বন্ধ করলে করবে না)
  --detach \
  --network jenkins \
  --env DOCKER_HOST=tcp://docker:2376 \
  # "docker" = container 1-এর network alias
  # Jenkins এই address-এ Docker API পাবে
  --env DOCKER_CERT_PATH=/certs/client \
  --env DOCKER_TLS_VERIFY=1 \     # Secure TLS connection ব্যবহার করো
  --publish 8080:8080 \           # Web UI — browser-এ localhost:8080 = Jenkins
  --publish 50000:50000 \         # Agent port — Jenkins agents connect করতে
  --volume jenkins-data:/var/jenkins_home \
  --volume jenkins-docker-certs:/certs/client:ro \
  # :ro = read-only। Jenkins certificate পড়বে, লিখবে না।

🛠️ Dummy Source Files — GitHub repo না পেলে এই ৩টি file তৈরি করো!

এই chapter-এ একটি Python calculator project ব্যবহার হয়েছে। যদি GitHub repo access না হয়, নিচের ৩টি file নিজে তৈরি করো। Jenkins pipeline হুবহু কাজ করবে।

pythonsources/calc.py — Calculator library (এই file তৈরি করো)
# sources/calc.py
# এই file-এ calculator functions আছে।
# Jenkins Build stage-এ এই file compile হবে।

def add(a, b):
    """দুটি সংখ্যা যোগ করো"""
    return a + b

def subtract(a, b):
    """a থেকে b বিয়োগ করো"""
    return a - b

def multiply(a, b):
    """দুটি সংখ্যা গুণ করো"""
    return a * b

def divide(a, b):
    """a কে b দিয়ে ভাগ করো — শূন্য হলে error"""
    if b == 0:
        raise ValueError("শূন্য দিয়ে ভাগ করা যাবে না!")
    return a / b
pythonsources/prog.py — Main program (এই file তৈরি করো)
# sources/prog.py
# এই file user থেকে command-line arguments নেয় এবং calculation করে।
# Jenkins Deliver stage-এ এই file থেকে executable তৈরি হবে।
# Executable চালানো: ./prog + 2 3

import sys
from calc import add, subtract, multiply, divide
# sys.argv = command line arguments-এর list
# sys.argv[0] = script নাম, sys.argv[1] = operation, ইত্যাদি

def main():
    if len(sys.argv) != 4:
        print("Usage: prog <operation> <num1> <num2>")
        print("Operations: + - * /")
        return

    op = sys.argv[1]
    a  = float(sys.argv[2])
    b  = float(sys.argv[3])

    operations = {'+': add, '-': subtract, '*': multiply, '/': divide}
    if op not in operations:
        print(f"Unknown operation: {op}"); return

    result = operations[op](a, b)
    print(f"{a} {op} {b} = {result}")

if __name__ == "__main__":
    main()
# if __name__ == "__main__" কী?
# এই file সরাসরি চালালে main() call হবে।
# কিন্তু অন্য file-এ import করলে main() call হবে না।
# এটা Python-এর convention — সব main script-এ এভাবে লেখা হয়।
pythonsources/test_calc.py — Unit tests (এই file তৈরি করো)
# sources/test_calc.py
# এই file-এ unit tests আছে।
# Jenkins Test stage-এ pytest এই file automatically খুঁজে চালাবে।
# Convention: test_ দিয়ে শুরু হওয়া functions = pytest automatically detect করে।

import pytest
from calc import add, subtract, multiply, divide

def test_add():
    assert add(2, 3) == 5
    assert add(-1, 1) == 0
    assert add(0, 0) == 0
# assert = এই condition সত্য হওয়া উচিত।
# সত্য না হলে → test FAIL → Jenkins Test stage fail করবে।

def test_add_float():
    assert add(0.1, 0.2) == pytest.approx(0.3)
# pytest.approx কেন?
# Computer-এ 0.1 + 0.2 = 0.30000000000000004 (floating point precision issue)
# pytest.approx(0.3) মানে "মোটামুটি 0.3" — এই পার্থক্য ignore করো।

def test_subtract():
    assert subtract(5, 3) == 2
    assert subtract(0, 5) == -5

def test_multiply():
    assert multiply(3, 4) == 12
    assert multiply(0, 100) == 0

def test_divide():
    assert divide(10, 2) == 5.0
    assert divide(7, 2) == 3.5

def test_divide_by_zero():
    with pytest.raises(ValueError):
        divide(5, 0)
# pytest.raises(ValueError) মানে:
# এই block-এর ভেতরে ValueError exception হওয়া উচিত।
# হলে → test PASS। না হলে → test FAIL।
# আমাদের divide(5, 0) ValueError raise করে → সঠিক!

Pipeline কী এবং কেন?

Freestyle Project-এ সব কিছু web UI-তে configure করা হয়। কিন্তু real project-এ আমরা Pipeline ব্যবহার করি — যেখানে pipeline-টা code হিসেবে Jenkinsfile-এ লেখা থাকে।

Scripted Pipeline (পুরোনো)

Groovy language-এ লেখা। Browser-এ directly লেখা যায়। Flexible কিন্তু complex। Jenkins 1.x এর সময় থেকে আছে।

Declarative Pipeline ⭐ (নতুন, recommended)

Jenkinsfile-এ লেখা হয়। Git-এ থাকে। Simpler syntax, more readable। Jenkins 2.x থেকে। এটাই আমরা ব্যবহার করবো।

📄

Groovy কী? Java-based scripting language। Jenkins এটা ব্যবহার করে Jenkinsfile লিখতে। তোমাকে Groovy expert হতে হবে না — basic structure শিখলেই হবে।

Pipeline as Code-এর সুবিধা: Jenkinsfile Git-এ থাকে তাই version control হয়, team-এর সবাই দেখতে পায়, code review করা যায়, এবং project clone করলে pipeline-ও চলে আসে।

সম্পূর্ণ Jenkinsfile — প্রতিটি লাইন বাংলায়

groovyJenkinsfile — repository root-এ রাখো
pipeline {
    agent none
    // agent none মানে: এই pipeline-এর জন্য কোনো global agent নেই।
    // প্রতিটি stage নিজের agent নির্দিষ্ট করবে।
    // agent any দিলে Jenkins যেকোনো available machine-এ চালাতো।

    stages {

        stage('Build') {
            agent {
                docker {
                    image 'python:3.8-alpine3.16'
                    // Docker hub থেকে এই image pull করো এবং container-এ চালাও।
                    // alpine = ছোট Linux distro (image size মাত্র ~5MB)
                    // প্রতিটি stage আলাদা container-এ চলে → isolated environment
                }
            }
            steps {
                sh 'python3.8 -m py_compile sources/prog.py sources/calc.py'
                // sh = shell command চালাও।
                // python -m py_compile = Python files-এর syntax check করো।
                // Syntax error থাকলে এখানেই ধরা পড়বে।
                // সফল হলে .pyc (compiled) files তৈরি হয়।

                stash(name: 'compiled-results', includes: 'sources/*.py*')
                // stash = files টেম্পরারিভাবে save করো।
                // কারণ: প্রতিটি stage আলাদা container-এ চলে।
                // Build stage-এ compile হওয়া files Deliver stage-এ দরকার।
                // stash ছাড়া পরের stage সেই files পাবে না।
                // includes: 'sources/*.py*' = sources/ folder-এর সব .py ও .pyc files।
            }
        }

        stage('Test') {
            agent {
                docker {
                    image 'grihabor/pytest'
                    // pytest pre-installed আছে এই image-এ।
                }
            }
            steps {
                sh 'pytest -v --junit-xml test-reports/results.xml sources/test_calc.py'
                // pytest = Python unit test runner।
                // -v = verbose — প্রতিটি test-এর নাম ও status দেখাও।
                // --junit-xml = XML format-এ results save করো।
                //   Jenkins এই XML পড়তে পারে → Dashboard-এ test results দেখাবে।
                // sources/test_calc.py = কোন file-এ tests আছে।
            }
            post {
                always {
                    junit "test-reports/results.xml"
                    // post always = Test pass হোক বা fail — সবসময় এটা চালাও।
                    // junit = Jenkins-কে XML results পড়তে বলো।
                    // Dashboard-এ "Test Results" section-এ দেখাবে।
                    // Fail হলেও results দেখা জরুরি — কোন test fail করেছে জানতে।
                }
            }
        }

        stage('Deliver') {
            agent any
            // agent any = যেকোনো available Jenkins agent ব্যবহার করো।
            // এই stage-এ Docker command চালাতে হবে, তাই host-এ চলা দরকার।

            environment {
                VOLUME = '$(pwd)/sources:/src'
                IMAGE  = 'cdrx/pyinstaller-linux'
                // environment = এই stage-এর জন্য environment variables।
                // VOLUME = Docker volume mapping: host-এর sources/ = container-এর /src
                // IMAGE = pyinstaller Docker image (Python → standalone executable বানায়)
            }
            steps {
                dir(path: env.BUILD_ID) {
                    // dir() = এই folder-এ কাজ করো।
                    // env.BUILD_ID = Jenkins-এর built-in variable — এই build-এর number।
                    // যেমন: build #5 হলে "5" নামের folder-এ কাজ হবে।
                    // আলাদা folder-এ রাখলে multiple builds conflict করে না।
                    unstash(name: 'compiled-results')
                    // unstash = Build stage-এ stash করা files ফিরিয়ে আনো।

                    sh "docker run --rm -v ${VOLUME} ${IMAGE} 'pyinstaller -F prog.py'"
                    // docker run = Docker container চালাও।
                    // --rm = container শেষ হলে automatically delete করো।
                    // -v ${VOLUME} = sources/ folder container-এ mount করো।
                    // pyinstaller -F prog.py = prog.py থেকে single executable তৈরি করো।
                    // Output: sources/dist/prog (standalone executable — Python লাগবে না!)
                }
            }
            post {
                success {
                    archiveArtifacts "${env.BUILD_ID}/sources/dist/prog"
                    // archiveArtifacts = Build artifact হিসেবে save করো।
                    // Dashboard থেকে download করা যাবে।
                    // এটাই final product — শেষ পর্যন্ত এটাই দেওয়া হবে।
                    sh "rm -rf ${env.BUILD_ID}/sources/build ${env.BUILD_ID}/sources/dist"
                    // Temp build files clean up করো।
                }
            }
        }
    }
}

Multibranch Pipeline — একাধিক Branch একসাথে

Real project-এ অনেক branch থাকে (main, develop, feature/xyz)। প্রতিটির জন্য আলাদা Pipeline তৈরি করা কষ্টের। Multibranch Pipeline automatically সব branch-এ Jenkinsfile খোঁজে এবং আলাদা pipeline চালায়।

Cron Syntax — Scheduled Build-এর ভাষা

# Format: মিনিট  ঘণ্টা  মাসের_দিন  মাস  সপ্তাহের_দিন
#         MINUTE  HOUR    DOM       MONTH   DOW
#
# * মানে "যেকোনো" (প্রতিটি), সংখ্যা মানে specific value

* * * * *     # প্রতি মিনিটে (test করার জন্য ভালো)
0 * * * *     # প্রতি ঘণ্টার শুরুতে (০ মিনিটে)
0 2 * * *     # প্রতিদিন রাত ২টায়
0 9 * * 1     # প্রতি সোমবার সকাল ৯টায় (1=Monday)
0 9 * * 1-5   # প্রতি সোমবার-শুক্রবার সকাল ৯টায় (weekdays)
H/5 * * * *   # প্রতি ৫ মিনিটে (H = hash, Jenkins optimize করে)
H H(0-8) * * * # রাত ০টা থেকে ৮টার মধ্যে একবার (Jenkins বেছে নেবে)

Webhook Setup — ngrok দিয়ে Local Jenkins Public করা

🌐

ngrok কী? তোমার computer-এর local server-কে internet-এ accessible করার tool। GitHub webhook-এর জন্য Jenkins-এর public URL দরকার। ngrok একটি temporary public URL দেয়।

কেন .pem file? VM (Virtual Machine) তে SSH করতে private key file (.pem) দরকার। যদি local computer-এ Jenkins চালাচ্ছো, scp step skip করো।

bashngrok setup করো
# Local computer-এ Jenkins চালালে সরাসরি ngrok install করো:
# ngrok.com থেকে download করো → unzip করো → চালাও

# VM-এ Jenkins চালালে — ngrok VM-এ পাঠাও:
scp -i "your-key.pem" ~/ngrok-stable-linux-amd64.zip ubuntu@YOUR_VM_IP:~/ngrok.zip
# scp = secure copy (SSH দিয়ে file transfer)
# -i "your-key.pem" = authentication key (AWS/GCP VM-এর জন্য)
# ~/ngrok-stable-linux-amd64.zip = local-এ ngrok zip file
# ubuntu@YOUR_VM_IP:~/ngrok.zip = VM-এ কোথায় রাখবে

# VM-এ unzip করো:
unzip ngrok.zip
./ngrok --version     # ngrok version 2.3.40 দেখালে সফল

# Jenkins-এর port forward করো:
./ngrok http 8080
# Output এরকম আসবে:
# Forwarding https://d4b48cd1f88c.ngrok.io -> http://localhost:8080
#                ↑ এই https URL copy করো
configGitHub Webhook configure করো
# GitHub Repo → Settings → Webhooks → Add webhook:

Payload URL: https://d4b48cd1f88c.ngrok.io/github-webhook/
             # ↑ ngrok URL + /github-webhook/ (এই path অবশ্যই দিতে হবে!)
Content type: application/json
Which events: Just the push event   # push করলেই trigger হবে
Active: ✓

# Jenkins-এ:
# Pipeline Configure → Build Triggers → ✅ GitHub hook trigger for GitScm polling
🧪

Jenkins Journey — তুমি কী কী শিখলে

🎯 তুমি এখন জানো:

  1. CI/CD কী: Code push → auto build+test+deploy। Manual কাজ কমায়, ভুল কমায়।
  2. Docker দিয়ে Jenkins: দুটি container (DinD + Jenkins), network, volumes।
  3. Freestyle Project: Simple tasks-এর জন্য। Web UI দিয়ে configure।
  4. Declarative Pipeline: Jenkinsfile-এ Build → Test → Deliver stage। stash/unstash দিয়ে file share।
  5. post block: always/success/failure — stage-এর পরে কী করতে হবে।
  6. archiveArtifacts: Build output Dashboard থেকে download করা যায়।
  7. Multibranch Pipeline: সব branches auto detect করে আলাদা pipeline চালায়।
  8. Cron scheduling: নির্দিষ্ট সময়ে auto build। Cron syntax: মিনিট ঘণ্টা দিন মাস সপ্তাহ।
  9. Webhook: git push করলেই auto trigger। ngrok দিয়ে local Jenkins public করা।
