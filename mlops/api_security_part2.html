🔑 পদ্ধতি ১: API Keys

API Key হলো একটি লম্বা, এলোমেলো অক্ষরের সংখ্যার সমষ্টি যা API প্রদানকারী আপনাকে দেয়। এটি দিয়ে সার্ভার বুঝতে পারে রিকোয়েস্টটি কার।

📌 মনে রাখুন: API Key একটি অ্যাপ্লিকেশনকে চিহ্নিত করে, কোনো নির্দিষ্ট ব্যবহারকারীকে নয়। একজন ব্যবহারকারীর একাধিক API Key থাকতে পারে।

API Key পাঠানোর দুটি উপায়

উপায় ১: Query String (URL-এর মধ্যে)

# URL-এর শেষে ? দিয়ে parameter যোগ করা হয় # এখানে api_key= হলো parameter নাম, এর পরে আপনার key http://domain.org/path/to/resource?api_key=abcd1234xyz # OpenWeatherMap উদাহরণ: https://api.openweathermap.org/data/2.5/weather?q=Dhaka&appid=MYKEY123
⚠️ Query String-এর সমস্যা: URL অনেক সিস্টেমে log হয়ে যায়। মানে আপনার API Key log file-এ সেভ হয়ে যাবে — যেটা বিপজ্জনক!

উপায় ২: HTTP Header (নিরাপদ পদ্ধতি)

# Header-এ পাঠানো — URL-এ দেখা যায় না # curl দিয়ে: curl -X GET https://api.example.com/data \ -H 'X-Api-Key: abcd1234xyz' # Python দিয়ে: import requests response = requests.get( url="https://api.example.com/data", headers={ "X-Api-Key": "abcd1234xyz" # Header-এ key পাঠানো } ) print(response.status_code)

FastAPI দিয়ে API Key Implementation

এখন দেখি কীভাবে নিজের API-তে API Key authentication যোগ করতে হয়:

# প্রথমে দরকারি module import করা from fastapi import Security, FastAPI, HTTPException, status from fastapi.security.api_key import APIKeyHeader, APIKey # আমাদের secret key (বাস্তবে এটি environment variable-এ থাকবে) API_KEY = "hello_datascientest" API_KEY_NAME = "access_token" # header-এর নাম # Header থেকে key নেওয়ার জন্য object তৈরি api_key_header = APIKeyHeader(name=API_KEY_NAME, auto_error=False) api = FastAPI()
# Key যাচাই করার function async def get_api_key(api_key_header: str = Security(api_key_header)): if api_key_header == API_KEY: # মিলে গেলে? return api_key_header # key ফেরত দাও # না মিললে 403 error throw করো raise HTTPException( status_code=status.HTTP_403_FORBIDDEN, detail="Could not validate credentials" )
# দুটি route: একটি free, একটি secured @api.get("/hello") def hello(): return 'Hello World !' # যে কেউ দেখতে পারবে @api.get("/secure") async def secure(api_key_header: APIKey = Depends(get_api_key)): return 'Hello this is secure!' # শুধু valid key দিয়ে

পরীক্ষা করুন:

# Key ছাড়া → 403 Error curl -X GET http://localhost:8000/secure # {"detail":"Not authenticated"} # Key দিয়ে → সফল! curl -X GET http://localhost:8000/secure \ -H 'access_token: hello_datascientest' # "Hello this is secure!"

সুবিধা

  • বাস্তবায়ন করা সহজ
  • ব্যবহার করা সহজ
  • অ্যাপ ট্র্যাক করা যায়

অসুবিধা

  • Key leak হলে বিপদ
  • Code-এ রাখলে বিপজ্জনক
  • নিয়মিত পরিবর্তন করা দরকার
✅ Best Practice: API Key কখনো সরাসরি code-এ লিখবেন না। Secret Manager বা Environment Variable ব্যবহার করুন।
👤 পদ্ধতি ২: Basic Authentication

Basic Auth হলো সবচেয়ে পরিচিত পদ্ধতি — Username ও Password দিয়ে login করা। কিন্তু এখানে password সরাসরি পাঠানো হয় না, Base64 encoding করে পাঠানো হয়।

Base64 কী? (খুব সহজ ব্যাখ্যা)

Base64 হলো একটি encoding পদ্ধতি যা টেক্সটকে একটি নির্দিষ্ট ফরম্যাটে রূপান্তরিত করে। এটি encryption নয় — যে কেউ decode করতে পারে!

উদাহরণ: username:password → Base64

hello:world → encode → aGVsbG86d29ybGQ=
daniel:datascientest → encode → ZGFuaWVsOmRhdGFzY2llbnRlc3Q=
john:secret → encode → am9objpzZWNyZXQ=
# Python দিয়ে Base64 encode করুন: import base64 result = base64.b64encode(b"daniel:datascientest") print(result) # b'ZGFuaWVsOmRhdGFzY2llbnRlc3Q=' # Decode করা (যে কেউ করতে পারে!): decoded = base64.b64decode("ZGFuaWVsOmRhdGFzY2llbnRlc3Q=") print(decoded) # b'daniel:datascientest' # Shell দিয়ে: echo hello:world | base64 # → aGVsbG86d29ybGQ=

Basic Auth-এর ধাপগুলো

Basic Auth-এর ৪টি ধাপ

Flask দিয়ে Basic Auth Implementation

# প্রয়োজনীয় package install: pip install flask_httpauth # কোড: from flask import Flask from flask_httpauth import HTTPBasicAuth from werkzeug.security import generate_password_hash, check_password_hash # generate_password_hash: plaintext → hashed password # check_password_hash: plaintext ও hash তুলনা করে api = Flask(import_name='my_api') auth = HTTPBasicAuth() # ব্যবহারকারী ডেটাবেস (বাস্তবে এটি real database-এ থাকবে) users = { "daniel": { 'password': generate_password_hash("datascientest"), # hash করা password 'private': 'Private Resource Daniel', 'role': ['admin', 'user'] # daniel-এর দুটো role }, "john": { 'password': generate_password_hash("secret"), 'private': 'Private Resource John', 'role': 'user' # john শুধু user } }
# Password যাচাই করার function (decorator দিয়ে register করা) @auth.verify_password def verify_password(username, password): # username database-এ আছে? এবং password মিলছে? if username in users and \ check_password_hash(users[username]['password'], password): return username # সফল হলে username ফেরত দাও # Role নির্ধারণ করার function @auth.get_user_roles def get_user_roles(user): return users[user]['role'] # ব্যবহারকারীর role list
# Routes তৈরি করা @api.route('/admin') @auth.login_required(role='admin') # শুধু admin-রা দেখতে পারবে def admin(): return "Hello {}, আপনি admin!".format(auth.current_user()) @api.route('/') @auth.login_required(role='user') # সব user দেখতে পারবে def index(): return "Hello, {}!".format(auth.current_user()) @api.route('/private') @auth.login_required(role='user') def private(): return "Resource: {}".format(users[auth.current_user()]['private'])
⚠️ Role-based Access Control:
  • daniel → role: ['admin', 'user'] → /admin, /, /private সব দেখতে পারবে
  • john → role: 'user' → শুধু /, /private দেখতে পারবে, /admin দেখলে 403!

Basic Auth-এর সিকিউরিটি সমস্যা

🚨 মারাত্মক সমস্যা: Base64 এনক্রিপশন নয়! কেউ নেটওয়ার্কে request intercept করলে খুব সহজেই password বের করতে পারবে:
# john:secret → am9objpzZWNyZXQ= (Base64) # এই string decode করা মাত্র সেকেন্ডের ব্যাপার: import base64 decoded = base64.b64decode("am9objpzZWNyZXQ=") print(decoded.decode()) # john:secret — খুব সহজে পাওয়া গেল! # তাই Basic Auth সবসময় HTTPS-এর সাথে ব্যবহার করা উচিত!

সুবিধা

  • বাস্তবায়ন সহজ
  • সব browser সাপোর্ট করে
  • Role-based access সহজ

অসুবিধা

  • Intercept হলে password চুরি
  • প্রতি request-এ password পাঠাতে হয়
  • HTTPS ছাড়া ব্যবহার করা উচিত নয়
🎫 পদ্ধতি ৩: JWT (JSON Web Token)

JWT হলো একটি "টিকেট"-এর মতো যা login করার পরে পাওয়া যায় এবং পরবর্তী request-এ এই টিকেট দেখালেই সার্ভার চিনতে পারে — বারবার password দিতে হয় না।

JWT = JSON Web Token — ডেটা বহনকারী ডিজিটাল টিকেট যা digitally signed (স্বাক্ষরিত)।

JWT-এর তিনটি অংশ

একটি JWT তিনটি অংশ নিয়ে তৈরি — প্রতিটি অংশ . (dot) দিয়ে আলাদা করা:

eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9
.
eyJzdWIiOiIxMjM0NTY3ODkwIiwibmFtZSI6IkRhbmllbCIsImlhdCI6MTUxNjIzOTAyMn0
.
eSaq3mzEMC8zHO49GZkxyHxf-DyKhYXz5Tx_HevmL8Y
📋

Header (শিরোনাম)

Token-এর ধরন (JWT) এবং কোন algorithm ব্যবহার হচ্ছে (HS256)

{ "alg": "HS256", "typ": "JWT" }
📦

Payload (তথ্য)

ব্যবহারকারীর তথ্য, token-এর মেয়াদ, ইত্যাদি

{ "sub": "1234", "name": "Rahul", "exp": 1716239022 }
✍️

Signature (স্বাক্ষর)

Header + Payload হ্যাশ করে secret key দিয়ে সাইন করা

এটি প্রমাণ করে token নকল নয়

⚠️ গুরুত্বপূর্ণ: JWT-এর Payload encrypted নয়, শুধু Base64 encoded। যে কেউ payload-এর তথ্য পড়তে পারবে! তাই গোপন তথ্য payload-এ রাখবেন না। Signature শুধু প্রমাণ করে যে token পরিবর্তন হয়নি।

JWT কীভাবে কাজ করে

JWT Authentication-এর সম্পূর্ণ flow

Flask দিয়ে JWT Implementation

# Install: pip3 install flask_jwt_extended==4.2.1 from flask import Flask, jsonify, request from flask_jwt_extended import create_access_token, get_jwt_identity, jwt_required, JWTManager from datetime import timedelta api = Flask("my_api") # Secret key: এই key দিয়ে token sign করা হবে # openssl rand -hex 32 দিয়ে generate করুন api.config["JWT_SECRET_KEY"] = "760257bc03d0f18b99ba31e6b90f6b95..." api.config["JWT_ACCESS_TOKEN_EXPIRES"] = timedelta(minutes=30) # ৩০ মিনিট মেয়াদ jwt = JWTManager(api) # JWT manager সংযুক্ত করা
# Login route: username+password দিয়ে token পাওয়া @api.route("/login", methods=["POST"]) def login(): username = request.json.get("username", None) password = request.json.get("password", None) user = get_user(users_db, username) if not user or not check_password(password, user['hashed_password']): return jsonify({"msg": "ভুল username বা password"}), 401 # সব ঠিক থাকলে token তৈরি করো access_token = create_access_token(identity=username) return jsonify(access_token=access_token) # Protected route: token ছাড়া দেখা যাবে না @api.route("/user", methods=["GET"]) @jwt_required() # এই decorator মানে JWT token আবশ্যক def get_current_user(): current_user = get_jwt_identity() # token থেকে user বের করা return jsonify(logged_in_as=current_user), 200

পরীক্ষা করুন:

# Step 1: Login করো, token নাও curl -X POST -H "Content-Type: application/json" \ -d '{"username":"daniel", "password":"datascientest"}' \ http://127.0.0.1:5000/login # উত্তর: {"access_token": "eyJhbGci..."} # Step 2: Token দিয়ে protected route access করো curl -X GET \ -H 'Authorization: Bearer eyJhbGci...' \ http://127.0.0.1:5000/user # উত্তর: {"logged_in_as": "daniel"}
iss Issuer — কে token তৈরি করেছে
sub Subject — কার জন্য token (সাধারণত user ID)
exp Expiration — token কখন মেয়াদ শেষ হবে (Unix timestamp)
iat Issued At — token কখন তৈরি হয়েছে

JWT-এর সুবিধা

  • Stateless — সার্ভারে session রাখতে হয় না
  • মেয়াদ সীমিত — leak হলেও সময়মতো expire
  • ডেটা বহন করতে পারে
  • Microservices-এ সহজে ব্যবহার

JWT-এর অসুবিধা

  • Secret key leak হলে সব token compromise
  • Payload encrypted নয় (সংবেদনশীল তথ্য রাখা যাবে না)
  • Token revoke করা কঠিন
  • HTTPS ছাড়া intercept সম্ভব
🛡️ পদ্ধতি ৪: HTTPS (এনক্রিপ্টেড যোগাযোগ)

HTTPS = HTTP + S (Secure)। এটি client ও server-এর মধ্যে সমস্ত ডেটা এনক্রিপ্ট করে পাঠায়। নেটওয়ার্কে কেউ intercept করলেও কিছু পড়তে পারবে না।

HTTP vs HTTPS: Man-in-the-Middle Attack

Symmetric vs Asymmetric Encryption

🔐

Symmetric (সিমেট্রিক)

একটিই চাবি — দুই পক্ষই একই চাবি দিয়ে lock/unlock করে।

সমস্যা: চাবি শেয়ার করতে গেলে চুরি হতে পারে!

🔑🔓

Asymmetric (অ্যাসিমেট্রিক)

দুটি চাবি — Public Key (সবাইকে দেওয়া যায়) + Private Key (গোপন)।

HTTPS এটি ব্যবহার করে!

Asymmetric Encryption কীভাবে কাজ করে?

🔐
Message পাঠানো (Encryption) Alice Bob-কে message পাঠাতে চায়। Alice Bob-এর Public Key দিয়ে message encrypt করে। এখন শুধু Bob-এর Private Key দিয়ে decrypt করা সম্ভব।
🔓
Message পড়া (Decryption) Bob তার নিজের Private Key দিয়ে decrypt করে message পড়ে। অন্য কেউ, হ্যাকারও, Bob-এর Private Key ছাড়া পড়তে পারবে না।
✍️
Signature (Digital Signature) Alice তার Private Key দিয়ে message sign করে পাঠায়। Bob Alice-এর Public Key দিয়ে verify করতে পারে — এটা সত্যিই Alice পাঠিয়েছে কিনা।
💡 মনে রাখুন:
  • Public Key দিয়ে encrypt → শুধু Private Key দিয়ে decrypt
  • Private Key দিয়ে sign → Public Key দিয়ে verify

TLS Handshake — HTTPS কীভাবে connection শুরু করে

TLS Handshake — HTTPS connection setup করার প্রক্রিয়া

💡 কেন Symmetric শেষে? Asymmetric encryption গণনায় ধীর ও ব্যয়বহুল। Handshake-এ Asymmetric ব্যবহার করে নিরাপদভাবে একটি shared secret তৈরি করা হয়, তারপর দ্রুত Symmetric encryption-এ switch করা হয়।

HTTPS-এর সুবিধা

  • ডেটা চুরি থেকে সুরক্ষা
  • Identity verify হয়
  • SEO-তে Google প্রাধান্য দেয়
  • Browser trust indicator (🔒)

কিছু বিষয়

  • Certificate নবায়ন করতে হয়
  • সামান্য performance overhead
  • Free: Let's Encrypt দিয়ে সম্ভব
