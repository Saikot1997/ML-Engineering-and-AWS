১
Data Version Control কী?
🍳 রান্নার রেসিপি দিয়ে বুঝি

ধরুন আপনি একটি রেসিপি লিখছেন। প্রথমে শুধু উপকরণের তালিকা। তারপর রান্নার পদ্ধতি যোগ করলেন। তারপর পরিমাণ ঠিক করলেন। এখন যদি কেউ জিজ্ঞেস করেন — "তোমার প্রথম ড্রাফটে কী ছিল?" — আপনি মনে করতে পারবেন না! Data Version Control হলো সেই ম্যাজিক রেকর্ডার যে প্রতিটি পরিবর্তন মনে রাখে।

কম্পিউটার বিজ্ঞানের দুনিয়ায় Version Control মানে হলো — কোনো ফাইলের প্রতিটি পরিবর্তন ট্র্যাক করে রাখা, যাতে যেকোনো সময় আগের অবস্থায় ফিরে যাওয়া যায়।

কোডের জন্য আমরা Git ব্যবহার করি। কিন্তু ডেটার জন্য? সেটাই হলো Data Version Control (DVC)।

🤔 কেন ডেটার ভার্সন কন্ট্রোল দরকার?

Machine Learning প্রজেক্টে সমস্যাটা হলো — একই ডেটাসেট নিয়ে অনেকে কাজ করেন, বিভিন্ন পরিবর্তন হয়, এবং কোন মডেল কোন ডেটায় ট্রেন হয়েছিল সেটা মনে থাকে না।

চিত্র ১: ডেটা ভার্সন কন্ট্রোল ছাড়া যে সমস্যা হয়
💡মূল সমস্যা

Git ডেটা ফাইল ট্র্যাক করতে পারে না কারণ: ডেটা ফাইল অনেক বড় (GB), এবং প্রতিটি পরিবর্তনে Git একটি নতুন কপি রাখে — ফলে রেপো দ্রুত বিশাল হয়ে যায়।

Data Version Control এর দুটো বড় সুবিধা:

✅সুবিধা ১: প্রজেক্টের বিবর্তন দেখা যায়

কী যোগ হয়েছে, কী বাদ দেওয়া হয়েছে, কখন — সব ইতিহাস আছে।

✅সুবিধা ২: Risk Management

কোনো সমস্যা হলে আগের ভার্সনে ফিরে যাও — undo বাটনের মতো, কিন্তু পুরো ডেটাসেটের জন্য!

🛠️ DVC ছাড়াও আরও টুল আছে

DVC
Git এর সাথে মিলিয়ে কাজ করে। ML প্রজেক্টের জন্য সেরা।
✅ ফ্রি, ওপেন-সোর্স
✅ Git এর মতো কমান্ড
❌ Relational DB এর ফিচার নেই
Git-LFS
Git এর একটি extension। Game dev থেকে এসেছে।
✅ Git এর সাথে ইন্টিগ্রেটেড
❌ হ্যান্ডেল করা কঠিন
❌ একবার যোগ করলে সরানো কষ্টকর
Dolt
SQL database + GitHub এর মতো ফিচার (fork, clone, merge)।
✅ SQL query করা যায়
❌ শুধু tabular data
❌ private data এ paid plan
LakeFS
বড় data lake এর জন্য। Airflow, Spark ইত্যাদির সাথে কাজ করে।
✅ বড় ডেটাসেটের জন্য আদর্শ
❌ ফাইল ডিলিট করা সহজ নয়
⚠️এই কোর্সে আমরা DVC শিখব

কারণ DVC সবচেয়ে বেশি ব্যবহৃত, ফ্রি, এবং Git এর সাথে সুন্দরভাবে কাজ করে।

২
DVC কী এবং কীভাবে কাজ করে?

DVC (Data Version Control) হলো ডেটা এবং Machine Learning মডেলের ভার্সন ট্র্যাক করার একটি টুল। এটি Git এর সাথে মিলে কাজ করে।

📚 লাইব্রেরি কার্ড দিয়ে বুঝি

ধরুন লাইব্রেরিতে ৫০০ পৃষ্ঠার বই আছে। আপনাকে প্রতিবার পুরো বই বহন না করে — শুধু একটি কার্ড দেওয়া হলো যাতে বইয়ের লোকেশন লেখা আছে। DVC ঠিক এটাই করে।

বড় ফাইল (ডেটা/মডেল) → আলাদা জায়গায় রাখে
ছোট pointer file (.dvc) → Git এ রাখে

Git এর সাথে পার্থক্য কী?

বিষয় Git DVC
কী ট্র্যাক করে? কোড, ছোট ফাইল বড় ডেটা ফাইল, ML মডেল
ফাইল কোথায় রাখে? Git রেপোতেই বাইরে (S3, GDrive, local)
রেপোতে কী থাকে? আসল ফাইল শুধু pointer (.dvc ফাইল)
ফাইল সাইজ সীমা ~100MB (GitHub limit) কোনো সীমা নেই
কমান্ড স্টাইল git add, git commit, git push dvc add, dvc commit, dvc push

DVC এর আর্কিটেকচার — কোথায় কী থাকে?

চিত্র ২: DVC এর সম্পূর্ণ আর্কিটেকচার

সহজ ভাষায় কীভাবে কাজ করে

১
আপনি ডেটা যোগ করেন (dvc add)

DVC বড় ফাইলটিকে একটি fingerprint (MD5 hash) দিয়ে চিহ্নিত করে। আসল ফাইলটি cache এ রাখে। একটি ছোট .dvc ফাইল তৈরি করে যেটা pointer হিসেবে কাজ করে।

২
Git এ .dvc ফাইল commit করেন

Git এ শুধু ছোট pointer ফাইলটি যায়। আসল বড় ডেটা যায় না। তাই রেপো ছোটই থাকে।

৩
Remote এ push করেন (dvc push)

আসল বড় ডেটা S3/GDrive/DagsHub এ আপলোড হয়। এখন যে কেউ এটা পেতে পারে।

৪
অন্য কেউ download করেন (dvc pull)

Git clone করলে শুধু .dvc ফাইল আসে। তারপর dvc pull করলে আসল ডেটা remote থেকে নামে।

🔑 সবচেয়ে গুরুত্বপূর্ণ কথা: DVC হলো Git এর সাথে parallel চলা একটি সিস্টেম। Code → Git। Data → DVC। দুটো একসাথে ব্যবহার করতে হয়।

ℹ️DVC কি একা ব্যবহার করা যায়?

হ্যাঁ, কিন্তু Git এর সাথে ব্যবহার করাটাই recommended। DVC একটি free, open-source, platform-agnostic টুল — অর্থাৎ Windows, Mac, Linux সব জায়গায় চলে এবং যেকোনো ML library এর সাথে কাজ করে।

৩
সেটআপ ও প্রথম পদক্ষেপ

এখন আমরা হাতে-কলমে শিখব। আমরা একটি road accident prediction প্রজেক্ট ব্যবহার করব উদাহরণ হিসেবে।

☁️ পদক্ষেপ ৩: Remote Storage সেট করা

DVC কে বলতে হবে ডেটা কোথায় রাখবে। দুটো উপায় দেখব:

উপায় ১: Local Storage (নিজের কম্পিউটারে)

Terminal — Local Remote Setup
# accidents ফোল্ডারে (Template_MLOps_accidents এর বাইরে) একটি ফোল্ডার তৈরি
mkdir ../dvc_remote

# এই ফোল্ডারকে DVC এর default remote storage হিসেবে সেট করুন
# -d মানে default, remote_storage হলো এই location এর label
dvc remote add -d remote_storage ../dvc_remote

এখন .dvc/config ফাইলটি দেখতে এরকম হবে:

.dvc/config
[core]
    remote = remote_storage # default remote এর নাম
['remote "remote_storage"']
    url = ../../dvc_remote # আমাদের local ফোল্ডারের path
✅এখন সব প্রস্তুত!

DVC initialize হয়েছে এবং remote storage সেট হয়েছে। এখন ডেটা ট্র্যাক করা শুরু করতে পারি।

🏦 ব্যাংক লকার দিয়ে বুঝি

dvc remote add মানে হলো — আপনি ব্যাংকে (remote storage) একটি লকার খুলছেন। dvc push মানে লকারে টাকা (ডেটা) রাখা। dvc pull মানে লকার থেকে টাকা বের করা। .dvc ফাইল হলো লকারের চাবি।

৪
ডেটা ট্র্যাক করা — DVC এর মূল কাজ

📌 dvc add — ডেটা ট্র্যাকিং শুরু করা

⚠️আগে এটা করুন!

dvc add করার আগে .gitignore ফাইলে /data/ লাইনটি comment out করুন (সামনে # দিন)। না করলে error আসবে।

Terminal — dvc add
# data/raw ফোল্ডারটিকে DVC tracking এ যোগ করুন
dvc add data/raw

এই একটি কমান্ডে ৩টি জিনিস একসাথে হয়:

চিত্র ৪: dvc add করলে কী কী হয়

এখন raw.dvc ফাইলটি খুললে এরকম দেখাবে:

data/raw.dvc
outs:
- md5: 90c3e04bb8fa1558eb70f9096b5b6010.dir
  size: 31082914
  nfiles: 4
  path: raw
💡MD5 কী?

MD5 হলো একটি hashing function। যেকোনো ফাইলকে একটি unique "fingerprint" এ রূপান্তর করে। ফাইল পরিবর্তন হলে MD5ও পরিবর্তন হয়। DVC এটা দিয়ে বোঝে কোন ভার্সন কোনটা।

📤 Git এ Commit ও DVC এ Push

Terminal — Git add ও commit
# ছোট pointer ফাইলগুলো Git এ যোগ করুন

git commit -m "First commit with setup and DVC files"

# বড় আসল ডেটা DVC remote এ push করুন

# pointer ফাইল GitHub এ push করুন
git push

📥 ডেটা Download করা

দুটো পরিস্থিতিতে ডেটা download করতে হয়:

১ ডেটা remote এ আছে, local এ দরকার। ২ আগের ভার্সনে ফিরে যেতে চাই।

Terminal — Download করা
# ধরুন আমরা local ডেটা delete করে ফেলেছি

rm -rf .dvc/cache

━━━━━ পদ্ধতি ১: fetch + checkout (আলাদাভাবে) ━━━━━
# Remote থেকে cache এ আনুন
dvc fetch data/raw.dvc

🕰️ ডেটার ভার্সন ব্যবস্থাপনা — Time Travel!

এটাই DVC এর সবচেয়ে শক্তিশালী দিক। একাধিক ভার্সন তৈরি করুন, যেকোনো সময় যেকোনো ভার্সনে ফিরে যান।

একটি নতুন ভার্সন তৈরির workflow:

Terminal — Dataset এর প্রথম ভার্সন তৈরি
# ধাপ ১: Script চালিয়ে preprocessed data তৈরি করুন
python ./src/data/make_dataset.py
# Input: ./data/raw | Output: ./data/preprocessed

# ধাপ ২: নতুন ফোল্ডার DVC tracking এ যোগ করুন
dvc add data/preprocessed

# ধাপ ৩: Git এ commit করুন
git add data/preprocessed.dvc data/.gitignore src/data/make_dataset.py
git commit -m "First preprocessing of the data"

# ধাপ ৪: Tag যোগ করুন (optional কিন্তু খুবই useful!)
git tag -a first_preprocess -m "Initial preprocessing"
git push origin --tags

# ধাপ ৫: Push করুন
dvc push
git push
💡Tag কী?

Tag হলো একটি commit এর উপর দেওয়া নাম। যেমন first_preprocess নামের tag দিলে পরে সহজে সেই commit এ ফিরে যেতে পারবেন, লম্বা hash code মনে না রেখেও।

dvc commit — Git commit থেকে আলাদা!

⚠️গুরুত্বপূর্ণ পার্থক্য

git commit: একটি নির্দিষ্ট সময়ে directory এর snapshot নেয়।
dvc commit: শুধু metadata (.dvc ফাইল) update করে, remote location এ কী আছে তা আপডেট করে। আগে থেকে tracked ফাইল পরিবর্তন হলে dvc commit ব্যবহার করুন।

Terminal — দ্বিতীয় ভার্সন (data পরিবর্তন করার পর)
# make_dataset.py এ পরিবর্তন করে আবার চালান
python ./src/data/make_dataset.py

# preprocessed ফোল্ডার আগে থেকেই tracked, তাই dvc commit
dvc commit # 'y' টাইপ করে confirm করুন

git add data/preprocessed.dvc src/data/make_dataset.py
git commit -m "Added new columns to dataset"
dvc push
git push

আগের ভার্সনে ফিরে যাওয়া (Time Travel):

Terminal — পুরনো ভার্সনে ফিরে যাওয়া
# সব commit এর ইতিহাস দেখুন (একটি নির্দিষ্ট তারিখের পর থেকে)
git log --since="2024-05-25" --all

# "First preprocessing of the data" commit এর hash code নোট করুন
# যেমন: abc1234def5678...

# সেই ভার্সনে যান
git checkout <HASH_CODE>
dvc pull # সেই সময়ের ডেটা নামাবে
✅ এই অধ্যায়ের সারসংক্ষেপ

ডেটা ট্র্যাকিং এর মূল workflow: dvc add → git add .dvc file → git commit → dvc push → git push

ডেটা ফিরে পাওয়া: git checkout <version> → dvc pull

এখন পর্যন্ত প্রতিটি ধাপ আলাদাভাবে চালাতে হয়েছে। DVC Pipeline দিয়ে পুরো ML workflow কে একটি automated chain এ পরিণত করা যায়।

🏭 কারখানার Assembly Line দিয়ে বুঝি

একটি গাড়ি তৈরিতে অনেক ধাপ আছে: কাঁচামাল → ফ্রেম তৈরি → ইঞ্জিন বসানো → রং করা → পরীক্ষা করা। প্রতিটি ধাপের output পরবর্তী ধাপের input। DVC Pipeline ঠিক এরকম একটি assembly line তৈরি করে।

আমাদের pipeline এ তিনটি ধাপ থাকবে:

prepare
raw → preprocessed
→
train
preprocessed → model
→
evaluate
model → metrics

# পুরনো individual .dvc ফাইল এবং output মুছুন
dvc remove data/preprocessed.dvc models/trained_model.joblib.dvc --outs

📋 Stage তৈরি করা — dvc stage add

প্রতিটি stage সংজ্ঞায়িত করতে ৩টি জিনিস বলতে হয়: Dependencies (-d) Outputs (-o) Command

Stage ১: prepare (ডেটা প্রস্তুত করা)

Terminal — prepare stage
dvc stage add -n prepare \
    -d src/data/make_dataset.py -d data/raw \
    -o data/preprocessed \
    python src/data/make_dataset.py

# -n prepare → এই stage এর নাম 'prepare'
# -d script.py → dependency: script পরিবর্তন হলে পুনরায় চালাবে
# -d data/raw → dependency: raw data পরিবর্তন হলে পুনরায় চালাবে
# -o data/preprocessed → output: এই folder DVC track করবে

Stage ২: train (মডেল ট্রেন করা)

Terminal — train stage
dvc stage add -n train \
    -d src/models/train_model.py -d data/preprocessed \
    -o models/trained_model.joblib \
    python src/models/train_model.py

Stage ৩: evaluation (মডেল মূল্যায়ন)

Terminal — evaluation stage
dvc stage add -n evaluation \
    -d src/models/evaluate_model.py -d models/trained_model.joblib \
    -M metrics/accuracy.json \
    python src/models/evaluate_model.py

# -M (বড় M) মানে এটি Metric ফাইল
# dvc metrics show দিয়ে দেখা যাবে
# -o এর মতো কিন্তু DVC জানে এটা metric
💡-o বনাম -M এর পার্থক্য

-o: সাধারণ output, DVC remote এ push হয়
-M: Metrics output, dvc metrics show দিয়ে সহজে দেখা যায়, Git এ tracked থাকে (cache: false)

সব stage যোগ করার পর dvc.yaml ফাইলটি এরকম দেখাবে:

dvc.yaml — পূর্ণ pipeline definition
stages:
  prepare:
    cmd: python src/data/make_dataset.py
    deps:
    - data/raw
    - src/data/make_dataset.py
    outs:
    - data/preprocessed

  train:
    cmd: python src/models/train_model.py
    deps:
    - data/preprocessed
    - src/models/train_model.py
    outs:
    - models/trained_model.joblib

  evaluation:
    cmd: python src/models/evaluate_model.py
    deps:
    - models/trained_model.joblib
    - src/models/evaluate_model.py
    metrics:
    - metrics/accuracy.json:
        cache: false

▶️ dvc repro — Pipeline চালানো

Terminal — Pipeline চালানো
# পুরো pipeline চালান
dvc repro

# শুধু একটি নির্দিষ্ট stage চালান
dvc repro prepare

# Metrics দেখুন
dvc metrics show
✅dvc repro এর স্মার্ট feature

দ্বিতীয়বার dvc repro চালালে, যে stage গুলোর dependencies পরিবর্তন হয়নি সেগুলো skip করবে। শুধু পরিবর্তিত অংশ পুনরায় চালাবে — সময় ও resources বাঁচায়।

🌐 DAG ও dvc dag কমান্ড

💡DAG কী?

DAG = Directed Acyclic Graph। মানে একটি graph যেখানে arrows একদিকে যায় এবং কোনো cycle নেই। আমাদের pipeline এর প্রতিটি stage node, এবং তাদের সংযোগ edges।

চিত্র ৭: আমাদের Pipeline এর DAG (dvc dag command এ যা দেখা যায়)
Terminal — Terminal এ DAG দেখুন
dvc dag

# Output এরকম দেখাবে:
+---------------+
| data/raw.dvc |
+---------------+
       *
       *
       *
+----------+
| prepare |
+----------+
       *
+-------+
| train |
+-------+
       *
+------------+
| evaluation |
+------------+

💡dvc.lock কী?

dvc.lock হলো pipeline এর বর্তমান state এর snapshot। এটি প্রতিটি stage এর input ও output এর MD5 hash রাখে। এই ফাইল দেখে DVC বোঝে কোন stage পুনরায় চালাতে হবে।

ধাপ ২: ৫টি Script তৈরি করুন

এই ৫টি script তৈরি করতে হবে (নাম সাজেশন দেওয়া হলো):

১
src/data/data_split.py — Data Splitting
Python — data_split.py এর structure
import pandas as pd
from sklearn.model_selection import train_test_split

# Download data
url = "https://datascientest-mlops.s3.eu-west-1.amazonaws.com/mlops_dvc_fr/raw.csv"
df = pd.read_csv(url)

# Split features and target
X = df.drop('silica_concentrate', axis=1)
y = df['silica_concentrate']

# Train/test split
X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.2)

# Save to data/processed/
X_train.to_csv('data/processed/X_train.csv', index=False)
X_test.to_csv('data/processed/X_test.csv', index=False)
y_train.to_csv('data/processed/y_train.csv', index=False)
y_test.to_csv('data/processed/y_test.csv', index=False)
২
src/data/normalize.py — Data Normalization

StandardScaler বা MinMaxScaler দিয়ে X_train ও X_test scale করুন। X_train_scaled.csv ও X_test_scaled.csv হিসেবে save করুন।

৩
src/models/grid_search.py — Best Parameters খোঁজা

GridSearchCV দিয়ে model parameters optimize করুন। Best params best_params.pkl হিসেবে models/ এ save করুন।

৪
src/models/training.py — Model Training

best_params.pkl ব্যবহার করে final model train করুন। gbr_model.pkl হিসেবে models/ এ save করুন।

৫
src/models/evaluate.py — Model Evaluation

Test data তে predict করুন। Predictions save করুন। MSE, R2 calculate করে scores.json এ save করুন।

Python — scores.json format
# scores.json এরকম হবে:
{
  "MSE": 0.1234,
  "R2": 0.8765
}

ধাপ ৩: DVC Pipeline সেটআপ

Terminal — Exam Pipeline
# split stage
dvc stage add -n split -d src/data/data_split.py \
  -o data/processed/X_train.csv -o data/processed/X_test.csv \
  -o data/processed/y_train.csv -o data/processed/y_test.csv \
  python src/data/data_split.py

# normalize stage
dvc stage add -n normalize \
  -d src/data/normalize.py \
  -d data/processed/X_train.csv -d data/processed/X_test.csv \
  -o data/processed/X_train_scaled.csv \
  -o data/processed/X_test_scaled.csv \
  python src/data/normalize.py

# gridsearch stage
dvc stage add -n gridsearch \
  -d src/models/grid_search.py \
  -d data/processed/X_train_scaled.csv \
  -d data/processed/y_train.csv \
  -o models/best_params.pkl \
  python src/models/grid_search.py

# training stage
dvc stage add -n training \
  -d src/models/training.py \
  -d models/best_params.pkl \
  -d data/processed/X_train_scaled.csv \
  -d data/processed/y_train.csv \
  -o models/gbr_model.pkl \
  python src/models/training.py

# evaluate stage
dvc stage add -n evaluate \
  -d src/models/evaluate.py \
  -d models/gbr_model.pkl \
  -d data/processed/X_test_scaled.csv \
  -d data/processed/y_test.csv \
  -o data/processed/prediction.csv \
  -M metrics/scores.json \
  python src/models/evaluate.py

🚀 DVC কমান্ড রেফারেন্স

dvc init
নতুন DVC project শুরু করুন। .dvc/ folder ও .dvcignore তৈরি হয়।
dvc remote add -d <name> <url>
Remote storage যোগ করুন। -d মানে default।
dvc add <file/folder>
ফাইল/ফোল্ডার DVC tracking এ যোগ করুন। .dvc ফাইল তৈরি হয়।
dvc commit
আগে থেকে tracked ফাইলের পরিবর্তন record করুন।
dvc push
Cache থেকে remote storage এ আপলোড করুন।
dvc pull
Remote থেকে ডেটা নামান (fetch + checkout)।
dvc fetch <file.dvc>
Remote থেকে cache এ আনুন। Workspace এ কপি করে না।
dvc checkout
Cache থেকে workspace এ কপি করুন।
dvc stage add
Pipeline এ নতুন stage যোগ করুন।
dvc repro
Pipeline reproduce করুন (পরিবর্তিত stages পুনরায় চালায়)।
dvc dag
Pipeline এর DAG (dependency graph) দেখুন।
dvc metrics show
সব metrics ফাইলের মান দেখুন।
dvc status
কোন ফাইল পরিবর্তন হয়েছে দেখুন।
dvc remove <file.dvc>
DVC tracking থেকে ফাইল সরান।
dvc config core.analytics false
DVC usage analytics বন্ধ করুন।

চিত্র ৮: DVC + Git এর সম্পূর্ণ Workflow

🆚 Git বনাম DVC — সাথে যোগসূত্র

Git কমান্ড DVC সমতুল্য উদ্দেশ্য
git init dvc init Project শুরু করা
git add file dvc add file ট্র্যাকিং এ যোগ করা
git commit dvc commit পরিবর্তন record করা
git push dvc push Remote এ আপলোড
git pull dvc pull Remote থেকে ডাউনলোড
git clone dvc fetch + dvc checkout সম্পূর্ণ কপি
git status dvc status পরিবর্তন দেখা
git log — ইতিহাস দেখা (Git ই দেখায়)

❓ সাধারণ সমস্যা ও সমাধান

🔴সমস্যা: "not currently on a branch"

কারণ: আপনি একটি পুরনো commit এ checkout করেছেন (detached HEAD state)।
সমাধান: git push origin HEAD:accidents_v2

🔴সমস্যা: dvc add এ error

কারণ: .gitignore এ /data/ আছে।
সমাধান: .gitignore এ /data/ লাইনের আগে # দিয়ে comment করুন।

🔴সমস্যা: dvc push authenticate করছে না

কারণ: credentials ঠিক নেই।
সমাধান: Google Drive এর জন্য browser এ login করুন। প্রথমবার authentication দরকার।
