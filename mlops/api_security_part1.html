🌐 API কী জিনিস? (একদম শুরু থেকে)

API মানে হলো Application Programming Interface। এই কথাটা শুনতে ভারী মনে হলেও ব্যাপারটা খুব সহজ।

🍽️ রেস্তোরাঁর উদাহরণ:

কল্পনা করুন আপনি একটি রেস্তোরাঁয় গিয়েছেন। আপনি রান্নাঘরে গিয়ে সরাসরি রাঁধুনিকে বলছেন না। বরং ওয়েটার (service staff) আপনার অর্ডার নিয়ে রান্নাঘরে যায়, খাবার নিয়ে আসে। এই ওয়েটার-ই হলো API।

আপনার অ্যাপ → API → সার্ভার (ডেটাবেস বা সার্ভিস)

অ্যাপ → API → সার্ভার: অনুরোধ পাঠানো ও উত্তর পাওয়া

আধুনিক সফটওয়্যারে হাজারো ছোট ছোট সার্ভিস (microservices) একসাথে কাজ করে। প্রতিটি সার্ভিস API-এর মাধ্যমে একে অপরের সাথে কথা বলে। এজন্যই API নিরাপত্তা এত গুরুত্বপূর্ণ।

⚠️ নিরাপত্তা কেন দরকার?

ধরুন আপনার একটি ব্যাংক অ্যাপ আছে। এই অ্যাপ API-এর মাধ্যমে ব্যালেন্স দেখায়, টাকা পাঠায়। এখন যদি কোনো হ্যাকার এই API-এ সরাসরি ঢুকতে পারে, তাহলে কী হবে? 😱

🚫

হ্যাকার বারবার রিকোয়েস্ট করে সার্ভার বন্ধ করে দিতে পারে

বিনামূল্যে সার্ভিস ব্যবহার করে আপনার খরচ বাড়িয়ে দিতে পারে

বাস্তব উদাহরণ: ২০১৯ সালে Facebook-এর একটি API দুর্বলতার কারণে ৫৩ কোটি ব্যবহারকারীর ফোন নম্বর ও ব্যক্তিগত তথ্য ফাঁস হয়ে গিয়েছিল!
🔒 Public vs Private Resources

API দুই ধরনের রিসোর্স পরিচালনা করে:

🌍

Public Resources (সর্বজনীন)

যেকেউ এই ডেটা দেখতে পারে। যেমন: আবহাওয়ার তথ্য, নিউজ ফিড, ব্লগ পোস্ট।

তবুও একটা API Key লাগতে পারে — কে কতটুকু ব্যবহার করছে সেটা ট্র্যাক করতে।

🏢

Private Resources (গোপনীয়)

শুধু অনুমোদিত ব্যক্তি/সার্ভিস দেখতে পারবে। যেমন: ব্যাংক তথ্য, মেডিকেল রেকর্ড, কর্মীর বেতন।

কঠোর নিরাপত্তা প্রয়োজন।

Public API — সবার জন্য | Private API — শুধু অনুমোদিতদের জন্য

🔑 Authentication বনাম Authorization

এই দুটি শব্দ প্রায়ই গুলিয়ে ফেলা হয়। কিন্তু এরা সম্পূর্ণ আলাদা জিনিস!

🪪

Authentication (প্রমাণীকরণ)

"তুমি কে?" — এটি যাচাই করে ব্যবহারকারী আসলেই সে যে পরিচয় দিচ্ছে কিনা।

উদাহরণ: পাসপোর্ট দেখানো, পাসওয়ার্ড দেওয়া, ফিঙ্গারপ্রিন্ট স্ক্যান

🚪

Authorization (অনুমোদন)

"তোমার কী করার অনুমতি আছে?" — পরিচয় জানার পরে, সে কোন কাজ করতে পারবে তা নির্ধারণ করে।

উদাহরণ: Admin সব দেখতে পারবে, User শুধু নিজেরটা

Authentication → Authorization → Resource Access

সহজ মনে রাখার উপায়:
  • 🪪 Authentication = "আমি রাহুল" — পরিচয় প্রমাণ করা (Who are you?)
  • 🚪 Authorization = "রাহুলের Admin প্যানেলে যাওয়ার অনুমতি আছে কি?" (What can you do?)
📊 Traceability — ট্র্যাকিং ও লগিং

Traceability মানে API-তে কে, কখন, কী করেছে — সেটা রেকর্ড রাখা। এটাকে লগ (Log) বলে।

প্রতিটি API রিকোয়েস্টে তিনটি তথ্য রেকর্ড করা হয়:

❓

What (কী করা হলো)

  • কোন endpoint ব্যবহার হলো
  • কোন HTTP method — GET, POST, DELETE
👤

Who (কে করলো)

  • কোন ব্যবহারকারী
  • কোন ডিভাইস (মোবাইল/ব্রাউজার)
  • কোন IP address থেকে
⏰

When (কখন হলো)

  • তারিখ ও সময়
  • কতক্ষণ লাগলো
# একটি সাধারণ লগ এন্ট্রির উদাহরণ "2024-03-15 14:32:07" | GET /api/weather | User: rahul_123 | IP: 192.168.1.50 | Status: 200 OK "2024-03-15 14:33:02" | DELETE /api/user/5 | User: unknown | IP: 45.23.11.99 | Status: 403 Forbidden "2024-03-15 14:33:45" | POST /api/login | User: admin | IP: 45.23.11.99 | Status: 401 Unauthorized
🛡️ IP Restriction (IP সীমাবদ্ধতা):

যদি আপনার API শুধু বাংলাদেশি ব্যবহারকারীদের জন্য হয়, তাহলে অন্য দেশের IP থেকে রিকোয়েস্ট আসলে সেটা সন্দেহজনক। আপনি নির্দিষ্ট IP বা দেশ ব্লক করতে পারেন।

🛂 বর্ডার চেকপোস্টের সাথে তুলনা

API নিরাপত্তার তিনটি স্তর বুঝতে বর্ডার পার হওয়ার উদাহরণটি সবচেয়ে ভালো:

বর্ডার পার = API নিরাপত্তার তিন স্তর

১
পাসপোর্ট দেখানো = Authentication কাস্টম অফিসার পাসপোর্ট দেখে বলেন — "হ্যাঁ, এটি আসল পাসপোর্ট, এই মানুষটি আসলেই Ahmed"।
২
কম্পিউটারে তথ্য যাচাই = Authorization কম্পিউটারে চেক করা হয় — "Ahmed কি এই দেশে প্রবেশের নিষিদ্ধ তালিকায় আছে?" যদি না থাকে, ঢুকতে পারবে।
৩
রেজিস্ট্রিতে নাম লেখা = Traceability Ahmed কখন প্রবেশ করলো, কোন পোর্ট দিয়ে — এই তথ্য সিস্টেমে সংরক্ষিত হলো।
📡 HTTP Status Codes — সার্ভার কী বলছে?

API রিকোয়েস্ট পাঠালে সার্ভার একটি নম্বর কোড দিয়ে জানায় — কী হলো। এই কোডগুলো জানা খুব জরুরি!

200
OK — সবকিছু ঠিক আছে ✅
201
Created — নতুন কিছু তৈরি হয়েছে ✨
401
Unauthorized — পরিচয় দেওনি / ভুল পাসওয়ার্ড ❌
403
Forbidden — পরিচয় আছে কিন্তু অনুমতি নেই 🚫
404
Not Found — জিনিসটা খুঁজে পাওয়া গেলো না 🔍
429
Too Many Requests — অনেক বেশি রিকোয়েস্ট ⚡
500
Server Error — সার্ভারে সমস্যা 💥
401 বনাম 403 — এই দুটির পার্থক্য:
  • 401 = "তুমি কে সেটাই জানি না" — Login করোনি বা ভুল credentials দিয়েছ
  • 403 = "তুমি কে জানি, কিন্তু তোমার এই কাজের অনুমতি নেই" — Logged in কিন্তু unauthorized
⚡ Rate Limiting — রিকোয়েস্ট সীমাবদ্ধতা

Rate Limiting মানে একটি নির্দিষ্ট সময়ের মধ্যে কতটি রিকোয়েস্ট করা যাবে তার সীমা নির্ধারণ করা।

🚰 পানির ট্যাপের উদাহরণ:

ভাবুন একটি পাইপলাইনে প্রতি মিনিটে সর্বোচ্চ ১০ বালতি পানি দেওয়া যায়। একসাথে ১০০ বালতি নিতে চাইলে পাইপ ফেটে যাবে। Rate Limiting এই সীমা নিশ্চিত করে।

Rate Limiting: প্রতি মিনিটে ৬০টি রিকোয়েস্টের পর ব্লক

Rate Limiting কেন দরকার?

  • 🛡️ DDoS আক্রমণ থেকে সুরক্ষা
  • 💰 অতিরিক্ত ব্যবহার রোধ করা
  • ⚖️ সব ব্যবহারকারীর মধ্যে সম্পদ ভাগ করা
  • 📊 API ব্যবহার পরিমাপ করা
🌤️ বাস্তব উদাহরণ: OpenWeatherMap API

OpenWeatherMap একটি জনপ্রিয় আবহাওয়া API। এটি দিয়ে আমরা authentication ও authorization ব্যবহারিকভাবে বুঝতে পারি।

API Key দিয়ে রিকোয়েস্ট

# URL structure: প্রশ্নচিহ্নের পরে দুটি parameter # q = শহরের নাম, appid = আপনার API Key https://api.openweathermap.org/data/2.5/weather?q=Dhaka&appid=XXXXXXXXXXXXXX # Python দিয়ে একই কাজ: import requests response = requests.get( url="https://api.openweathermap.org/data/2.5/weather", params={ "q": "Dhaka", "appid": "আপনার_API_KEY_এখানে" } ) print(response.status_code) # 200 মানে সফল print(response.json()) # আবহাওয়ার ডেটা

ভুল API Key দিলে কী হয়?

# ভুল key বা key ছাড়া রিকোয়েস্ট: https://api.openweathermap.org/data/2.5/weather?q=Dhaka # সার্ভারের উত্তর: Status: 401 Unauthorized { "cod": 401, "message": "Invalid API key. Please see https://openweathermap.org/faq" } # মানে: Authentication ব্যর্থ হয়েছে — পরিচয় প্রমাণ হয়নি

Free Plan-এ Premium Endpoint ব্যবহার করলে?

# এই endpoint শুধু paid plan-এর জন্য: https://pro.openweathermap.org/data/2.5/forecast/climate?lat=23&lon=90&appid=XXXXX # সার্ভারের উত্তর: Status: 401 (বা 403 হওয়া উচিত) # মানে: Authorization ব্যর্থ হয়েছে — free plan-এ এই সুবিধা নেই
💡 মজার বিষয়: কখনও কখনও API সঠিক error কোড না দিলেও (403 দেওয়ার বদলে 401 দেয়), ব্যবহারিক উদ্দেশ্যটা একই — আপনার request ব্লক করা হচ্ছে।

Rate Limit অতিক্রম করলে?

# Free plan: প্রতি মিনিটে সর্বোচ্চ ৬০টি রিকোয়েস্ট # এর বেশি হলে আপনার API key block হয়ে যাবে! # OpenWeatherMap আপনাকে email করবে সতর্ক করতে import requests API_KEY = "XXXX" url = "https://api.openweathermap.org/data/2.5/weather" try: for i in range(-90, 90, 5): # ৩৬টি latitude for j in range(-180, 180, 10): # ৩৬টি longitude response = requests.get(url=url, params={"lat": i, "lon": j, "appid": API_KEY}) response.raise_for_status() # error হলে exception except requests.HTTPError: print(response.status_code) # 429 দেখাবে!
