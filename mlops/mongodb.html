NoSQL কী জিনিস?

প্রথমে বুঝতে হবে — ডেটাবেস কী? সহজ করে বলো — ডেটাবেস হলো একটা বিশাল খাতা যেখানে তুমি তথ্য রাখো, খোঁজো, আপডেট করো।

বছরের পর বছর ধরে সবাই Relational Database ব্যবহার করতো — যেমন MySQL, PostgreSQL। এগুলোতে ডেটা রাখা হয় সারি আর কলামের টেবিলে — ঠিক Excel Spreadsheet এর মতো।

সমস্যা কোথায়?

ধরো তুমি একটা ওয়েবসাইটের ইউজার ট্র্যাক করছো। প্রথমে শুধু নাম-ইমেইল লাগতো। এখন নতুন ফিচার এলো — কেউ ৩টা ফোন নম্বর দেয়, কেউ ১টাও দেয় না। কেউ পোষা প্রাণীর তথ্য দেয়, কেউ দেয় না।

Relational DB-তে প্রতিবার টেবিলের কাঠামো বদলাতে হয়! এটা ঝামেলার।

NoSQL — সমাধান এলো!

NoSQL মানে শুধু "No SQL" না — এখন এর মানে "Not Only SQL" — শুধু SQL নয়, আরো আছে।

🗄️ Relational (SQL)

• কঠোর schema (ছাঁচ) লাগে
• সব row একই structure
• পুরনো, পরিপক্ক
• সম্পর্ক বোঝাতে ভালো

📄 NoSQL

• নমনীয় structure
• প্রতিটি document আলাদা হতে পারে
• Big Data-র জন্য উপযুক্ত
• দ্রুত উন্নয়নের জন্য সহজ

Document-Oriented Database কীভাবে কাজ করে?

এখানে ডেটা রাখা হয় Document আকারে। Document মানে একটা key-value জোড়ার সমষ্টি — এটা অনেকটা Python-এর Dictionary বা JSON ফাইলের মতো।

মনে রাখো: Document DB-তে একই Collection-এ দুটো Document সম্পূর্ণ আলাদা structure রাখতে পারে। এটাই সবচেয়ে বড় সুবিধা!

MongoDB-র তিনটি স্তর

MongoDBRelational DBবাস্তব উদাহরণ
DatabaseDatabaseপুরো একটা প্রজেক্ট (e.g. "ecommerce")
CollectionTableএকটা ধরনের তথ্য (e.g. "products")
DocumentRowএকটা নির্দিষ্ট পণ্যের তথ্য
FieldColumnপণ্যের নাম, দাম, ইত্যাদি

JSON ফরম্যাট — একটু বোঝাই

MongoDB-তে ডেটা BSON ফরম্যাটে রাখা হয় (Binary JSON), কিন্তু তুমি দেখবে JSON আকারে। JSON হলো key-value জোড়া:

JSON উদাহরণ
{
  "name": "Saikot",           // string (লেখা)
  "age": 25,                 // number (সংখ্যা)
  "isStudent": true,        // boolean (হ্যাঁ/না)
  "address": {              // nested object (ভেতরে object)
    "city": "Dhaka",
    "zip": "1200"
  },
  "hobbies": ["coding", "reading"]  // array (তালিকা)
}
JSON vs BSON: JSON হলো মানুষ পড়তে পারে এমন ফরম্যাট। BSON হলো Binary — কম্পিউটার দ্রুত প্রসেস করতে পারে। MongoDB ভেতরে BSON রাখে, বাইরে JSON দেখায়।

ইনস্টলেশন — Docker দিয়ে

সরাসরি MongoDB ইনস্টল না করে আমরা Docker ব্যবহার করবো। Docker হলো একটা "বাক্স" যেখানে পুরো সফটওয়্যার প্যাক করা থাকে — তোমার কম্পিউটারে আলাদা কিছু ইনস্টল করতে হয় না।

docker-compose.yml ফাইল — লাইন বাই লাইন বোঝাই

docker-compose.yml
version: "3.3"          # Docker Compose ফাইলের সংস্করণ
services:               # কোন কোন সার্ভিস চালাবো তার তালিকা
  mongodb:              # আমাদের MongoDB সার্ভিসের নাম
    image: mongo:7.0    # MongoDB এর "রেসিপি" — version 7.0
    container_name: my_mongo  # container-এর নাম
    environment:          # পরিবেশ চলক (secret তথ্য)
      MONGO_INITDB_ROOT_USERNAME: datascientest  # ব্যবহারকারীর নাম
      MONGO_INITDB_ROOT_PASSWORD: dst123         # পাসওয়ার্ড
    volumes:              # কম্পিউটার ↔ container ফোল্ডার সংযোগ
      - ./sample_training:/data/db
    ports:                # port forwarding — 27017:27017
      - "27017:27017"      # তোমার PC:container এর port

পদক্ষেপে পদক্ষেপে চালু করো

  1. Docker আপডেট করো ও প্যাকেজ ইনস্টল করো
  2. docker-compose up -d — background-এ MongoDB চালু করো
  3. docker ps — নিশ্চিত করো container চলছে
  4. docker exec -it my_mongo bash — container-এ ঢোকো
  5. mongosh -u datascientest -p dst123 — MongoDB Shell চালু করো
Port কী? Port হলো কম্পিউটারের একটা "দরজা"। MongoDB সবসময় 27017 দরজায় কথা শোনে। 27017:27017 মানে — তোমার কম্পিউটারের 27017 দরজা, container-এর 27017 দরজার সাথে সংযুক্ত।

db মানে কী? MongoDB Shell-এ db মানে বর্তমানে যে database-এ আছো সেটা। যদি use sample করো, তাহলে db = sample।

R — Read: ডকুমেন্ট পড়া

findOne() — একটা document পাও
# zips collection থেকে যেকোনো একটা document দেখাও
db.zips.findOne()

# শর্ত দিয়ে খোঁজো — pop (জনসংখ্যা) যেখানে 3450
db.zips.findOne({"pop": 3450})

# state = "MA" যেখানে
db.zips.findOne({"state": "MA"})
find() — একাধিক document পাও
# MA state-এর সব document
db.zips.find({"state": "MA"})

# সব document দেখাও (20টা দেখাবে, বাকি দেখতে "it" লেখো)
db.zips.find()
findOne vs find: findOne() শুধু একটা document দেয়। find() সব matching document দেয় (একটা Cursor হিসেবে — সর্বোচ্চ 20টা একসাথে দেখায়)।

C — Create: নতুন Document তৈরি

insertOne() — একটা document যোগ করো
# একটা নতুন শহর যোগ করো
db.zips.insertOne({
  "city": "Paris",
  "pop": "1000000",
  "state": "France"
})
insertMany() — একসাথে অনেক document
db.zips.insertMany([
  {"city": "Paris",      "state": "France"},
  {"city": "Courbevoie", "state": "France"}
])

_id কী?

প্রতিটা document-এ MongoDB নিজেই একটা unique _id তৈরি করে। এটা ObjectId ধরনের — যেমন ObjectId("5c8eccc1...")। এটা সবসময় unique — কোনো দুটো document-এর _id কখনো এক হবে না।

U — Update: Document আপডেট করা

updateOne() — একটা document আপডেট
# BREMEN শহরের state পরিবর্তন করো
# প্রথম argument: কোন document → দ্বিতীয়: কী পরিবর্তন
db.zips.updateOne(
  {"city": "BREMEN"},           // খোঁজার শর্ত
  {$set: {"state": "France"}}  // পরিবর্তন: $set দিয়ে
)
$push — array-তে element যোগ
# grades collection-এ একটা student-এর score array-তে নতুন item যোগ
db.grades.updateOne(
  {"_id": ObjectId("56d5f7eb604eb380b0d8d9c8")},
  {$push: {"scores": {"exam": "quizz", "score": 100.0}}}
)
Operatorকাজউদাহরণ
$setfield-এর মান সেট করো{$set: {"age": 30}}
$pusharray-তে element যোগ করো{$push: {"tags": "new"}}
$incসংখ্যা বাড়াও/কমাও{$inc: {"count": 1}}

D — Delete: Document মুছা

deleteOne() / deleteMany()
# France state-এর সব document মুছো
db.zips.deleteMany({"state": "France"})

# পুরো collection মুছো (সাবধান!)
db.zips.drop()

# একটা database মুছো (সব collection মুছা গেলে database এমনিই মুছে যায়)
সাবধান! deleteMany() বা drop() করলে ডেটা আর ফিরে পাবে না। সবসময় backup রাখো!

Advanced MQL — শক্তিশালী Query

তুলনা Operator (Comparison)

সংখ্যার উপর শর্ত দিতে এগুলো ব্যবহার হয়:

Operatorমানেউদাহরণ
$eqসমান (=)pop = 5000
$neসমান নয় (≠)state ≠ "TX"
$gtবড় (>)pop > 10000
$ltছোট (<)pop < 5000
$gteবড় বা সমান (≥)pop ≥ 12678
$lteছোট বা সমান (≤)pop ≤ 20000
উদাহরণ
# জনসংখ্যা 12678 বা বেশি
db.zips.find({"pop": {$gte: 12678}})

# জনসংখ্যা 10000 থেকে 20000 এর মধ্যে (AND দিয়ে)
db.zips.find({
  $and: [
    {"pop": {$gt: 10000}},
    {"pop": {$lt: 20000}}
  ]
})

লজিক্যাল Operator

$expr — একই document-এর দুই field তুলনা
# grades collection-এ student_id আর class_id সমান যেগুলো
db.grades.find({
  $expr: {$eq: ["$student_id", "$class_id"]}
})
$expr কেন? সাধারণ query-তে একটা field-এর সাথে fixed value তুলনা করো। কিন্তু দুটো field একে অপরের সাথে তুলনা করতে হলে $expr লাগে।

Projection — শুধু দরকারি field দেখাও

মাঝে মাঝে পুরো document দরকার নেই — শুধু কিছু field দরকার। এটাকে Projection বলে।

উদাহরণ
# TX state-এর শহরগুলোর শুধু pop (জনসংখ্যা) দেখাও
db.zips.find(
  {"state": "TX"},  // ফিল্টার
  {"pop": 1}         // projection: 1 = দেখাও
)

# pop বাদে বাকি সব দেখাও
db.zips.find(
  {"state": "TX"},
  {"pop": 0}         // 0 = বাদ দাও
)

# _id বাদ দাও, city আর pop দেখাও
db.zips.find(
  {"state": "TX"},
  {"_id": 0, "city": 1, "pop": 1}
)
নিয়ম: Projection-এ ০ আর ১ একসাথে মেশানো যাবে না। ব্যতিক্রম: _id। যেমন {"_id": 0, "city": 1} — এটা চলবে।

Dot Notation — ভেতরের field ধরো

যদি document-এ nested object বা array থাকে, dot (.) দিয়ে ভেতরে ঢোকো:

উদাহরণ
# loc.y field দেখাও (nested object)
db.zips.find({}, {"loc.y": 1})

# acquisitions array-র প্রথম element-এর company name
# acquisitions.0 = প্রথম element (index 0)
# acquisitions.0.company.name = আরো ভেতরে
db.cie.find({}, {"acquisitions.0.company.name": 1})

$elemMatch — Array-র ভেতরে খোঁজো

Array-র কোনো element যদি একাধিক শর্ত পূরণ করে কিনা দেখতে চাও:

উদাহরণ
# কে LittleBigPlanet company acquire করেছে?
db.cie.find(
  {
    "acquisitions": {
      $elemMatch: {
        "acquired_year": 2010,
        "acquired_month": 3,
        "acquired_day": 2
      }
    }
  },
  {"name": 1}
)
// ০৬

Cursor Methods — ফলাফল নিয়ন্ত্রণ

find() একটা Cursor ফেরত দেয়। Cursor মানে — collection-এর উপর একটা pointer যা ধীরে ধীরে ডেটা দেয়। এই Cursor-এ কিছু দরকারি method আছে:

sort() — সাজাও

উদাহরণ
# student_id দিয়ে descending (বড় থেকে ছোট) সাজাও
db.grades.find().sort({"student_id": -1})
#                              -1 = descending (বড় → ছোট)
#                               1 = ascending (ছোট → বড়)

# দুটো key দিয়ে সাজাও
db.grades.find().sort({"student_id": -1, "class_id": 1})

limit() — সর্বোচ্চ কয়টা দেখাবে

উদাহরণ
# মাত্র ৫টা document দেখাও (pandas-এর head() এর মতো)
db.zips.find().limit(5)

# city অনুযায়ী সাজিয়ে প্রথম ৫টা
db.zips.find().limit(5).sort({"city": 1})

count() — গণনা করো

উদাহরণ
# মোট কতটা document আছে?
db.zips.find().count()

# TX state-এ কতটা শহর?
db.zips.find({"state": "TX"}).count()

Aggregation Framework — পাইপলাইন

MQL-এ কিছু সীমাবদ্ধতা আছে — যেমন nested field-এ সরাসরি খোঁজা যায় না। Aggregation Framework এই সমস্যা সমাধান করে।

$match — ফিল্টার stage

উদাহরণ
# cie collection: Seattle-এ office আছে এমন company
db.cie.aggregate([
  {$match: {"offices.city": "Seattle"}},
  {$project: {"_id": 1, "name": 1}}
])

# LittleBigPlanet কে acquire করেছে? (nested array খোঁজা)
db.cie.aggregate([
  {$match: {"acquisitions.company.name": "LittleBigPlanet"}}
])
$match-এর শক্তি: MQL-এর find()-এ nested array-তে সরাসরি খোঁজা কঠিন। কিন্তু $match dot notation দিয়ে সহজেই array-র ভেতরে ঢুকতে পারে।

$project — ফলাফলের shape বদলাও

উদাহরণ
# Elon Musk কোন company-তে ছিলেন, নতুন নামে দেখাও
db.cie.aggregate([
  {$match: {
    $and: [
      {"relationships.person.first_name": "Elon"},
      {"relationships.person.last_name": "Musk"}
    ]
  }},
  {$project: {
    "_id": 1,
    "society": "$name"   // name field-কে "society" নামে দেখাও
  }}
])

$group — গ্রুপ করো, সংখ্যা গোনো

উদাহরণ
# Paris-এ office আছে এমন company গুলো কোন বছর তৈরি হয়েছে?
# প্রতি বছরে কতটা company — সবচেয়ে বেশি থেকে সাজাও
db.cie.aggregate([
  {$match: {
    "offices.city": "Paris",
    "founded_year": {$gt: 1999}
  }},
  {$group: {
    "_id": "$founded_year",    // কোন field দিয়ে গ্রুপ?
    "nb_cie": {$sum: 1}         // প্রতি গ্রুপে কয়টা? গুনে দাও
  }},
  {$sort: {"nb_cie": -1}}       // সবচেয়ে বেশি থেকে সাজাও
])
// ০৮

Data Modeling-এর পদক্ষেপ

  3. প্রতিটা Collection-এর structure ঠিক করো — nested object না reference ID — কোনটা better?
  4. পরীক্ষা করো আর উন্নত করো — query slow? structure বদলাও।
