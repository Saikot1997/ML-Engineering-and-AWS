Apache Airflow কী?

ধরো তুমি প্রতিদিন সকালে কিছু কাজ করো — প্রথমে ডেটা download করো, তারপর সেটা clean করো, তারপর একটা report বানাও, আর শেষে সেটা email করো। এই কাজগুলো যদি manually করতে হয় প্রতিদিন, তাহলে ক্লান্তিকর। এখন যদি কেউ তোমার হয়ে এই পুরো sequence স্বয়ংক্রিয়ভাবে করে দিতে পারে — তাকেই বলে workflow orchestration tool।

Apache Airflow হলো এরকমই একটা open-source platform যেটা তোমার data workflows কে automate করে, schedule করে, আর monitor করে।

📌 সহজ ভাষায়
Airflow হলো একজন smart manager যে তোমার হয়ে সব কাজ ঠিক সময়ে, ঠিক ক্রমে করে দেয়। কোনো কাজ fail করলে সে নিজেই আবার চেষ্টা করে, তোমাকে email করে জানায়।

💾

Backup & DevOps

Database backup, server health check ইত্যাদি কাজ schedule করা যায়।

Airflow vs CI/CD — পার্থক্য কী?

অনেকে Airflow-কে Jenkins বা GitHub Actions-এর সাথে গুলিয়ে ফেলেন। এরা আসলে আলাদা কাজের জিনিস:

🌬️ Airflow (Orchestration)

  • কখন চলে: data বদলালে
  • কাজ: ETL, ML pipelines
  • উদাহরণ: "প্রতিদিন রাত ১২টায় sales data process করো"
  • trigger: schedule বা data event

⚙️ Jenkins/GitHub Actions (CI/CD)

  • কখন চলে: code বদলালে
  • কাজ: build, test, deploy
  • উদাহরণ: "নতুন code push করলে automatically deploy করো"
  • trigger: code commit/push

Workflow vs Dataflow — আরেকটা গুরুত্বপূর্ণ পার্থক্য

Workflow কাজের ক্রম নিয়ে কথা বলে। যেমন: "প্রথমে ডেটা নামাও, তারপর clean করো, তারপর save করো।" Airflow এটা করে।
Dataflow কাজের ভেতরে data কীভাবে flow করে সেটা নিয়ে। Apache Spark বা Flink এটা করে।
⚠️ সতর্কতা
Airflow-এ এক task থেকে অন্য task-এ বিশাল পরিমাণ data পাঠানো উচিত না। এটা data transport-এর জায়গা না — এটা শুধু task coordination করে।

Airflow Architecture — ভেতরের কলকব্জা

Airflow অনেকগুলো component মিলে তৈরি। এদের বোঝা দরকার কারণ এরা একসাথে কাজ করে:

Airflow Architecture Diagram
Webserver এটা তোমার সাথে কথা বলে। Browser-এ port 8080-এ গেলে যে dashboard দেখো সেটা এই Webserver serve করছে। এখানে DAG দেখো, task status দেখো, logs পড়ো।
Scheduler এটা Airflow-এর মস্তিষ্ক। সে ঠিক করে কোন task কখন চলবে। DAG file পড়ে, dependencies বোঝে, আর সঠিক সময়ে task queue-তে পাঠায়।
Executor Scheduler-এর মধ্যে থাকে। Scheduler বলে "এই task চালাও" আর Executor সেটা কীভাবে চালাবে তা ঠিক করে। Local, Celery, Kubernetes — বিভিন্ন ধরনের Executor আছে।
Workers আসল কাজ এরা করে। Executor যখন বলে "task চালাও", Workers সেই task execute করে। Multiple workers থাকলে parallel-এ কাজ করতে পারে।
Metadata DB এটা Airflow-এর স্মৃতি। সব DAG-এর history, task-এর status, connections, variables — সব এখানে store থাকে। সাধারণত PostgreSQL ব্যবহার করা হয়।
DAG Directory তুমি যে Python file-এ DAG লেখো সেগুলো এই folder-এ রাখো। Scheduler নিয়মিত এই folder স্ক্যান করে নতুন DAG খোঁজে।

প্রথম DAG তৈরি

DAG, Task, Operator, Run — মূল ধারণাগুলো

DAG কী? — গ্রাফ তত্ত্ব থেকে শুরু

DAG মানে Directed Acyclic Graph — এটা একটু mathematical শোনাচ্ছে, কিন্তু ভয় নেই, ব্যাখ্যা করছি।

Graph কী? — কিছু বিন্দু (nodes) আর তাদের মধ্যে সংযোগ (edges) নিয়ে তৈরি। ঢাকার metro map-এ স্টেশন হলো nodes, আর স্টেশনের মধ্যে রেললাইন হলো edges।

DAG বোঝার উদাহরণ — সকালে জুতো পরার ক্রম

Directed = arrows একটা দিকে যায় (task 1 → task 2, কিন্তু task 2 → task 1 না)।
Acyclic = কোনো loop নেই। একবার task 6-এ গেলে আবার task 1-এ ফিরে আসা যায় না।

🔴 গুরুত্বপূর্ণ
DAG-এর topology (আকৃতি) অনেক গুরুত্বপূর্ণ! যদি Task 2 fail করে, তাহলে Task 2-এর উপর যারা নির্ভর করে তারাও fail হবে। কিন্তু Task 4-এর উপর নির্ভরশীল tasks চলতে পারবে।

Task, Operator, Run — তিনটা আলাদা জিনিস

Task একটা কাজের সংজ্ঞা। যেমন "এই Python function চালাও"। একটা Python function-এর মতো — define করা আছে কিন্তু এখনো চলেনি।
Operator Task define করার tool। Airflow-এ অনেক built-in Operator আছে — PythonOperator (Python চালায়), BashOperator (Bash command চালায়), PostgresOperator (SQL চালায়) ইত্যাদি।
DAG Run একটা DAG যখন actually execute হয়, সেটা একটা "DAG Run"। একটা DAG অনেকবার run হতে পারে।
Task Instance একটা DAG Run-এর মধ্যে একটা Task যখন চলে, সেটা একটা "Task Instance"। Log, status সব Task Instance-এর জন্য আলাদা।

Operatorকী করেউদাহরণ

প্রথম DAG লেখা — হাতে-কলমে

my_first_dag.py নামে একটা file তৈরি করো ./dags/ ফোল্ডারে:

python — my_first_dag.py 
# Step 1: দরকারি libraries import করো
from airflow import DAG
from airflow.utils.dates import days_ago
from airflow.operators.python import PythonOperator
import datetime

# Step 2: DAG define করো
# "with" ব্যবহার করলে প্রতিটা task-এ আলাদা dag=my_dag লিখতে হয় না
with DAG(
    dag_id='my_very_first_dag',        # DAG-এর unique নাম
    description='আমার প্রথম DAG',        # বর্ণনা (optional)
    tags=['tutorial', 'datascientest'],  # tag দিয়ে filter করা যায়
    schedule_interval=None,              # None মানে manually চালাতে হবে
    default_args={
        'owner': 'airflow',              # কে এই DAG-এর মালিক
        'start_date': days_ago(2),       # কবে থেকে শুরু হবে
    }
) as my_dag:

    # Step 3: Function define করো — এটাই আসল কাজ
    def print_date_and_hello():
        print(datetime.datetime.now())   # এখনকার সময় print করো
        print('Hello from Airflow!')       # একটা message print করো

    # Step 4: Task তৈরি করো — PythonOperator দিয়ে
    my_task = PythonOperator(
        task_id='my_very_first_task',       # Task-এর unique নাম
        python_callable=print_date_and_hello, # কোন function চালাবে
    )

  • dag_id — এটা পুরো Airflow-এ unique হতে হবে। দুটো DAG একই নাম রাখলে error হবে।
  • schedule_interval=None — মানে এই DAG নিজে নিজে চলবে না, manually trigger করতে হবে।
  • start_date — এটা দিতেই হবে। days_ago(2) মানে দুইদিন আগের date।
  • python_callable — function-এর নাম দাও, brackets () ছাড়া।
📌 days_ago(2) কী?

days_ago(2) মানে "আজ থেকে ২ দিন আগের date"। যদি আজ ১০ জানুয়ারি হয়, তাহলে days_ago(2) = ৮ জানুয়ারি। Airflow-এ start_date অবশ্যই অতীতের হতে হয়, তাহলেই DAG run করা যায়। ভবিষ্যতের date দিলে DAG trigger করা যাবে না।

📌 **kwargs কী? (silly মনে হলেও গুরুত্বপূর্ণ!)

**kwargs মানে "keyword arguments" — Python-এ যেকোনো সংখ্যক named arguments নেওয়ার shorthand। যেমন def fn(**kwargs) মানে function-টা যেকোনো নামের argument নিতে পারবে।

Airflow-এ PythonOperator যখন function call করে, সে নিজে থেকে কিছু extra information পাঠায় — যেমন execution date, DAG run id ইত্যাদি। **kwargs দিয়ে এগুলো catch করা যায়। যদি না চাও তাহলে না লিখলেও চলে।

দুটো Task — Dependencies তৈরি

এখন দুটো Task আছে, কিন্তু এরা independent। আমরা বলতে চাই: Task 1 শেষ হলে Task 2 চলবে।

এর জন্য >> operator ব্যবহার করো:

python — dependencies উদাহরণ 
with DAG(...) as my_dag:

    def say_hello():
        print('Hello!')

    def say_bye():
        print('Goodbye!')

    task1 = PythonOperator(task_id='hello_task', python_callable=say_hello)
    task2 = PythonOperator(task_id='bye_task', python_callable=say_bye)

# >> মানে "task1 শেষ হলে task2 চলবে"
task1 >> task2

# একাধিক dependency:
# task1 >> [task2, task4]  → task1 শেষে task2 আর task4 parallel-এ
# task2 >> task3
# task4 >> task5
# [task3, task5] >> task6  → task3 আর task5 শেষে task6

    }

Recurring DAGs — নিয়মিত চালানো

schedule_interval parameter দিয়ে DAG কখন চলবে তা বলো। এটা CRON format ব্যবহার করে।

📌 CRON Format কী?
CRON হলো Linux-এ scheduled tasks চালানোর পদ্ধতি। একটা string দিয়ে বলো "কখন চালাবে"।
CRON Expression Format
Expressionমানে
* * * * *প্রতি মিনিটে
0 * * * *প্রতি ঘণ্টার শুরুতে (XX:00)
0 9 * * *প্রতিদিন সকাল ৯টায়
0 9 * * 1প্রতি সোমবার সকাল ৯টায়
@dailyপ্রতিদিন midnight-এ (shortcut)
@weeklyপ্রতি সোমবার midnight-এ
@hourlyপ্রতি ঘণ্টায়

Trigger Rules — কখন task চলবে?

Default হলো: upstream সব tasks success হলে তবে task চলবে। কিন্তু এটা বদলানো যায়।

Trigger Ruleকখন task চলবে
all_success✅ Default। সব parent task success হলে। (সবচেয়ে সাধারণ)
all_doneসব parent task শেষ হলে (success বা fail — যেকোনো)
one_successযেকোনো একটা parent task success হলেই চলবে
one_failedযেকোনো একটা parent task fail হলেই চলবে
none_failedকোনো parent fail হয়নি (success বা skip হয়েছে)
python — trigger_rule উদাহরণ 
# task1 সবসময় success, task2 সবসময় fail
# task3 = "দুটো শেষ হলেই চলো, success/fail যাই হোক"
task3 = PythonOperator(
    task_id='task3',
    python_callable=successful_task,
    trigger_rule='all_done'    # এটা না থাকলে task3 চলতই না!
)
[task1, task2] >> task3

Retries — ব্যর্থ হলে আবার চেষ্টা

কিছু কাজ গুরুত্বপূর্ণ — একবার fail করলেই ছেড়ে দেওয়া যাবে না। retries আর retry_delay দিয়ে Airflow-কে বলো কতবার চেষ্টা করবে।

python — retry উদাহরণ 
import datetime

def always_fails():
    raise Exception('এই task সবসময় fail করে!')

task1 = PythonOperator(
    task_id='my_failed_task',
    python_callable=always_fails,
    retries=5,                              # ৫ বার retry করবে
    retry_delay=datetime.timedelta(seconds=30)  # প্রতি retry-এর আগে ৩০ সেকেন্ড অপেক্ষা
)
📌 timedelta কী? (silly মনে হলেও জানা দরকার!)

timedelta হলো Python-এর "সময়ের পার্থক্য" বোঝানোর object। যেমন "৩০ সেকেন্ড" বা "৫ মিনিট" বা "২ ঘণ্টা" — এগুলো timedelta দিয়ে লেখা হয়।

datetime.timedelta(seconds=30) = ৩০ সেকেন্ডের একটা duration object।

Airflow-এ retry_delay=timedelta(seconds=30) মানে "retry করার আগে ৩০ সেকেন্ড অপেক্ষা করো।" শুধু 30 লিখলে কাজ করবে না — Airflow-এর timedelta object দরকার।

📌 f-string কী? (Python 3.6+)

Code-এ f"Data saved to {filepath}" এরকম দেখবে — এটাকে f-string বলে। f দিয়ে শুরু হলে string-এর ভেতরে {} দিয়ে variable-এর value সরাসরি বসানো যায়।

যেমন: city = "Paris" হলে f"Hello {city}" = "Hello Paris"। পুরানো পদ্ধতিতে "Hello " + city লিখতে হতো।

Fail হলে email পাঠানোর option আছে:

python — email notification 
task1 = PythonOperator(
    task_id='my_failed_task',
    python_callable=always_fails,
    retries=5,
    retry_delay=datetime.timedelta(seconds=30),
    email_on_retry=True,          # retry হলে email পাঠাও
    email_on_failure=True,        # fail হলেও email পাঠাও
    email=['tumi@example.com']    # কোথায় পাঠাবে
)

Production-এ কিছু কাজ সবসময় করতে হয়: শুরুতে resources তৈরি (Spark session, database connection) এবং শেষে সেগুলো বন্ধ করা। এজন্য as_setup() ও as_teardown() ব্যবহার করো।

python — my_subdag.py (SubDAG সংজ্ঞা) 
from airflow import DAG
from airflow.operators.bash import BashOperator

# একটা function যেটা DAG return করে
def create_sub_dag(dag_id, schedule_interval, start_date):
    sub_dag = DAG(dag_id=dag_id, ...)

    task1 = BashOperator(bash_command="echo subdag task 1", dag=sub_dag, ...)

TaskGroups — আধুনিক পদ্ধতি

from airflow.utils.task_group import TaskGroup
from airflow.operators.dummy import DummyOperator

with DAG(...) as my_dag:

    # Group A-তে ৩টা task
    with TaskGroup("group_A") as group_A:
        task_A1 = DummyOperator(task_id="task_A1")
        task_A2 = DummyOperator(task_id="task_A2")

Branching — শর্ত অনুযায়ী আলাদা path

কখনো কখনো কোনো condition-এর উপর নির্ভর করে আলাদা task চালাতে হয়। যেমন: "যদি sales বেশি হয় → Report A বানাও, নয়তো Report B বানাও।"

এর জন্য BranchPythonOperator ব্যবহার করো। এটা একটা function call করে যেটা পরের task-এর id return করে।

python — Branching উদাহরণ 
from airflow.operators.python import BranchPythonOperator
import random

# এই function decide করে কোন branch-এ যাবে
def decide_branch(condition):
    if condition:
        return 'task_A'   # task_A-র task_id return করো
    else:
        return 'task_B'   # task_B-র task_id return করো

branch_task = BranchPythonOperator(
    task_id='decide',
    python_callable=decide_branch,
    op_args={'condition': bool(random.getrandbits(1))}
)

# যে branch select হবে না, সে "skipped" হয়ে যাবে
start >> branch_task
branch_task >> [task_A, task_B]
[task_A, task_B] >> end

XComs — Task-এর মধ্যে Data পাঠানো

মনে করো Task 1 একটা number calculate করল এবং Task 2-কে সেটা জানাতে হবে। এই কাজের জন্য XCom (Cross-Communication) ব্যবহার করো।

python — XCom Push (পাঠানো) 
# পদ্ধতি ১: simple return (Airflow নিজে XCom store করে)
def calculate_value():
    result = 42
    return result  # এটা automatically XCom-এ 'return_value' নামে save হয়

# পদ্ধতি ২: নিজে নাম দিয়ে push করো
def calculate_value_named(task_instance):
    result = 42.5
    task_instance.xcom_push(
        key="my_result",   # নাম দাও
        value=result        # যা পাঠাবে
    )
python — XCom Pull (পাওয়া) 
def use_the_value(task_instance):
    # আগের task-এর value নিয়ে আসো
    value = task_instance.xcom_pull(
        key="my_result",
        task_ids=['calculate_task']   # কোন task-এর XCom চাই
    )
    print(f"মান পেলাম: {value}")

XCom-এর data Airflow-এর database-এ store হয়। তাই maximum 48KB data পাঠানো যাবে। বড় data পাঠাতে S3 বা অন্য storage ব্যবহার করো।

DAG Decorators — আধুনিক, সুন্দর লেখার পদ্ধতি

Airflow-এর TaskFlow API-এ Python decorators দিয়ে DAG লেখা যায়। এটা পুরনো পদ্ধতির চেয়ে অনেক সংক্ষিপ্ত।

📜 পুরনো পদ্ধতি

  • DAG object manually তৈরি
  • প্রতিটা task-এ dag=my_dag
  • XCom manually push/pull
  • Dependencies >> দিয়ে

✨ Decorator পদ্ধতি

  • @dag দিয়ে DAG define
  • @task দিয়ে task define
  • Return value automatically XCom হয়
  • Function call করেই dependency তৈরি
python — Decorator পদ্ধতি (আধুনিক) 
from airflow.decorators import dag, task
from airflow.utils.dates import days_ago
import random

# @task decorator দিয়ে task define করো
@task
def generate_number():
    value = random.uniform(0, 1)
    return value  # return করলে automatic XCom

@task
def print_number(num):
    print(f"সংখ্যাটা হলো: {num}")

# @dag decorator দিয়ে DAG define করো
@dag(
    dag_id='decorator_dag',
    schedule_interval=None,
    start_date=days_ago(0)
)
def my_pipeline():
    # Function call করেই dependency তৈরি হয়
    num = generate_number()     # task 1
    print_number(num)            # task 2, num-এর উপর depend করে

# DAG instantiate করো
my_dag = my_pipeline()

FileSensor নির্দিষ্ট path-এ file আছে কিনা দেখে।
HttpSensor HTTP endpoint পাওয়া যাচ্ছে কিনা দেখে।
SqlSensor Database-এ কোনো condition পূরণ হয়েছে কিনা দেখে।
python — FileSensor উদাহরণ 
from airflow.sensors.filesystem import FileSensor

my_sensor = FileSensor(
    task_id="check_file",
    fs_conn_id="my_filesystem_connection",  # Connection ID
    filepath="/tmp/my_file.txt",             # কোন file খুঁজবে
    poke_interval=30,                          # ৩০ সেকেন্ড পরপর চেক করবে
    timeout=5 * 30,                           # ১৫০ সেকেন্ড পরেও না পেলে fail
    mode='reschedule'  # file না পেলে task free করে দেয় (efficient)
)

# Sensor successful হলে তারপর এই task
my_sensor >> print_file_task
📌 mode='reschedule' vs mode='poke'
  • poke: task চলমান থাকে, প্রতি poke_interval-এ check করে। Resource খরচ বেশি।
  • reschedule: check করে, না পেলে task free হয়ে যায়, পরে আবার check করে। Efficient।

Best Practices — ভালো Airflow Developer হতে হলে

✅ ছোট Tasks প্রতিটা task একটাই কাজ করুক। বড় task ভেঙে ছোট ছোট করো। ছোট task সহজে retry করা যায়, debug করা যায়।
✅ Static start_date Production-এ days_ago() না, বরং fixed date দাও: datetime(2024, 1, 1)। এটা predictable behavior দেয়।
✅ default_args যে settings সব task-এ একই হবে (owner, retries, email) সেগুলো DAG-এর default_args-এ রাখো।
✅ DAG ফাইলে শুধু DAG code DAG file-এ task/function-এর বাইরে code লিখো না। বাইরের code প্রতিবার Airflow scan করার সময় চলে — এটা inefficient।
✅ Task পুরানোটা রাখো কোনো task delete করো না। ইতিহাস নষ্ট হয়। পুরানো task রেখে দাও, নতুন task যোগ করো।
✅ Sensors দিয়ে verify করো Database-এ insert করার পরে Sensor দিয়ে verify করো যে data আসলেই এসেছে।
✅ Document করো DAG আর Task-এ doc_md দিয়ে documentation লিখো। অন্যরা বুঝতে পারবে।
❌ বড় Data পাঠিও না Tasks-এর মধ্যে বড় data পাঠাতে XCom ব্যবহার করো না। S3, database ইত্যাদি ব্যবহার করো।

Dummy ১: clean_data/data.csv তৈরি করো

এই CSV-তে temperature, city, pression, date কলাম থাকে। নিচের script দিয়ে ৩০ দিনের ৩টা শহরের fake weather data বানাও:

python — create_dummy_data.py (terminal-এ চালাও) 
"""
এই script চালালে clean_data/data.csv তৈরি হবে।
Terminal-এ: python3 create_dummy_data.py
"""
import pandas as pd
import random
import os
from datetime import datetime, timedelta

# ৩টা শহর, ৩০ দিন × ২৪ ঘণ্টা = ৭২০ rows per city
cities = ['Paris', 'London', 'Washington']

# শহরের base temperature (Kelvin-এ — OpenWeatherMap Kelvin ব্যবহার করে)
# কেন Kelvin? কারণ OpenWeatherMap API default-এ Kelvin দেয়।
# 300 Kelvin = 27°C (300 - 273 = 27)
base_temps = {'Paris': 285, 'London': 283, 'Washington': 295}
base_pressure = {'Paris': 1013, 'London': 1010, 'Washington': 1015}

rows = []
start_date = datetime(2024, 1, 1, 0, 0)

for city in cities:
    current_temp = base_temps[city]
    for i in range(720):   # ৩০ দিন × ২৪ ঘণ্টা
        dt = start_date + timedelta(hours=i)
        # temperature একটু একটু করে বদলায় (realistic করতে)
        current_temp += random.uniform(-0.5, 0.5)
        rows.append({
            'temperature': round(current_temp, 2),
            'city': city,
            'pression': base_pressure[city] + random.randint(-5, 5),
            'date': dt.strftime("%Y-%m-%d %H:%M")
        })

df = pd.DataFrame(rows)

# folder তৈরি করো যদি না থাকে
os.makedirs('clean_data', exist_ok=True)
df.to_csv('clean_data/data.csv', index=False)

print(f"✅ তৈরি হয়েছে! {len(df)} rows, columns: {list(df.columns)}")
print(df.head(3))
📌 Script-এর প্রতিটা অপরিচিত জিনিস
  • random.uniform(-0.5, 0.5) — -0.5 থেকে 0.5-এর মধ্যে একটা random decimal number দেয়। Temperature একটু একটু করে বাড়ে/কমে বলে realistic।
  • random.randint(-5, 5) — -5 থেকে 5-এর মধ্যে একটা random integer দেয়।
  • timedelta(hours=i) — i ঘণ্টা পরের datetime বের করে। loop-এ i=0,1,2... হলে প্রতি ঘণ্টার timestamp পাওয়া যায়।
  • os.makedirs('clean_data', exist_ok=True) — folder তৈরি করো; যদি আগেই থাকে error দিও না (exist_ok=True এটা করে)।
  • df.to_csv('path', index=False) — DataFrame-কে CSV file-এ save করো। index=False না দিলে row number (0,1,2...) extra column হিসেবে আসবে।
  • json.dump(data, f, indent=2) — Python object-কে JSON format-এ file-এ লেখো। indent=2 মানে human-readable formatting।
  • int(timestamp.timestamp()) — datetime object-কে Unix timestamp-এ convert করো (1970 সাল থেকে seconds count)। OpenWeatherMap এই format ব্যবহার করে।

import requests
import json
import os
from datetime import datetime
from airflow.models import Variable

def fetch_weather_data():
    # Airflow Variable থেকে cities list নাও
    cities = Variable.get("cities", deserialize_json=True)
    # cities = ['paris', 'london', 'washington']

    api_key = Variable.get("openweathermap_api_key")

    all_data = []
    for city in cities:
        # API-তে GET request পাঠাও
        url = f"https://api.openweathermap.org/data/2.5/weather?q={city}&appid={api_key}"
        response = requests.get(url)
        data = response.json()
        all_data.append(data)

    # এখনকার সময় দিয়ে file নাম বানাও: "2024-03-17 10:30.json"
    now = datetime.now()
    filename = now.strftime("%Y-%m-%d %H:%M") + ".json"
    filepath = os.path.join("/app/raw_files", filename)

    # JSON file-এ save করো
    with open(filepath, 'w') as f:
        json.dump(all_data, f)

    print(f"Data saved to {filepath}")

import pandas as pd
import json, os

def transform_data_into_csv(n_files=None, filename='data.csv'):
    parent_folder = '/app/raw_files'

    # files গুলো নতুন থেকে পুরানো order-এ sort করো
    files = sorted(os.listdir(parent_folder), reverse=True)

    # n_files দেওয়া থাকলে শুধু সেটুকু নাও
    if n_files:
        files = files[:n_files]

    dfs = []
    for f in files:
        with open(os.path.join(parent_folder, f), 'r') as file:
            data_temp = json.load(file)
        for data_city in data_temp:
            dfs.append({
                'temperature': data_city['main']['temp'],
                'city':        data_city['name'],
                'pression':   data_city['main']['pressure'],
                'date':        f.split('.')[0]   # filename থেকে date নাও
            })

    df = pd.DataFrame(dfs)
    df.to_csv(os.path.join('/app/clean_data', filename), index=False)
    print(f"Saved {len(df)} rows to {filename}")

তিনটা আলাদা function, প্রতিটা একটা model train করে এবং score XCom-এ পাঠায়:

python — Task 4: Model Training 
import pandas as pd
from sklearn.model_selection import cross_val_score
from sklearn.linear_model import LinearRegression
from sklearn.tree import DecisionTreeRegressor
from sklearn.ensemble import RandomForestRegressor

def prepare_data(path='/app/clean_data/fulldata.csv'):
    df = pd.read_csv(path)
    df = df.sort_values(['city', 'date'], ascending=True)
    dfs = []
    for c in df['city'].unique():
        df_temp = df[df['city'] == c].copy()
        df_temp['target'] = df_temp['temperature'].shift(1)
        for i in range(1, 10):
            df_temp[f'temp_m-{i}'] = df_temp['temperature'].shift(-i)
        df_temp = df_temp.dropna()
        dfs.append(df_temp)
    df_final = pd.concat(dfs, ignore_index=False)
    df_final = df_final.drop(['date'], axis=1)
    df_final = pd.get_dummies(df_final)
    X = df_final.drop(['target'], axis=1)
    y = df_final['target']
    return X, y

def compute_score(model, X, y):
    scores = cross_val_score(model, X, y, cv=3, scoring='neg_mean_squared_error')
    return scores.mean()

# Task 4' — Linear Regression
def train_linear_regression(task_instance):
    X, y = prepare_data()
    model = LinearRegression()
    score = compute_score(model, X, y)
    print(f"Linear Regression score: {score}")
    task_instance.xcom_push(key="score_lr", value=score)

# Task 4'' — Decision Tree
def train_decision_tree(task_instance):
    X, y = prepare_data()
    model = DecisionTreeRegressor()
    score = compute_score(model, X, y)
    print(f"Decision Tree score: {score}")
    task_instance.xcom_push(key="score_dt", value=score)

# Task 4''' — Random Forest
def train_random_forest(task_instance):

    score = compute_score(model, X, y)

from joblib import dump

def select_best_model(task_instance):
    # XCom থেকে সব scores নিয়ে আসো
    # xcom_pull একটা list return করে (একাধিক task থেকে নিতে পারে)
    # তাই [0] দিয়ে প্রথম (একমাত্র) element নাও
    score_lr = task_instance.xcom_pull(key="score_lr", task_ids=['train_lr'])[0]
    score_dt = task_instance.xcom_pull(key="score_dt", task_ids=['train_dt'])[0]
    score_rf = task_instance.xcom_pull(key="score_rf", task_ids=['train_rf'])[0]

    # neg_mean_squared_error কেন? এটা একটু confusing! 😅
    # MSE (Mean Squared Error) = error-এর মাপ। কম হলে ভালো।
    # sklearn cross_val_score সবসময় "বড় = ভালো" করে রাখে।
    # তাই MSE-কে negative করে: -5 > -10, মানে error 5 < error 10 → ভালো।
    scores = {
        'LinearRegression': (LinearRegression(), score_lr),
        'DecisionTree':     (DecisionTreeRegressor(), score_dt),
        'RandomForest':     (RandomForestRegressor(), score_rf),
    }

    # সবচেয়ে বড় score = সবচেয়ে কম error = সেরা model
    best_name = max(scores, key=lambda k: scores[k][1])
    best_model, best_score = scores[best_name]
    print(f"Best model: {best_name} with score {best_score}")

    # সেরা model পুরো data দিয়ে train করো এবং save করো
    X, y = prepare_data()
    best_model.fit(X, y)
    dump(best_model, '/app/clean_data/best_model.pickle')
    print(f"Model saved!")

    tags=['weather', 'ml'],
    schedule_interval='*/1 * * * *',   # প্রতি মিনিটে
    default_args={
        'owner': 'airflow',
        'start_date': datetime(2024, 1, 1),  # static date
    },

    start = DummyOperator(task_id='start')

    fetch = PythonOperator(task_id='fetch_weather', python_callable=fetch_weather_data)

    transform_full >> [train_lr, train_dt, train_rf]
