ডেটাবেস — মূল তত্ত্ব

১.১ ডেটাবেস কী?

কল্পনা করুন আপনার কাছে একটি বিশাল নোটবুক আছে। সেখানে বন্ধুদের নাম, ফোন নম্বর, ঠিকানা লেখা। বন্ধু বাড়লে খোঁজা কঠিন হয়ে যায়।

ডেটাবেস (Database) হলো এই নোটবুকের কম্পিউটার সংস্করণ — তবে অনেক শক্তিশালী। এটি তথ্যের একটি সংগঠিত সংগ্রহ যা সাধারণত কম্পিউটারে ইলেকট্রনিকভাবে সংরক্ষণ করা হয়।

📚 সরল ভাষায়: ডেটাবেস = কম্পিউটারে রাখা একটি অত্যন্ত স্মার্ট খাতা, যেখানে তথ্য সাজানো থাকে সারি ও কলামে — যাতে সহজে খোঁজা, পরিবর্তন ও সংরক্ষণ করা যায়।

চিত্র ১: কাগজের খাতা থেকে ডেটাবেসে রূপান্তর

📋
Flat Files
.txt বা .csv ফাইল। ছোট ডেটার জন্য ঠিক আছে।
📊
Spreadsheets
Excel বা Google Sheets। মাঝারি ডেটার জন্য।
🗄️
Relational DB
PostgreSQL, MySQL। বড় ও জটিল ডেটার জন্য সেরা।

১.২ DBMS কী? (Database Management System)

ডেটাবেস নিজে শুধু তথ্য ধরে রাখে। কিন্তু সেই তথ্য দেখতে, যোগ করতে, পরিবর্তন বা মুছতে একটা সফটওয়্যার দরকার — এটাই DBMS।

চিত্র ২: DBMS কীভাবে কাজ করে

📝
গুরুত্বপূর্ণ পার্থক্য:
• Database = শুধু তথ্য (data)
• DBMS = তথ্য পরিচালনার সফটওয়্যার
• Database System = DBMS + Database একসাথে

SQL (Structured Query Language) হলো DBMS-এর সাথে কথা বলার ভাষা।

৫.১ SQL কী ও ACID Properties

SQL (Structured Query Language) হলো ডেটাবেসের সাথে কথা বলার ভাষা। ১৯৭০-এর দশকে তৈরি, শুধুমাত্র ডেটা পরিচালনার জন্য।

SQL দিয়ে কী করা যায়?

  • 📥 Store: নতুন ডেটা যোগ (INSERT)
  • 🔄 Update: ডেটা পরিবর্তন (UPDATE)
  • 🗑️ Delete: ডেটা মুছে ফেলা (DELETE)
  • 🔍 Retrieve: ডেটা বের করা (SELECT)

ACID Properties

  • 🅐 Atomicity: সব হবে বা কিছুই না
  • 🅒 Coherence: সব constraint মানতে হবে
  • 🅘 Isolation: লেনদেন একে অপরকে প্রভাবিত করবে না
  • 🅓 Durability: commit হলে সিস্টেম crash-এও টিকবে

৫.২ CREATE TABLE — টেবিল তৈরি

SQL Syntax
CREATE TABLE table_name (

    ...
);
🐘 Clients টেবিল তৈরি
DROP TABLE IF EXISTS Clients;  -- আগে থেকে থাকলে মুছুন

CREATE TABLE Clients (
    ClientId         serial         PRIMARY KEY,    -- স্বয়ংক্রিয় ID
    ClientLastName   varchar(45)  NOT NULL,       -- অবশ্যই দিতে হবে
    ClientFirstName  varchar(45)  NOT NULL,
    ClientAddress    varchar(45)  NOT NULL,
    ClientPostalCode varchar(10)  NOT NULL,      -- VARCHAR! Integer নয়!
    ClientCity       varchar(60)  NOT NULL,      -- 60 অক্ষর (দীর্ঘ নামের জন্য)
    ClientCountry    varchar(45)  NOT NULL,
    ClientPhone      varchar(45)  DEFAULT NULL, -- ঐচ্ছিক
    ClientEmail      varchar(45)  DEFAULT NULL  -- ঐচ্ছিক
);
🐘 Dogs টেবিল তৈরি
DROP TABLE IF EXISTS Dogs;

CREATE TABLE Dogs (

    BreedId         int            DEFAULT NULL,  -- Breeds টেবিলের FK

Data Types সংক্ষেপে: INTEGER (পূর্ণ সংখ্যা) | VARCHAR(n) (টেক্সট, সর্বোচ্চ n অক্ষর) | DATE (তারিখ YYYY-MM-DD) | BOOLEAN (true/false) | DECIMAL (দশমিক সংখ্যা)

৬.৩ LIKE — Pattern Matching

LIKE দিয়ে অক্ষরের ধরন অনুযায়ী খোঁজা যায়।

% — যেকোনো দৈর্ঘ্যের string

'B%' → B দিয়ে শুরু (Buddy, Bibi, Boxer...)

'%y' → y তে শেষ

'%dy%' → মাঝে "dy" আছে

_ — ঠিক একটি অক্ষর

'_____' → ঠিক ৫ অক্ষরের নাম (Buddy, Molly...)

'B_bi' → Bibi, Babi, Bubi

'a_c' → abc, arc, aac

LIKE উদাহরণ
-- M দিয়ে শুরু কুকুর
SELECT * FROM Dogs WHERE DogName LIKE 'M%';
-- Mentalo, Maggie, Molly

-- ঠিক ৫ অক্ষরের নাম
SELECT * FROM Dogs WHERE DogName LIKE '_____';
-- Buddy, Molly, Rocky, Shrek

-- ৬ অক্ষরের কম নাম
SELECT * FROM Dogs WHERE DogName NOT LIKE '______%';

-- m দিয়ে শুরু gender (mâlle সহ!)
SELECT DogName, DogGender FROM Dogs
WHERE DogBreed='Poodle' AND DogGender LIKE 'm%';
💡
ILIKE: LIKE-এর মতো কিন্তু case-insensitive। ILIKE 'b%' খুঁজবে Buddy, buddy, BUDDY — সবই। PostgreSQL-নির্দিষ্ট।

৬.৪ ORDER BY ও LIMIT — সাজানো ও সীমিত করা

ORDER BY ও LIMIT উদাহরণ
-- নাম অনুসারে A-Z সাজানো
SELECT ClientLastName, ClientFirstName FROM Clients
ORDER BY ClientLastName ASC;   -- ASC = ascending (ছোট থেকে বড়), default

-- দাম অনুসারে বড় থেকে ছোট
SELECT DogName, SalePrice FROM Dogs
ORDER BY SalePrice DESC;        -- DESC = descending (বড় থেকে ছোট)

-- শুধু প্রথম ১০ সারি
SELECT DogId, DogName FROM Dogs LIMIT 10;

-- ৬ নম্বরের পর থেকে ৫টি সারি (pagination)
SELECT DogId, DogName FROM Dogs OFFSET 6 LIMIT 5;

-- DISTINCT + ORDER BY একসাথে
SELECT DISTINCT ClientLastName, ClientFirstName FROM Clients
ORDER BY ClientLastName;
-- José Hernandez শুধু একবার দেখাবে (দুজন না!)

LIMIT কেন? Amazon-এ লক্ষ লক্ষ পণ্য আছে। সব একবারে দেখালে সার্ভার ধীর হবে। প্রথম ১০০টি দেখান, "পরের পাতা"-য় OFFSET বাড়ান।

মনে করুন Nathalie চায় কুকুরের নাম এবং মালিকের নাম একসাথে দেখতে। সে হয়তো এভাবে query করবে:

⚠️
সমস্যা! এই query-তে ২৫২টি লাইন আসবে! কারণ এটা Cartesian Product তৈরি করে — প্রতিটি কুকুরকে প্রতিটি client-এর সাথে গুণ করে। এটা আমরা চাই না।

চিত্র: Cartesian Product বনাম INNER JOIN

৭.২ INNER JOIN — শুধু মিলে যাওয়া রেকর্ড

চিত্র: চার ধরনের JOIN এর Venn Diagram তুলনা

INNER JOIN — কুকুর ও মালিক খুঁজুন
SELECT Dogs.DogName, Clients.ClientFirstName, Clients.ClientLastName
FROM Dogs
INNER JOIN Clients ON Dogs.ClientId = Clients.ClientId;
-- ফলাফল: ১৬ rows (শুধু বিক্রি হওয়া কুকুর)
তিনটি টেবিল — কুকুর + মালিক + Breed
SELECT Dogs.DogName, Breeds.BreedName,
       Clients.ClientFirstName, Clients.ClientLastName
FROM Dogs
INNER JOIN Clients ON Dogs.ClientID = Clients.ClientID
INNER JOIN Breeds ON Dogs.BreedID = Breeds.BreedID;
-- Wouf | Dalmatian | Anne | Moreau — এরকম ১৬টি!
LEFT JOIN — অবিক্রীত কুকুরও দেখাবে
SELECT Dogs.DogName, Clients.ClientFirstName, Clients.ClientLastName
FROM Dogs
LEFT JOIN Clients ON Dogs.ClientId = Clients.ClientId;
-- ফলাফল: ২১ rows (৫টি বিক্রি না হওয়া কুকুরের মালিক = NULL)
CONCAT + Table Alias — সুন্দর দেখানো
SELECT
  CONCAT(cl.ClientFirstName, ' ', cl.ClientLastName) AS Client,
  ch.DogName AS Dog,
  r.BreedName AS Breed
FROM Clients cl
LEFT OUTER JOIN Dogs ch ON ch.ClientId = cl.ClientId
LEFT OUTER JOIN Breeds r ON ch.BreedId = r.BreedId;
-- "Anne Moreau" | "Wouf" | "Dalmatian"

৭.৩ Aggregation Functions — সংযুক্তি ফাংশন

ফাংশনSQLকী করেউদাহরণ
গণনাCOUNT()কতটি row আছেকুকুর কতটি?
সর্বোচ্চMAX()সবচেয়ে বড় মানসবচেয়ে দামি কুকুর
সর্বনিম্নMIN()সবচেয়ে ছোট মানসবচেয়ে সস্তা কুকুর
গড়AVG()গড় মানগড় বিক্রয়মূল্য
যোগফলSUM()সব যোগ করেমোট আয়
Aggregation উদাহরণ
SELECT COUNT(*) FROM Dogs;                            -- 21
SELECT COUNT(DogTattooNumber) FROM Dogs;               -- 9 (NULL বাদ)
SELECT SUM(SalePrice) FROM Dogs
  WHERE date_part('year', SaleDate)=2023;              -- 4230 ইউরো
SELECT AVG(SalePrice) FROM Dogs
  WHERE DogGender=True AND date_part('year',SaleDate)=2023; -- 652.8
SELECT MAX(SalePrice), MIN(SalePrice) FROM Dogs;        -- 1000 | 197

৭.৪ GROUP BY — দল করে হিসাব

চিত্র: GROUP BY দিয়ে লিঙ্গ অনুযায়ী গণনা

GROUP BY + HAVING উদাহরণ
-- লিঙ্গ অনুযায়ী কুকুর গণনা
SELECT DogGender AS Gender, COUNT(*) AS "কুকুরের সংখ্যা"
FROM Dogs
GROUP BY DogGender;
-- f: 8  |  t: 13

-- ১ এর বেশি কুকুর কেনা client (HAVING ব্যবহার)
SELECT ClientId, COUNT(*) AS "কেনা কুকুর"
FROM Dogs
WHERE ClientId IS NOT NULL
GROUP BY ClientId
HAVING COUNT(*) > 1
ORDER BY COUNT(*) DESC;
-- ClientId 5 (Céline Johnson): 3 কুকুর!

-- সেরা বছর র‍্যাংকিং
SELECT date_part('year', SaleDate) AS "বছর",
       ROUND(AVG(SalePrice)) AS "গড় মূল্য"
FROM Dogs
WHERE SaleDate IS NOT NULL
GROUP BY date_part('year', SaleDate)
HAVING AVG(SalePrice) >= 200
ORDER BY AVG(SalePrice) DESC;
-- 2023: 705 | 2022: 612 | 2020: 275
📌
WHERE বনাম HAVING:
WHERE = GROUP করার আগে ফিল্টার (input ফিল্টার)
HAVING = GROUP করার পরে ফিল্টার (aggregated ফলাফল ফিল্টার)

CASE সম্পূর্ণ উদাহরণ
SELECT
  Clients.ClientLastName,
  SUM(Dogs.SalePrice) AS TotalExpense,
  CASE
    WHEN SUM(Dogs.SalePrice) >= 1500 THEN 'Excellent'
    WHEN SUM(Dogs.SalePrice) >= 1000 THEN 'Good'
    ELSE 'Average'
  END AS Satisfaction
FROM Clients

-- ৫০০+ দামে কুকুর কেনা সব client
SELECT * FROM Clients c
WHERE EXISTS (
  SELECT 1 FROM Dogs ch
  WHERE ch.ClientId = c.ClientId
  AND ch.SalePrice > 500
);

CREATE TABLE DogsAudit (

RETURNS TRIGGER AS $$
BEGIN
  INSERT INTO DogsAudit VALUES (OLD.DogId, OLD.DogName, OLD.SalePrice, NOW());
  RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER before_update_dog

#কী করতে হবেমূল SQL concept
1Type অনুযায়ী Pokémon গণনা (বেশি থেকে কম)JOIN, GROUP BY, COUNT, ORDER BY DESC
2Base points > 600 Pokémon তালিকাWHERE, ORDER BY DESC
3Type অনুযায়ী গড় points (কম থেকে বেশি)JOIN, GROUP BY, AVG, ORDER BY ASC
4'Overgrow' ability সহ PokémonJOIN তিনটি Table, WHERE
5প্রতিটি Pokémon-এর প্রধান ও গৌণ typeLEFT JOIN, self-join
6Generation গড়ের চেয়ে বেশি stats-এর PokémonSubquery, GROUP BY
7Fire type + attack > 100JOIN, WHERE দুটো শর্ত
8Generation গড়ের তুলনায় "উপরে/নিচে"CASE + Subquery (সবচেয়ে জটিল!)
Query 1 — উদাহরণ সমাধান
SELECT t.name_type AS type, COUNT(*) AS count
FROM PokemonType pt
JOIN Types t ON pt.type_id = t.type_id
GROUP BY t.name_type
ORDER BY count DESC;
-- Water: 131 | Normal: 109 | Flying: 98 | Grass: 98...
Query 8 — সবচেয়ে জটিল (CASE + Subquery)
SELECT
  p.name_pokemon AS pokemon_name,
  p.generation AS pokemon_generation,
  p.base_total AS total_stats,
  CASE
    WHEN p.base_total >
      (SELECT AVG(p2.base_total)
       FROM Pokemon p2
       WHERE p2.generation = p.generation)
    THEN 'Supérieur à la moyenne'
    ELSE 'Inférieur ou égal à la moyenne'
  END AS total_stats_comparison
FROM Pokemon p;
-- Charizard: Gen 1 | 634 | Supérieur à la moyenne

SQL Cheat Sheet — দ্রুত রেফারেন্স

  


  

    

      
DDL — টেবিল তৈরি ও পরিবর্তন

      
-- ডেটাবেস তৈরি
CREATE DATABASE mydb;

-- টেবিল তৈরি
CREATE TABLE mytable (
  id    serial       PRIMARY KEY,
  name  varchar(50) NOT NULL,
  age   int          DEFAULT NULL
);

-- কলাম যোগ
ALTER TABLE mytable ADD price decimal;

-- টেবিল মুছুন
DROP TABLE IF EXISTS mytable;

    

    

      
DML — ডেটা পরিচালনা

      
-- যোগ করুন
INSERT INTO t (col1, col2)
VALUES (val1, val2);

-- আপডেট (WHERE অবশ্যই!)
UPDATE t
SET col1=val1, col2=val2
WHERE id=1;

-- মুছুন (WHERE অবশ্যই!)
DELETE FROM t
WHERE id=1;

    

    

      
DQL — ডেটা পড়া

      
-- সব দেখুন
SELECT * FROM t;

-- ফিল্টার করুন
SELECT col1, col2 FROM t
WHERE condition
ORDER BY col DESC
LIMIT 10;

-- অনন্য মান
SELECT DISTINCT col FROM t;

-- গণনা
SELECT COUNT(*) FROM t;
SELECT SUM(price) FROM t;
