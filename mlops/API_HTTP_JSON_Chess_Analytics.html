API আসলে কী?

API বোঝা ছাড়া আধুনিক data engineering বা software development সম্ভব নয়। একদম শুরু থেকে বুঝি।

API-র পূর্ণ রূপ ও সংজ্ঞা

API = Application Programming Interface

বাংলায়: দুটো program-এর মধ্যে কথা বলার নিয়মকানুনের চুক্তি।

চুক্তিতে তিনটা বিষয়:
① কোথায় পাঠাবে — endpoint URL (ঠিকানা)
② কীভাবে পাঠাবে — HTTP method, headers, parameters
③ কী পাবে ফিরে — response format (সাধারণত JSON), status codes

🍽️ রেস্তোরাঁর উপমা

তুমি (Customer) = তোমার app — যে request করছে
মেনু কার্ড = API documentation — কী order করা যাবে তার নিয়ম
ওয়েটার = API — তোমার order নিয়ে রান্নাঘরে দেয়
রান্নাঘর = Server — আসল কাজ এখানে হয়
খাবার = Response — তুমি যা চেয়েছিলে

তুমি রান্নাঘরে সরাসরি যাচ্ছো না — শুধু মেনু দেখে ওয়েটারকে বলছো। এটাই API।

API Request → Response চক্র
বাস্তব উদাহরণ: তুমি Weather app খোলো → app টা OpenWeather API-তে request পাঠায় → API তোমার এলাকার আবহাওয়া data নিয়ে আসে → তুমি screen-এ দেখো। Server-এর ভেতরে কী হয় জানো না — শুধু API-র নিয়ম মেনে request করেছ।

API-র চার ধরন

সব API এক রকম নয়। কে ব্যবহার করতে পারবে তার উপর ভিত্তি করে চার ধরনের API আছে।

🌍
Public API — সবার জন্য

যে কেউ ব্যবহার করতে পারে। সাধারণত API key লাগে (নিবন্ধন করলে পাওয়া যায়)। কখনো billing হয়।

উদাহরণ: Chess.com API, OpenWeather, Wikipedia API, GitHub API।

Data Science project-এর জন্য সোনার খনি — বিনামূল্যে real data।

🔒
Private API — শুধু ভেতরে

Company-র নিজস্ব ব্যবহারের জন্য। বাইরের কেউ access পায় না।

উদাহরণ: Bank-এর payment system ও account system-এর মধ্যে যোগাযোগ।

ML Engineer হিসেবে তুমি company-র internal data এই API দিয়েই পাবে।

🤝
Partner API — চুক্তিবদ্ধ

নির্বাচিত business partner-দের জন্য। Agreement করতে হয়।

উদাহরণ: Starbucks ও Esri-র location data partnership।

Public-এর মতো সবাই পায় না, Private-এর মতো সম্পূর্ণ বন্ধও নয়।

🔗
Composite API — একসাথে অনেক

একটা API call-এ পেছনে অনেক API call হয়।

উদাহরণ: Travel booking-এ একটা search করলে airline + hotel + weather API সব একসাথে call হয়।

তুমি complexity দেখো না — শুধু এক response পাও।

তৃতীয় অধ্যায়

HTTP Methods — চিঠির ধরন

HTTP = HyperText Transfer Protocol। এটা সেই ভাষা যেটায় browser/app এবং server কথা বলে। প্রতিটা request একটা "method" দিয়ে শুরু হয় — যেটা বলে তুমি কী করতে চাও।

চার HTTP Method — কোনটা কী করে
Endpoint কী?

Endpoint হলো API-র একটা নির্দিষ্ট ঠিকানা (URL) যেটা একটা নির্দিষ্ট কাজ করে।

GET https://api.chess.com/pub/titled/GM → সব GM-এর নাম
GET https://api.chess.com/pub/player/hikaru → hikaru-র profile
GET https://api.chess.com/pub/player/hikaru/stats → hikaru-র statistics

তিনটা আলাদা endpoint — তিনটা আলাদা কাজ।

চতুর্থ অধ্যায়

Status Code — Server-এর জবাব

API call করার পর server একটা 3-digit number পাঠায়। এই নম্বরগুলো মনে রাখলে সমস্যা diagnose করা সহজ।

200 OK
✅ সফল
201 Created
✅ তৈরি হয়েছে
204 No Content
✅ ঠিক আছে
400 Bad Request
⚠ তোমার ভুল
401 Unauthorized
⚠ Login করো
403 Forbidden
⚠ অনুমতি নেই
404 Not Found
⚠ পাওয়া যায়নি
429 Too Many
⚠ Rate limit!
500 Server Error
🔴 Server-এর ভুল
503 Unavailable
🔴 Server বন্ধ
✅ 2xx — সফল

200 OK = সবচেয়ে বেশি দেখবে। সব ঠিক আছে।
201 = POST করার পর নতুন record তৈরি হয়েছে।
204 = DELETE করার পর — মুছে গেছে, body নেই।

⚠️ 4xx — তোমার ভুল

400 = request-এ ভুল format বা missing field।
401 = API key দাওনি বা ভুল।
403 = এই data দেখার permission নেই।
404 = যা চাইলে সেটা exist করে না।
429 = বেশি দ্রুত request — throttled।

🔴 5xx — Server-এর সমস্যা

তোমার কোনো ভুল নেই — server নিজেই সমস্যায় পড়েছে। কিছুক্ষণ পরে retry করো। 503 মানে server সাময়িক বন্ধ।

💡 সোনার নিয়ম

সবসময় status code check করো!

response.raise_for_status()

এই একটা line — 4xx/5xx হলে automatically error throw হবে এবং তুমি জানতে পারবে।

পঞ্চম অধ্যায়

JSON — ডেটার সার্বজনীন ভাষা

JSON = JavaScript Object Notation। API response প্রায় সবসময় JSON format-এ আসে। এটা পড়তে পারলে যেকোনো API-র ডেটা নিয়ে কাজ করতে পারবে।

📦 লেবেলযুক্ত বাক্সের উপমা

JSON হলো labelled বাক্স। বাক্সের ভেতরে আরো ছোট বাক্স, তালিকা থাকতে পারে।
"username": "hikaru" মানে: "username" নামের drawer-এ "hikaru" রাখা আছে।

Python — JSON access ও navigation
import json

# ফাইল থেকে JSON পড়া
with open('player.json', 'r') as f:
    data = json.load(f)

# সরাসরি key দিয়ে access
print(data["username"])          # hikaru
print(data["followers"])         # 1450000

# Nested: ভেতরের object-এ যাওয়া
print(data["stats"]["blitz_rating"])  # 3200

# Array: index দিয়ে
print(data["achievements"][0])   # US Champion
print(data["achievements"][-1])  # শেষেরটা

# সব achievement loop করো
for ach in data["achievements"]:
    print(ach)

# ✅ SAFE: .get() — key না থাকলে error হয় না
age = data.get("age", "অজানা")  # "age" নেই → "অজানা" ফেরত
print(age)   # অজানা (KeyError হবে না!)

# ❌ UNSAFE: key না থাকলে KeyError crash করে
age = data["age"]  # ভুল — KeyError!
সবচেয়ে সাধারণ ভুল: data["key"] লেখা — key না থাকলে crash। সবসময় data.get("key", default) ব্যবহার করো। API schema যেকোনো সময় বদলাতে পারে।

import requests

# Chess.com User-Agent header চায় —礼儀 হিসেবে দাও
headers = {'User-Agent': 'MyApp/1.0'}

try:
    response = requests.get(
        'https://api.chess.com/pub/titled/GM',
        headers=headers,
        timeout=10        # ১০ সেকেন্ড পরেও জবাব না এলে বন্ধ করো
    )
    response.raise_for_status()   # 4xx/5xx হলে exception throw করবে
    data = response.json()
    print(f"মোট GM: {len(data['players'])}")

except requests.exceptions.Timeout:
    print("সময় শেষ — server জবাব দিচ্ছে না")

except requests.exceptions.HTTPError as e:
    print(f"HTTP সমস্যা: {e}")

except Exception as e:
    print(f"অন্য সমস্যা: {e}")
Step 3 — পেশাদার: safe_get() retry + backoff সহ
import time, requests

def safe_get(url, headers=None, retries=3, timeout=10, backoff=2):
    """
    Retry সহ safe GET।
    retries=3  → ৩ বার চেষ্টা করবে
    backoff=2  → প্রতি failure-এ 2^attempt সেকেন্ড অপেক্ষা
                 attempt=1 → 2s, attempt=2 → 4s, attempt=3 → raise
    """
    for attempt in range(1, retries + 1):
        try:
            r = requests.get(url, headers=headers, timeout=timeout)
            r.raise_for_status()
            return r              # সফল হলে return
        except requests.exceptions.RequestException:
            if attempt == retries:
                raise             # শেষ চেষ্টাও ব্যর্থ — error তুলে দাও
            wait = backoff ** attempt
            print(f"চেষ্টা {attempt} ব্যর্থ। {wait}s অপেক্ষা...")
            time.sleep(wait)

# ব্যবহার:
r = safe_get('https://api.chess.com/pub/titled/GM', headers=headers)
gm_list = r.json()['players']
কেন timeout দিতে হয়? timeout না দিলে — যদি server কোনো কারণে সাড়া না দেয় — তোমার program চিরকাল অপেক্ষা করতে থাকবে। timeout=10 মানে ১০ সেকেন্ড পরে automatically বন্ধ হবে।

ETL Pipeline — API থেকে CSV পর্যন্ত

Extract (বের করো) → Transform (রূপান্তর করো) → Load (সংরক্ষণ করো)। Data Engineering-এর মূল কাজ।

ETL Pipeline — ধাপে ধাপে
Complete ETL Pipeline — Members API উদাহরণ
import requests
import pandas as pd

## ═══ EXTRACT ════════════════════════════════════════

def extract_skills():
    """API থেকে members ও skills data বের করি"""
    
    # ধাপ ১: সব member ID-এর তালিকা নাও
    r = requests.get(
        'https://dst-moduleapi.s3.eu-west-1.amazonaws.com/members',
        timeout=10
    )
    r.raise_for_status()
    member_ids = r.json()['members']    # যেমন: [1, 2, 3, 4, 5]

    # ধাপ ২: প্রতিটা member-এর বিস্তারিত তথ্য নাও
    members_data = []
    for mid in member_ids:
        m = requests.get(
            f'https://dst-moduleapi.s3.eu-west-1.amazonaws.com/members/{mid}',
            timeout=10
        )
        m.raise_for_status()
        members_data.append(m.json())

    df_members = pd.DataFrame(members_data)

    # ধাপ ৩: skills reference data
    s = requests.get(
        'https://dst-moduleapi.s3.eu-west-1.amazonaws.com/skills',
        timeout=10
    )
    df_skills = pd.DataFrame(s.json()['skills'])
    return df_members, df_skills


## ═══ TRANSFORM ══════════════════════════════════════

def transform_skills(df_members, df_skills):
    """
    Skills list explode করি, skill নাম যোগ করি,
    তারপর প্রতিটা skill-এর KPI বের করি।
    """
    
    # explode: একটা list → আলাদা rows
    # আগে: Yohan, skills=[1,2,3]
    # পরে: Yohan,1  /  Yohan,2  /  Yohan,3
    df = df_members.explode('MemberSkillsID')

    # merge: skill ID → skill নাম (SQL LEFT JOIN-এর মতো)
    df = df.merge(
        df_skills,
        how='left',
        left_on='MemberSkillsID',
        right_on='SkillID'
    )

    # groupby: প্রতিটা skill-এর statistics
    stats = df.groupby('SkillName').agg(
        SkillMastery=('MemberName', 'nunique'),  # কতজন এই skill জানে
        AverageAge=('MemberAge', 'mean')         # গড় বয়স
    ).reset_index()

    stats['AverageAge'] = stats['AverageAge'].round(0).astype(int)
    return stats


## ═══ LOAD ═══════════════════════════════════════════

def load_skills(stats, path='skills_kpis.csv'):
    """DataFrame কে CSV-তে সংরক্ষণ করো"""
    stats.to_csv(path, index=False)
    print(f"✅ সংরক্ষিত: {path}")

## ═══ PIPELINE চালাও ════════════════════════════════

try:
    df_m, df_s = extract_skills()          # E
    stats       = transform_skills(df_m, df_s)  # T
    load_skills(stats)                         # L
    print(stats.head())
except Exception as e:
    print(f"Pipeline ব্যর্থ: {e}")
explode() কেন দরকার? একজন member-এর কাছে ৫টা skill থাকলে সেটা list হিসেবে আসে। কিন্তু groupby করতে প্রতিটা skill আলাদা row-এ থাকা দরকার। explode() সেটাই করে।

Multi-API Integration — একাধিক API একসাথে

বাস্তব data engineering-এ একাধিক API থেকে ডেটা নিয়ে join করতে হয়। এটাকে Star Schema বলে — একটা central fact table, চারপাশে dimension tables।

Star Schema — Fact Table + Dimension Tables
Multi-API merge — Transactions + Clients + Products
import requests
import pandas as pd

# Endpoints
TX24    = 'https://dst-moduleapi.s3.eu-west-1.amazonaws.com/transactions24'
CLIENT  = 'https://dst-moduleapi.s3.eu-west-1.amazonaws.com/Client/{}'
PRODUCT = 'https://dst-moduleapi.s3.eu-west-1.amazonaws.com/Product/{}'

# ১. Transaction data (Fact Table)
transactions = pd.DataFrame(
    requests.get(TX24, timeout=10).json()
)

# ২. Client details — unique ID গুলো দিয়ে loop করো
client_rows = [
    requests.get(CLIENT.format(int(cid)), timeout=10).json()
    for cid in transactions['ClientID'].dropna().unique()
]
df_clients = pd.DataFrame(client_rows)

# ৩. Product details
product_rows = [
    requests.get(PRODUCT.format(int(pid)), timeout=10).json()
    for pid in transactions['ProductID'].dropna().unique()
]
df_products = pd.DataFrame(product_rows)

# ৪. সব একসাথে merge (LEFT JOIN)
df_full = (
    transactions
    .merge(df_clients,  on='ClientID',  how='left')
    .merge(df_products, on='ProductID', how='left')
)

# ৫. KPI বের করো
df_full['AmountSpent'] = (
    df_full['Quantity'].astype(float) *
    df_full['Price'].astype(float)
)

# প্রতিটা client-এর মোট খরচ
client_spend = (
    df_full.groupby('ClientID')['AmountSpent'].sum()
    .sort_values(ascending=False)
)
print(client_spend.head(5))

country_map = {}
for url in df_gms['country'].dropna().unique():

        name = requests.get(

        ).json()['name']

    except:
        country_map[url] = "Unknown"

# URL → নাম replace করো

প্রতিটা player-এর stats endpoint আলাদা। key validate করো — কিছু player হয়তো Blitz খেলেননি।

def get_stats(username):
    """একজন player-এর chess stats আনো"""
    url = f'https://api.chess.com/pub/player/{username}/stats'
    return requests.get(url, headers=headers, timeout=10).json()

player_kpis = []

for username in df_gms['username'][:50]:
    kpi   = {'username': username}
    stats = get_stats(username)

    # Blitz stats — key আছে কিনা check করো
    if 'chess_blitz' in stats:
        b     = stats['chess_blitz']
        total = b['record']['win'] + b['record']['loss'] + b['record']['draw']
        if total > 0:
            kpi['BlitzWinRate']  = b['record']['win']  / total
            kpi['BlitzLossRate'] = b['record']['loss'] / total
            kpi['BlitzDrawRate'] = b['record']['draw'] / total
            kpi['BlitzRating']   = b['last']['rating']

    # Rapid stats
    if 'chess_rapid' in stats:
        r     = stats['chess_rapid']
        total = r['record']['win'] + r['record']['loss'] + r['record']['draw']
        if total > 0:
            kpi['RapidWinRate'] = r['record']['win'] / total
            kpi['RapidRating']  = r['last']['rating']

    player_kpis.append(kpi)

df_stats = pd.DataFrame(player_kpis)
print(df_stats.head())

# Profile + Stats join করো
df_full = df_gms.merge(df_stats, on='username', how='left')

## ═══ বিশ্লেষণ ═══════════════════════════════════

# কোন দেশে সবচেয়ে বেশি GM?
print("শীর্ষ ৫ দেশ (GM সংখ্যায়):")

# সবচেয়ে বেশি follower কার?
print("\nসবচেয়ে জনপ্রিয় খেলোয়াড়:")
print(df_full[['name', 'followers']]
      .sort_values('followers', ascending=False)
      .head(5))

# শীর্ষ Blitz rating-এর player
print("\nশীর্ষ ৫ Blitz player:")
print(df_full[['name', 'BlitzRating']]
      .sort_values('BlitzRating', ascending=False)
      .head(5))

## ═══ Pearson Correlation ══════════════════════
# Blitz Win Rate এবং Blitz Rating কি সম্পর্কিত?
# Formula: Cov(X,Y) / (std(X) * std(Y))

X = df_full['BlitzWinRate']
Y = df_full['BlitzRating']

# NaN বাদ দাও (কেউ হয়তো Blitz খেলেনি)
mask = X.notna() & Y.notna()
X, Y = X[mask], Y[mask]

# Correlation calculate করো
cov  = (X * Y).mean() - X.mean() * Y.mean()
corr = cov / (X.std() * Y.std())
print(f"\nBlitz Win Rate ও Rating-এর correlation: {corr.round(3)}")
Correlation ব্যাখ্যা:
+1 কাছে → জেতার সাথে rating বাড়ে (প্রত্যাশিত)
0 কাছে → কোনো সম্পর্ক নেই (inactive বা provisional rating)
-1 কাছে → অস্বাভাবিক — outlier বা data সমস্যা তদন্ত করো

সাধারণ ভুল ও Best Practices

এই ভুলগুলো না করলে তুমি অনেক সময়, frustration এবং crash এড়াতে পারবে। প্রতিটা একটা বাস্তব সমস্যার সমাধান।

⏱️
ভুল ১ — Timeout না দেওয়া
Server সাড়া না দিলে program চিরকাল অপেক্ষা করতে থাকে। কোনো error-ও আসে না।
সমাধান: সবসময় requests.get(url, timeout=10) দাও।
❓
ভুল ২ — Status code চেক না করা
Request fail হলেও তুমি জানো না — ভুল বা empty ডেটা দিয়ে কাজ চলতে থাকে।
সমাধান: response.raise_for_status() — 4xx/5xx হলে exception throw হবে।
🔑
ভুল ৩ — data["key"] ব্যবহার করা
Key না থাকলে KeyError crash করে। API schema যেকোনো সময় বদলাতে পারে।
সমাধান: data.get("key", default) — key না থাকলে default ফেরত আসে।
📊
ভুল ৪ — explode না করে aggregate করা
একজনের ৫টা skill — list হিসেবে থাকলে groupby ঠিকভাবে কাজ করে না। Double-counting হয়।
সমাধান: df.explode('column') আগে করো, তারপর groupby।
🧮
ভুল ৫ — Exploded row-এ average করা
explode করার পর একজনের বয়স ৫ বার গণনা হয়। mean() করলে ভুল আসে।
সমাধান: average করার আগে df[['name','age']].drop_duplicates() করো।
🚦
ভুল ৬ — Rate limit উপেক্ষা করা
2500 GM-এর জন্য একটানা loop করলে Chess.com 429 (Too Many Requests) দেবে।
সমাধান: time.sleep(0.5) প্রতিটা request-এর পরে। আগে [:50] দিয়ে test করো।
🔐
ভুল ৭ — API key code-এ hardcode করা
GitHub-এ upload করলে সবাই দেখতে পাবে। তোমার account compromise হতে পারে।
সমাধান: os.getenv('MY_API_KEY') — environment variable ব্যবহার করো।
🔄
ভুল ৮ — Schema drift ধরতে না পারা
API আজ একটা field দিচ্ছে, কাল হয়তো দেবে না। তুমি জানো না।
সমাধান: সবসময় .get() দিয়ে access করো। DataFrame-এর shape ও dtypes validate করো।

📊 সম্পূর্ণ সারসংক্ষেপ — এক নজরে

বিষয় কী কীভাবে ব্যবহার করবে মনে রাখো
API দুই program-এর চুক্তি endpoint URL + HTTP method দিয়ে request রেস্তোরাঁর ওয়েটারের মতো
HTTP GET ডেটা পড়া requests.get(url, timeout=10) Data Science-এ ৯৫% এটাই
Status Code Server-এর জবাব raise_for_status() 200=ঠিক, 4xx=তোমার ভুল, 5xx=server
JSON ডেটার format response.json() → dict .get() ব্যবহার করো, [] নয়
explode() list → আলাদা row df.explode('col') groupby-র আগে করো
merge() দুটো DataFrame join df.merge(df2, on='key', how='left') SQL LEFT JOIN-এর মতো
ETL Extract→Transform→Load প্রতিটার জন্য আলাদা function Clean code = maintainable pipeline
Rate Limit API-র সর্বোচ্চ সীমা time.sleep(0.5) প্রতি call-এ 429 এলে মানে বেশি দ্রুত
safe_get() Retry + backoff নিজে function বানাও বা library ব্যবহার করো Production-এ অবশ্যই দরকার
শেষ কথা — সাফল্যের রহস্য

API integration ভয়ের কিছু নয়। শুরুটা সবসময় একই:

① API documentation পড়ো — endpoint কী, format কী
② ছোট test করো — একটা user-এর data আনো
③ সফল হলে loop করো পুরো dataset-এ
④ Error handle করো — timeout, rate limit, missing keys
⑤ Clean function বানাও — extract, transform, load আলাদা

Practice is key. যত বেশি API দিয়ে কাজ করবে, তত সহজ লাগবে।
