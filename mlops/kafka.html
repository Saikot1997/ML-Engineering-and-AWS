Kafka কী? সহজ ভাষায়

Apache Kafka হলো একটি টুল যেটা দিয়ে এক সিস্টেম থেকে আরেক সিস্টেমে রিয়েলটাইমে ডেটা পাঠানো যায়। এটা মূলত LinkedIn তৈরি করেছিল, তারপর ২০১১ সালে Open Source হিসেবে ছেড়ে দেয়।

🎯 সহজ উপমা

কল্পনা করো একটা ডাকঘর (Post Office) — অনেক মানুষ চিঠি দেয়, আর অনেক মানুষ সেই চিঠি পায়। Kafka হলো সেই ডাকঘর, শুধু পার্থক্য হলো এখানে চিঠি কোটি কোটি, আর সব কিছু হয় একটা সেকেন্ডের মধ্যে।

অনেকেই Kafka-কে বিভিন্নভাবে সংজ্ঞায়িত করে:

📨

Message Broker

এক জায়গা থেকে বার্তা নিয়ে অন্য জায়গায় দেওয়া

🔄

ETL Tool

Extract → Transform → Load — ডেটা এক সিস্টেম থেকে অন্যটায় নেওয়া

🗄️

Database

কিছু ক্ষেত্রে ডেটা স্টোরেজ হিসেবেও ব্যবহার হয়

🌊

Streaming Platform

সঠিক সংজ্ঞা — একটা Distributed Streaming Platform

✅ সরকারি সংজ্ঞা

Kafka হলো একটি Distributed Event Streaming Platform — মানে, অনেক সার্ভারে ছড়িয়ে থাকা, রিয়েলটাইমে ইভেন্ট (ঘটনা/বার্তা) প্রসেস করার একটি প্ল্যাটফর্ম।

Kafka কেন এত জনপ্রিয়?

Kafka-র জনপ্রিয়তার ৪টি মূল কারণ আছে:

১
Publish-Subscribe পদ্ধতি

এক সিস্টেম বার্তা "ছাড়ে", অন্য সিস্টেম সেটা "ধরে" — সরাসরি যোগাযোগ না করে

২
Distributed Architecture (স্কেলেবিলিটি)

অনেক সার্ভার মিলে কাজ করে, তাই কোটি কোটি বার্তাও সামলাতে পারে

৩
Connector System (Kafka Connect)

MongoDB, MySQL, ElasticSearch ইত্যাদির সাথে সহজে সংযোগ করা যায়

৪
Stream Processing (Kafka Streams)

ডেটা আসার সাথে সাথে সেটা প্রসেস করা, ফিল্টার করা, ট্রান্সফর্ম করা যায়

অধ্যায় ০২

সমস্যাটা আসলে কী?

Kafka কেন তৈরি হয়েছিল সেটা বুঝতে হলে আগে সমস্যাটা বুঝতে হবে।

বাস্তব জীবনের উদাহরণ

ধরো তোমার কোম্পানিতে ৩টা সিস্টেম আছে:

  • 🛒 Orders Management — অর্ডার ম্যানেজমেন্ট সিস্টেম
  • 📦 Stock Management — স্টক ম্যানেজমেন্ট সিস্টেম
  • 📧 Email Notification — ইমেইল নোটিফিকেশন সিস্টেম

যখন কেউ অর্ডার দেয়, তখন:

চিত্র ১: Orders সিস্টেম থেকে অন্য সিস্টেমে ডেটা পাঠাতে হবে — কীভাবে?

প্রথম সমাধান: সরাসরি API Call

সবচেয়ে সহজ উপায় হলো Orders সিস্টেম সরাসরি Stock সিস্টেমের API call করবে।

🤔 API Call মানে কী? (silly মনে হলেও জানা দরকার!)
ধরো তুমি রেস্তোরাঁয় বসে ওয়েটারকে ডেকে অর্ডার দিলে — সেটা API call-এর মতো। তুমি সরাসরি রান্নাঘরে গেলে না, ওয়েটারের মাধ্যমে বার্তা গেল। এখানে Orders সিস্টেম = "তুমি", Stock সিস্টেম = "রান্নাঘর", HTTP Request = "ওয়েটার"। যদি রান্নাঘর বন্ধ থাকে (down), ওয়েটার ফিরে আসবে ব্যর্থ হয়ে!

❌ সমস্যা কী?

  • Stock সিস্টেম যদি down থাকে?
  • API call fail করবে
  • স্টক update হবে না
  • Stock-out হয়ে যাবে!
  • নতুন সিস্টেম যোগ হলে জটিলতা বাড়বে

✅ দরকার কী?

  • Stock down থাকলেও বার্তা রাখতে পারা
  • পরে Stock উঠলে বার্তা পাওয়া
  • একই বার্তা Email সিস্টেমও পাওয়া
  • সহজে নতুন সিস্টেম যোগ করা
  • সিস্টেমগুলো একে অপরের উপর নির্ভরশীল না হওয়া
অধ্যায় ০৩

Message Queue — প্রথম সমাধান

এই সমস্যার প্রথম সমাধান হলো Message Queue — একটা সারি (queue) যেখানে বার্তা জমা থাকে।

📬 Message Queue কী?

Message Queue হলো একটা Asynchronous (অ-সমকালীন) পদ্ধতি যেখানে পাঠানো বার্তা একটা "লাইনে" জমা হয়। টার্গেট সিস্টেম যখন প্রস্তুত থাকবে, তখন সেই বার্তাগুলো প্রসেস করবে।

🤔 Asynchronous মানে কী?
Synchronous (সমকালীন): তুমি দোকানে ফোন করলে — দোকানদার ধরল, কথা হলো, শেষ। দুজন একই সময়ে কথা বলল।
Asynchronous (অ-সমকালীন): তুমি WhatsApp message পাঠালে — দোকানদার এখন ব্যস্ত, পরে দেখবে। তোমাকে অপেক্ষা করতে হলো না। Message Queue এভাবে কাজ করে!
🤔 FIFO মানে কী?
First In, First Out — মুদির দোকানে লাইন ধরার মতো। যে আগে এসেছে সে আগে সার্ভিস পাবে। বার্তা #১ আগে Queue-তে গেলে, #১ আগে প্রসেস হবে, তারপর #২, তারপর #৩। উল্টোটা হলো LIFO (Last In First Out) — যেমন stack of plates।

চিত্র ২: Message Queue — বার্তা লাইনে জমা হয়, পরে প্রসেস হয়

Message Queue-র সুবিধা

Stock সিস্টেম যদি কিছুক্ষণ down থাকে, তাহলে বার্তাগুলো Queue-তে জমা হতে থাকবে। সিস্টেম আবার উঠলে, সেই বার্তাগুলো FIFO (First In, First Out) অর্থাৎ যে বার্তা আগে এসেছে সেটা আগে প্রসেস হবে।

কিন্তু Message Queue-রও সমস্যা আছে!

❌ মূল সমস্যা

Queue-তে কোনো বার্তা প্রসেস হয়ে গেলে সেটা মুছে যায়। তাই একই বার্তা যদি Email সিস্টেমও পেতে চায়, তাহলে আলাদা একটা Queue বানাতে হবে!

চিত্র ৩: একাধিক সিস্টেমের জন্য একাধিক Queue — ক্রমশ জটিল হয়ে পড়ে

১০টা সিস্টেম হলে ১০টা Queue লাগবে, ১০০টা হলে ১০০টা — এটা ম্যানেজ করা অসম্ভব হয়ে পড়বে!

অধ্যায় ০৪

Publish-Subscribe — Kafka-র আসল পদ্ধতি

এই সমস্যার সমাধান দিতেই এসেছে Publish-Subscribe (Pub/Sub) মডেল।

📡 Pub/Sub কী?

Pub/Sub-এ পাঠানো সিস্টেম (Publisher/Producer) বার্তা পাঠায় একটা Topic-এ। গ্রহণকারী সিস্টেমগুলো (Subscriber/Consumer) সেই Topic-এ Subscribe করে রাখে। এভাবে একটা Topic থেকে অনেক সিস্টেম একই বার্তা পেতে পারে।

📺 সহজ উপমা: YouTube Channel

ধরো একজন YouTuber ভিডিও আপলোড করল (Publisher)। যারা Channel Subscribe করেছে তারা সবাই নোটিফিকেশন পাবে (Consumers)। YouTuber জানে না কারা subscribe করেছে — সে শুধু ভিডিও দেয়, বাকিরা নিজেরা নেয়। এটাই Pub/Sub!

চিত্র ৪: Pub/Sub মডেল — Topic-এ বার্তা জমা, যে কেউ Subscribe করে নিতে পারে

Pub/Sub-এর মূল সুবিধাগুলো

🔗

Loosely Coupled

Producer জানে না Consumer কে, Consumer জানে না Producer কে — স্বাধীনভাবে কাজ করে

♻️

বার্তা টিকে থাকে

Queue-র মতো প্রসেসের পর মুছে যায় না, একটা নির্দিষ্ট সময় পর্যন্ত থাকে

👥

Multiple Consumers

একই Topic থেকে অনেক Consumer একই বার্তা পেতে পারে

⚡

Scalable

নতুন Consumer যোগ করা বা বাদ দেওয়া যায় কোনো প্রভাব ছাড়া

অধ্যায় ০৫

Kafka-র ভেতরের গঠন — Distributed Architecture

Kafka শুধু Pub/Sub না, এর পেছনে আছে একটা শক্তিশালী Distributed Architecture — মানে অনেক সার্ভার মিলে কাজ করে।

মূল তিনটি উপাদান

📤

Producer (উৎপাদক)

যে সিস্টেম বার্তা পাঠায়। যেমন: অর্ডার সিস্টেম।

🖥️

Broker (দালাল/সার্ভার)

Kafka Cluster-এর প্রতিটা সার্ভার। এরা বার্তা ধরে রাখে এবং পরিচালনা করে।

📥

Consumer (ভোক্তা)

যে সিস্টেম বার্তা পায়। যেমন: স্টক সিস্টেম, ইমেইল সিস্টেম।

চিত্র ৫: Kafka Cluster — ৩টা Broker, Leader ও Follower Partition সহ

Leader ও Follower Partition

প্রতিটা Partition-এর একটা Leader আছে এবং বাকিগুলো Follower। Leader-ই মূলত সব কাজ করে, Follower শুধু নকল (replica) রাখে।

🔐 Fault Tolerance — কী হয় যদি একটা Broker নষ্ট হয়?

যদি কোনো Broker নষ্ট হয়, তার Leader Partition-গুলো স্বয়ংক্রিয়ভাবে অন্য Broker-এর Follower থেকে নতুন Leader হিসেবে নির্বাচিত হয়। এতে কোনো ডেটা হারায় না!

Apache ZooKeeper কী?

ZooKeeper হলো একটা আলাদা টুল যেটা Kafka-কে সাহায্য করে:

  • কোন Partition Leader, কোনটা Follower — সেটা ঠিক করা
  • Broker নষ্ট হলে নতুন Leader নির্বাচন করা
  • Cluster-এর সার্বিক ব্যবস্থাপনা
ℹ️ জানার বিষয়

ভবিষ্যতে Kafka-র নতুন ভার্সনে ZooKeeper সরিয়ে দেওয়া হবে, Kafka নিজেই এই কাজ করবে। এই ফিচারটার নাম KRaft mode।

অধ্যায় ০৬

Topic, Partition, Offset — সব বিস্তারিত

Topic কী?

Topic হলো একটা বার্তার বিভাগ বা ক্যাটাগরি — যেমন একটা YouTube Channel। Producer বার্তা পাঠায় একটা নির্দিষ্ট Topic-এ, Consumer সেই Topic থেকে পড়ে।

🗂️ উদাহরণ

একটা E-commerce সাইটে হতে পারে: orders payments notifications inventory — এগুলো আলাদা Topic।

Partition কী?

প্রতিটা Topic-কে কয়েকটা Partition-এ ভাগ করা হয়। এটা করা হয় দুটো কারণে:

  • Parallelism: একাধিক Consumer একই সময়ে আলাদা Partition থেকে পড়তে পারে
  • Scalability: বিভিন্ন Broker-এ ছড়িয়ে রাখা যায়

চিত্র ৬: একটা Topic-এ ৩টা Partition, প্রতিটায় আলাদা Offset

Offset কী?

Offset হলো প্রতিটা Partition-এ প্রতিটা বার্তার একটা সিরিয়াল নম্বর (index)। যেমন ডায়েরির পৃষ্ঠা নম্বর।

💡 গুরুত্বপূর্ণ

Offset হিসাব হয় প্রতিটা Partition-এ আলাদাভাবে। Partition 0-তে offset 0, 1, 2... এবং Partition 1-এও offset 0, 1, 2... — এগুলো আলাদা।

Key দিয়ে Partition নির্ধারণ

Producer চাইলে প্রতিটা বার্তার সাথে একটা Key দিতে পারে। একই Key-এর সব বার্তা সবসময় একই Partition-এ যাবে।

🎯 কেন Key ব্যবহার করব?

ধরো User ID = "101" এর সব অর্ডার Events একই Partition-এ রাখলে, সেগুলো সিরিয়াল মেনে প্রসেস হবে। "Order Created" → "Order Shipped" → "Order Delivered" — এই ক্রম নিশ্চিত হবে।

Consumer Group কী?

একাধিক Consumer মিলে একটা Consumer Group তৈরি করতে পারে। Group-এর ভেতরে প্রতিটা Partition একটাই Consumer পাবে — এতে কাজ ভাগ হয়ে যায়।

চিত্র ৭: Consumer Group — কাজ ভাগ করে নেওয়া হয় Partition অনুযায়ী

⚖️ Consumer Group-এর নিয়ম

একটা Group-এ Consumer-এর সংখ্যা যদি Partition-এর সংখ্যার বেশি হয়, তাহলে কিছু Consumer বেকার বসে থাকবে। সর্বোচ্চ সমতা হয় যখন Consumer সংখ্যা = Partition সংখ্যা।

Producer — বার্তা পাঠানো

Producer হলো সেই কোড যেটা Kafka-তে বার্তা পাঠায়।

producer.py — সহজ উদাহরণ
from kafka import KafkaProducer

# Kafka Cluster-এর সাথে সংযোগ করো
kafka_producer = KafkaProducer(
    # bootstrap_servers = "Kafka-র দরজায় কড়া নাড়ো"
    # localhost = তোমার নিজের কম্পিউটার (127.0.0.1 একই কথা)
    # 9092 = Port নম্বর (বাড়ির দরজা নম্বরের মতো, Kafka এই দরজায় থাকে)
    # "bootstrap" মানে শুরুতে একটা Broker-এর address দাও,
    # Kafka বাকি সব Broker নিজেই খুঁজে নেবে!
    bootstrap_servers="localhost:9092"
)

# ৩০টা বার্তা পাঠাও
for i in range(1, 30):
    kafka_producer.send(
        topic="test",                              # কোন Topic-এ?
        value=f"New message # {i}".encode("utf-8")  # বার্তা (bytes-এ)
    )

# সব বার্তা পাঠানো নিশ্চিত করো
kafka_producer.flush()
🤔 flush() মানে কী? Kafka Producer বার্তা পাঠানোর সময় সেগুলো প্রথমে একটা buffer (অস্থায়ী মেমোরি) তে জমায় — performance বাড়াতে। flush() মানে: "এখনই buffer খালি করো, সব জমানো বার্তা এখনই পাঠাও!" Script শেষ হওয়ার আগে flush না করলে buffer-এ থাকা বার্তা হারিয়ে যেতে পারে।
💡 কেন .encode("utf-8")?

Kafka-তে বার্তা অবশ্যই bytes ফরম্যাটে দিতে হয়। Python-এর string সরাসরি দেওয়া যায় না। তাই .encode("utf-8") দিয়ে bytes-এ রূপান্তর করতে হয়।

Key সহ বার্তা পাঠানো

producer_with_key.py
from kafka import KafkaProducer

kafka_producer = KafkaProducer(
    bootstrap_servers="localhost:9092"
)

for i in range(1, 30):
    kafka_producer.send(
        topic="test",
        value=f"New message # {i}".encode("utf-8"),
        # জোড় নম্বর → key "0" → Partition 0
        # বেজোড় নম্বর → key "1" → Partition 1
        key=f"{i % 2}".encode("utf-8")
    )

kafka_producer.flush()
🗝️ Key কীভাবে কাজ করে?

i % 2 মানে i-কে 2 দিয়ে ভাগের ভাগশেষ। যদি i=4, তাহলে 4%2=0 → key="0"। যদি i=5, তাহলে 5%2=1 → key="1"। একই key-এর বার্তা সবসময় একই Partition-এ যাবে।

Serializer — স্বয়ংক্রিয় এনকোডিং

🤔 lambda কী? (Python-এর anonymous function — silly কিন্তু জানা দরকার!)
সাধারণত Python-এ ফাংশন এভাবে লেখা হয়:
def encode_value(v): return v.encode("utf-8")
Lambda দিয়ে একই জিনিস এক লাইনে লেখা যায়:
lambda v: v.encode("utf-8")
মানে: "v নামে একটা input নাও, তারপর v.encode("utf-8") return করো।" Lambda হলো ছোট, একবার-ব্যবহারের নামহীন ফাংশনের শর্টকাট — যেখানে পুরো def লেখা অপচয় হয়।

প্রতিটা বার্তায় .encode("utf-8") লেখা ক্লান্তিকর। এর বদলে Producer-এ একবার value_serializer সেট করলেই হয়:

Serializer দিয়ে Producer
from kafka import KafkaProducer

kafka_producer = KafkaProducer(
    bootstrap_servers="localhost:9092",
    client_id="easy_production",          # Producer-এর নাম (log-এ দেখা যাবে)
    value_serializer=lambda v: v.encode("utf-8"),  # স্বয়ংক্রিয় encode
    key_serializer=lambda k: k.encode("utf-8")      # key-ও encode
)

# এখন আর .encode() লাগবে না!
for i in range(1, 6):
    kafka_producer.send(topic="test", value=f"No need encoding # {i}")

acks মানমানে কীঝুঁকিগতি

Consumer-এ Group ID ও Manual Commit

group_id দিলে Consumer Group তৈরি হয়। enable_auto_commit=False দিলে বার্তা সফলভাবে প্রসেস না হওয়া পর্যন্ত নিশ্চিতকরণ দেওয়া হবে না:

Advanced Consumer
from kafka import KafkaConsumer

def decode_str(string):
    if string is None:
        return None
    else:
        return string.decode("utf-8")

kafka_consumer = KafkaConsumer(
    "test",
    bootstrap_servers="localhost:9092",
    group_id="my-consumer-group",  # Consumer Group-এর নাম
    auto_offset_reset="earliest",
    key_deserializer=decode_str,    # স্বয়ংক্রিয় decode
    value_deserializer=decode_str,
    enable_auto_commit=False,      # Manual commit চাই
    consumer_timeout_ms=5000       # ৫ সেকেন্ড অপেক্ষার পর থামবে
)

for message in kafka_consumer:
    print(message.key, message.value)
    kafka_consumer.commit()        # বার্তা প্রসেস হলো, তারপর commit

kafka_consumer.close()

ধরো বার্তা পড়া হলো কিন্তু প্রসেস করার আগেই Consumer crash করল। Auto Commit থাকলে Kafka মনে করবে বার্তা প্রসেস হয়ে গেছে — কিন্তু আসলে হয়নি! Manual Commit দিলে কাজ শেষ হওয়ার পরেই Kafka-কে জানাবে।

নির্দিষ্ট Partition পড়া (TopicPartition)

Specific Partition Consumer
from kafka import KafkaConsumer, TopicPartition

kafka_consumer = KafkaConsumer(
    bootstrap_servers="localhost:9092",
    auto_offset_reset="earliest",
    enable_auto_commit=False,
    consumer_timeout_ms=1000
)

# শুধু "test" Topic-এর Partition 0 পড়বো
test0 = TopicPartition("test", 0)
kafka_consumer.assign([test0])

for message in kafka_consumer:
    print(message.key, message.value)
    kafka_consumer.commit()

kafka_consumer.close()

Dummy data মানে নকল/পরীক্ষামূলক ডেটা। বাস্তব না হলেও Kafka শেখার জন্য যথেষ্ট। Producer থেকে পাঠাবে, Consumer পড়বে — এটুকু practice-এর জন্য real data লাগে না।

Option 1: Smart Downloader (ডাউনলোড fail হলে dummy বানাও)

smart_setup.py — ডাউনলোড না হলে dummy তৈরি
import os, urllib.request, json, random
from datetime import datetime, timedelta

URL = "https://dst-de.s3.eu-west-3.amazonaws.com/kafka_fr/kafka.zip"

def try_download():
    print("⏳ ডাউনলোড চেষ্টা করছি...")
    try:
        # urllib.request.urlretrieve = URL থেকে ফাইল নামাও
        urllib.request.urlretrieve(URL, "kafka.zip")
        print("✅ ডাউনলোড সফল!")
        return True
    except Exception as e:
        print(f"❌ ডাউনলোড fail হয়েছে: {e}")
        return False

def create_dummy_data():
    print("🔧 Dummy ডেটা তৈরি করছি...")
    products  = ["Laptop", "Phone", "Tablet", "Headphones", "Keyboard"]
    customers = ["Rahim", "Karim", "Saikot", "Priya", "Tamal"]
    statuses  = ["order_created", "payment_done", "order_shipped", "delivered"]

    orders = []
    base_time = datetime(2024, 1, 1, 9, 0, 0)
    for i in range(1, 51):  # ৫০টা নকল অর্ডার
        orders.append({
            "order_id"  : f"ORD-{i:04d}",
            "customer"  : random.choice(customers),
            "product"   : random.choice(products),
            "quantity"  : random.randint(1, 5),
            "price_bdt": random.randint(1000, 80000),
            "status"    : random.choice(statuses),
            "timestamp": (base_time + timedelta(minutes=i*5)).isoformat()
        })
    with open("dummy_orders.json", "w", encoding="utf-8") as f:
        json.dump(orders, f, ensure_ascii=False, indent=2)
    print(f"✅ {len(orders)}টা নকল অর্ডার dummy_orders.json-এ সংরক্ষিত!")
    return orders

# মূল যুক্তি: আগে download চেষ্টা, fail হলে dummy বানাও
if not try_download():
    orders = create_dummy_data()

Option 2: সরাসরি Kafka-তে Dummy ডেটা পাঠাও

ফাইল ডাউনলোড বা unzip-এর ঝামেলা না করে সরাসরি Kafka-তে JSON বার্তা পাঠাতে পারো:

dummy_producer.py — JSON ডেটা সরাসরি Kafka-তে
from kafka import KafkaProducer
import json, random, time
from datetime import datetime

# JSON Serializer: Python dict → JSON string → bytes
# json.dumps() = Python object-কে JSON string-এ রূপান্তর করে
# ensure_ascii=False = বাংলা অক্ষর ঠিকমতো থাকে
producer = KafkaProducer(
    bootstrap_servers="localhost:9092",
    value_serializer=lambda v: json.dumps(v, ensure_ascii=False).encode("utf-8"),
    key_serializer=lambda k: k.encode("utf-8")
)

products  = ["Laptop", "Phone", "Tablet", "Mouse", "Keyboard"]
customers = ["user_101", "user_202", "user_303", "user_404"]
statuses  = ["order_created", "payment_done", "order_shipped", "delivered"]

print("🚀 Kafka-তে Dummy ডেটা পাঠানো শুরু...")

for i in range(1, 31):
    customer_id = random.choice(customers)
    event = {
        "event_id"  : i,
        "customer_id": customer_id,
        "product"   : random.choice(products),
        "quantity"  : random.randint(1, 3),
        "price_bdt": random.randint(500, 50000),
        "status"    : random.choice(statuses),
        "timestamp": datetime.now().isoformat()
    }
    # customer_id = Key → একই customer এর সব event একই Partition-এ
    producer.send(topic="test", key=customer_id, value=event)
    print(f"  ✉ [{customer_id}] {event['status']} — {event['product']} (৳{event['price_bdt']})")
    time.sleep(0.1)  # ১০০ms বিরতি

producer.flush()
print("✅ সব ডেটা পাঠানো শেষ!")

Dummy Consumer — JSON বার্তা পড়া

dummy_consumer.py
from kafka import KafkaConsumer
import json

consumer = KafkaConsumer(
    "test",
    bootstrap_servers="localhost:9092",
    auto_offset_reset="earliest",
    # JSON Deserializer: bytes → JSON string → Python dict
    # json.loads() = JSON string-কে Python object-এ রূপান্তর
    value_deserializer=lambda v: json.loads(v.decode("utf-8")),
    key_deserializer=lambda k: k.decode("utf-8") if k else None,
    consumer_timeout_ms=3000  # ৩ সেকেন্ড কিছু না আসলে থামো
)

print("📥 Kafka থেকে ডেটা পড়ছি...")
total = 0

for message in consumer:
    event = message.value  # এখন Python dict — সরাসরি key দিয়ে access করো
    print(
        f"  [{event['customer_id']}] {event['product']} "
        f"→ {event['status']} (৳{event['price_bdt']})"
    )
    total += 1

consumer.close()
print(f"✅ মোট {total}টা বার্তা পড়া হলো।")

কোর্সের শেষে এই প্রশ্নগুলো দিয়ে নিজেকে পরীক্ষা করো। উত্তর বেছে নিলে ব্যাখ্যা দেখতে পাবে।

প্রশ্ন ১: Kafka আসলে কী?
A) একটা Python লাইব্রেরি
B) একটা Distributed Event Streaming Platform
C) একটা Batch ডেটা প্রসেসিং টুল
D) একটা সাধারণ Message Queue
✅ সঠিক উত্তর: B
Kafka হলো একটা Distributed Event Streaming Platform। এটা শুধু Message Queue না — এটা Pub/Sub, Kafka Streams (প্রসেসিং), Kafka Connect (সংযোগ) — সব একসাথে দেয়।
প্রশ্ন ২: Kafka Cluster-এর Broker কী?
A) Cluster-এর একটা Failure
B) Cluster-এর একটা সার্ভার, যেখানে Partition-এর ডেটা থাকে
C) Kafka আর Database-এর মধ্যে সংযোগ
D) একটা Docker Image
✅ সঠিক উত্তর: B
Broker হলো Kafka Cluster-এর একটা সার্ভার। প্রতিটা Broker এক বা একাধিক Partition-এর ডেটা ধরে রাখে এবং অন্য Broker-এর সাথে যোগাযোগ করে।
প্রশ্ন ৩: একটা Broker নষ্ট হলে কী হয়?
A) Broker কখনো নষ্ট হতে পারে না
B) পুরো Cluster বন্ধ হয়ে যায়
C) সেই Broker-এর Leader Partition-গুলো স্বয়ংক্রিয়ভাবে অন্য Broker-এ চলে যায়
D) সব ডেটা হারিয়ে যায়
✅ সঠিক উত্তর: C
Kafka Fault Tolerant! Broker নষ্ট হলে তার Leader Partition-এর Follower অন্য Broker-এ ছিল — সেটাই নতুন Leader হয়। ZooKeeper এই leader election পরিচালনা করে। কোনো ডেটা হারায় না।
প্রশ্ন ৪: একজন User-এর সব বার্তা Production Order-এ পেতে হলে কী করতে হবে?
A) কিছু করতে হবে না, Kafka নিজেই গ্যারান্টি দেয়
B) এটা অসম্ভব, Kafka Order গ্যারান্টি দেয় না
C) User ID-কে Key হিসেবে ব্যবহার করে Partition করতে হবে
D) User-এর ডেটা বাইরের Database-এ রাখতে হবে
✅ সঠিক উত্তর: C
Kafka শুধু একটা Partition-এর ভেতরে Order গ্যারান্টি দেয়। তাই একই User-এর বার্তা একই Partition-এ রাখতে User ID-কে Key করতে হবে। একই Key → একই Partition → ক্রম নিশ্চিত।

A) Apache Kafka-র একটা Component যেটা বাইরের সিস্টেম থেকে ডেটা আনা-নেওয়ার জন্য Connector ব্যবহার করে
B) Kafka-র জন্য একটা VPN
C) Kafka-র একটা Python Client
D) Cloud-এর জন্য Kafka-র একটা ভার্সন

বোনাস: Python-এ acks='all' দিলে কী হয়?
A) বার্তা দ্রুত পাঠানো হয়, কোনো নিশ্চিতকরণ নেই
B) শুধু Leader Broker নিশ্চিত করলেই হয়
C) সব Broker (Leader + সব Follower) নিশ্চিত করলে তবেই পরবর্তী বার্তা পাঠানো হয়
