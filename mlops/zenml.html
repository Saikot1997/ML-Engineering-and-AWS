📘 Module 1 — Introduction to ZenML
১
ZenML কী? কেন দরকার?
ML Pipeline management এর সমস্যা ও ZenML এর সমাধান

🤔 সমস্যাটা কী?

ধরো তুমি একটা ML model তৈরি করলে। প্রথমে Jupyter notebook এ সব code লিখলে। Model ভালো করল। কিন্তু production এ নিয়ে যেতে হবে।

এখন সমস্যা: Data preprocessing কোড কোথায়? Model training কোথায়? এগুলো কি reproducible? কেউ কি এই experiment আবার চালাতে পারবে একই result পেয়ে? নতুন data আসলে কীভাবে automatically retrain হবে?

ZenML এই সব সমস্যার সমাধান করে। এটা একটা open-source ML pipeline orchestration framework যেটা ML lifecycle এর প্রতিটা ধাপকে structured, reproducible এবং automatable করে।

🏯 নামের মানে: ZenML এর logo তে একটা Japanese torii gate আছে। "Zen" মানে শান্তি ও সরলতা। ML কে সরল ও শান্তিপূর্ণ করাই ZenML এর লক্ষ্য।

🎯 ZenML এর মূল features

🔄 Pipeline তৈরি

Modular pipelines তৈরি করো যেখানে প্রতিটা step আলাদাভাবে test ও reuse করা যায়। Code duplication কমে, bug fix সহজ হয়।

🔁 Reproducibility

ML এর বড় challenge হলো same result পাওয়া। ZenML configurations ও dependencies store করে — যেকোনো সময় same result পাওয়া যায়।

📦 Artifact Management

Pipeline এর প্রতিটা output (dataset, model, metric) track করে, version করে। কোন run এ কোন data ব্যবহার হয়েছে সব জানা যায়।

🔗 Tool Integration

৫০+ tools এর সাথে integrate করে — TensorFlow, PyTorch, MLflow, AWS, GCP, Azure। তোমার existing stack বদলাতে হবে না।

⚙️ Orchestration

Training, validation, deployment, monitoring — সব repetitive tasks automatically হয়। Data scientists higher-value কাজে focus করতে পারে।

🤝 Collaboration

Team এ easily share করা যায়। Pipelines standardized হওয়ায় নতুন team member সহজে বুঝতে পারে।

ZenML ML lifecycle management — input থেকে output পর্যন্ত

🆚 ZenML vs MLflow vs Airflow — পার্থক্য কী?

MLflow: Experiment tracking ও model registry ভালো করে। কিন্তু full pipeline orchestration এর জন্য যথেষ্ট না।

Airflow: Task scheduling ও workflow automation ভালো। কিন্তু ML specific — artifact versioning, model registry — এগুলো নেই।

ZenML: ML lifecycle এর জন্য specific। MLflow ও Airflow উভয়ের সাথে integrate করতে পারে। Pipeline + Artifact + Stack — সব একসাথে।

mkdir zenml cd zenml
২

Virtual environment তৈরি ও activate করো

# virtualenv দিয়ে environment তৈরি করো virtualenv env_zenml # Activate করো (Linux/Mac) source env_zenml/bin/activate # Windows এ # env_zenml\Scripts\activate

Virtual environment কেন? এটা একটু silly শোনায় কিন্তু গুরুত্বপূর্ণ!

ধরো তোমার একটা project এ pandas==1.3 দরকার, আরেকটায় pandas==2.0। দুটো same machine এ install করলে conflict হবে। Virtual environment একটা "আলাদা ঘর" — প্রতিটা project তার নিজের dependencies নিজের ঘরে রাখে। অন্য project এর সাথে কোনো সম্পর্ক নেই।

Pipeline তৈরি করা — @pipeline decorator
ZenML এ pipeline define করার সম্পূর্ণ পদ্ধতি

Pipeline কী?

ML workflow এ Pipeline হলো একটা organized sequence of tasks — প্রতিটা task একটা নির্দিষ্ট কাজ করে এবং output পরের task এ যায়। ZenML এ Pipeline define করা সহজ — শুধু @pipeline decorator ব্যবহার করো।

📋 feature_engineering Pipeline — সম্পূর্ণ ব্যাখ্যা

# pipelines/feature_engineering.py from zenml import pipeline from steps import data_loader, data_splitter, data_preprocessor from typing import Optional, List @pipeline # Decorator মানে: Python function এর আগে @ দিয়ে special behavior যোগ করা # @pipeline ZenML কে বলে: "এই function টা একটা pipeline — track করো, cache করো" def feature_engineering( test_size: float = 0.2, # test data কতটুকু? (20%) drop_na: Optional[bool] = None, # NaN values drop করবে? normalize: Optional[bool] = None, # Normalize করবে? drop_columns: Optional[List[str]] = None, target: Optional[str] = "target", # target column কোনটা? random_state: int = 17, ): # Step 1: Data load করো raw_data = data_loader(random_state=random_state, target=target) # Step 2: Train/Test split করো dataset_trn, dataset_tst = data_splitter( dataset=raw_data, # Step 1 এর output এখানে input test_size=test_size, ) # Step 3: Preprocess করো dataset_trn, dataset_tst, _ = data_preprocessor( dataset_trn=dataset_trn, # Step 2 এর output dataset_tst=dataset_tst, drop_na=drop_na, normalize=normalize, drop_columns=drop_columns, target=target, random_state=random_state, ) # Pipeline শেষ — artifacts automatically store হয়!
Feature Engineering Pipeline এর data flow — step এর output পরের step এর input

Steps তৈরি করা — @step decorator
Pipeline এর individual units কীভাবে তৈরি করে?

Step কী?

Step হলো pipeline এর একটা নির্দিষ্ট, autonomous unit। প্রতিটা step input নেয়, কাজ করে, output দেয়। ZenML এ step define করতে @step decorator ব্যবহার করো।

Step গুলো self-contained — individually test করা যায়, multiple pipelines এ reuse করা যায়।

📋 data_preprocessor Step — সম্পূর্ণ ব্যাখ্যা

# steps/data_preprocessor.py import pandas as pd from zenml import step from sklearn.pipeline import Pipeline from typing import Optional, List, Tuple from typing_extensions import Annotated from utils.preprocess import NADropper, ColumnsDropper from sklearn.preprocessing import MinMaxScaler @step # @step decorator মানে: এই function টা pipeline এর একটা unit # ZenML automatically input/output track করবে, cache করবে def data_preprocessor( # Input parameters: random_state: int, dataset_trn: pd.DataFrame, # previous step থেকে আসা data dataset_tst: pd.DataFrame, drop_na: Optional[bool] = None, normalize: Optional[bool] = None, drop_columns: Optional[List[str]] = None, target: Optional[str] = "target", ) -> Tuple[ # Output types declare করো — Python type hints # Tuple[A, B, C] মানে: এই function ৩টা জিনিস return করবে # Annotated[pd.DataFrame, "dataset_trn"] মানে: DataFrame type, নাম "dataset_trn" Annotated[pd.DataFrame, "dataset_trn"], # নামসহ declare Annotated[pd.DataFrame, "dataset_tst"], Annotated[Pipeline, "preprocess_pipeline"], ]: # sklearn Pipeline তৈরি করো (transformations এর chain) preprocess_pipeline = Pipeline([("passthrough", "passthrough")]) # Conditionally steps add করো if drop_na: preprocess_pipeline.steps.append(("drop_na", NADropper())) if drop_columns: preprocess_pipeline.steps.append(("drop_columns", ColumnsDropper(drop_columns))) if normalize: preprocess_pipeline.steps.append(("normalize", MinMaxScaler())) # fit_transform(): শেখো + apply করো (শুধু training data তে করো) # fit() মানে: "এই data দেখে নিয়ম শেখো" — যেমন min/max range কত? # transform() মানে: "সেই নিয়ম apply করো" dataset_trn = preprocess_pipeline.fit_transform(dataset_trn) # Test data তে শুধু transform করো (fit করো না — data leakage হবে!) dataset_tst = preprocess_pipeline.transform(dataset_tst) return dataset_trn, dataset_tst, preprocess_pipeline # ZenML automatically এগুলো artifact হিসেবে store করবে!

⚠️ Data Leakage সতর্কতা: Training data তে fit_transform() করো কিন্তু test data তে শুধু transform() করো। Test data দেখে normalization parameters ঠিক করলে model evaluate করতে পারবে না।

📋 data_loader Step

# steps/data_loader.py import pandas as pd from zenml import step from sklearn.datasets import load_breast_cancer @step def data_loader( random_state: int, target: str = "target", ) -> pd.DataFrame: # Output type declare করো # Breast Cancer dataset load করো (sklearn built-in — internet ছাড়াই পাওয়া যায়!) # random_state=17 মানে: randomness এর seed। একই seed দিলে একই result — reproducible! # (যেকোনো number দিতে পারো, 42 বা 17 popular choice — কোনো magic নেই এতে 😄) data = load_breast_cancer() df = pd.DataFrame(data.data, columns=data.feature_names) df[target] = data.target # target column add করো return df # ZenML এটা artifact হিসেবে store করবে

📋 model_trainer Step

# steps/model_trainer.py from zenml import step, ArtifactConfig from sklearn.base import ClassifierMixin import pandas as pd @step def model_trainer( dataset_trn: pd.DataFrame, model: ClassifierMixin, # SGD বা RandomForest — যেকোনো classifier target: str = "target", ) -> Annotated[ClassifierMixin, "sklearn_classifier"]: X_train = dataset_trn.drop(columns=[target]) y_train = dataset_trn[target] model.fit(X_train, y_train) # Train করো return model # Trained model return করো

🔧 Utils — Reusable Functions

কেন আলাদা utils folder?

Step এর ভেতরে সব logic লিখলে code duplicate হয়। Utils folder এ common functions রাখো — যেকোনো step থেকে import করা যাবে।

🔁 Modularity

Functions centralize করলে কোনো step ই নিজে নিজে rewrite করে না।

🧹 Clean Code

Step focus করে step এর কাজে। Transformation logic utils এ।

🧪 Testing

Utils এর functions আলাদাভাবে unit test করা সহজ।

# utils/preprocess.py import pandas as pd from typing import Union, List class NADropper: """sklearn Pipeline compatible NaN dropper.""" def fit(self, *args, **kwargs): return self # sklearn convention: fit() self return করে def transform(self, X: Union[pd.DataFrame, pd.Series]): return X.dropna() # NaN rows drop করো class ColumnsDropper: """Specified columns drop করে।""" def __init__(self, columns: List[str]): self.columns = columns def fit(self, *args, **kwargs): return self def transform(self, X: pd.DataFrame): return X.drop(columns=self.columns, errors="ignore")

📋 run.py — Entry Point

run.py হলো main entry point। এখান থেকে কোন pipeline চালাবে সেটা command line argument দিয়ে বলা হয়।

# run.py (simplified) import click from pipelines import feature_engineering, training_pipeline @click.command() @click.option("--feature-pipeline", is_flag=True, default=False) @click.option("--training-pipeline", is_flag=True, default=False) @click.option("--inference-pipeline", is_flag=True, default=False) @click.option("--train-dataset-version-name", default=None) @click.option("--test-dataset-version-name", default=None) def main(feature_pipeline, training_pipeline_flag, ...): if feature_pipeline: feature_engineering() # Pipeline call করো if training_pipeline_flag: training_pipeline( train_dataset_version=train_dataset_version_name, )

📊 Dashboard এ Step Status

Step এর ৩ধরনের Status

✓ Completed

Step সফলভাবে শেষ হয়েছে। Output artifact save হয়েছে। পরবর্তী run এ Cached হতে পারে।

⟪ Cached

এই step আগে same input দিয়ে চলেছে। পুনরায় না চালিয়ে cached result ব্যবহার করে। সময় বাঁচায়।

! Failed

Error হয়েছে — code bug, data problem, বা unhandled exception। Logs দেখে fix করতে হবে।

✅ Cache এর সুবিধা: Feature engineering করার পরে training pipeline চালালে preprocessing আবার হয় না — cached result ব্যবহার হয়। অনেক সময় বাঁচে।

Artifacts — ZenML এর Data Management
Artifact কী, কেন গুরুত্বপূর্ণ, কীভাবে ব্যবহার করে?

📦 Artifact কী?

Artifact হলো pipeline এ produce বা consume হওয়া যেকোনো data। প্রতিটা step এ input ও output হয় artifacts।

ZenML automatically artifacts track করে, version করে এবং store করে। তুমি বলতে পারবে — "Training run #5 এ কোন dataset ব্যবহার হয়েছিল?" ZenML বলে দেবে।

📋 Artifact এর ধরন

📊 Dataset

  • Raw data (CSV, Parquet)
  • Preprocessed train/test sets
  • Augmented বা synthetic data

🤖 Model

  • Trained ML models
  • sklearn, PyTorch, TensorFlow
  • Production model versions

📈 Metrics

  • Accuracy, F1, AUC scores
  • Model performance results
  • Comparison between versions

📄 Reports

  • Visualizations (plots, charts)
  • Summaries
  • Training logs

🔄 Specific Artifact Version ব্যবহার করো

কেন version specify করবে?

Feature engineering আবার চালালে নতুন version তৈরি হয়। Training pipeline চালাতে হলে কোন version এর data দিয়ে train করবে সেটা বলতে হয়। Version specify করলে preprocessing step skip হয় — সময় বাঁচে।

# Version 1 এর data দিয়ে train করো python run.py --training-pipeline \ --train-dataset-version-name=1 \ --test-dataset-version-name=1 # Version specify না করলে — preprocessing আবার চলবে python run.py --training-pipeline
Version specify করলে preprocessing steps cached — শুধু training চলে
১১
Artifact Versioning, Tags ও Metadata
Artifacts identify করা সহজ করো

সমস্যাটা কী?

Default এ ZenML artifacts incremental number দিয়ে version করে (1, 2, 3...). কিন্তু version 5 বলতে কী বোঝায়? কোন parameters দিয়ে তৈরি?

ZenML দেয় ৩টা solution: Manual version naming, Tags, আর Metadata।

🏷️ ArtifactConfig — Custom Version, Tags, Metadata

# steps/data_preprocessor.py from zenml import step, ArtifactConfig @step def data_preprocessor( random_state: int, dataset_trn: pd.DataFrame, dataset_tst: pd.DataFrame, drop_na: Optional[bool] = True, normalize: Optional[bool] = True, target: Optional[str] = "target", ) -> Tuple[ # ArtifactConfig দিয়ে custom version, metadata, tags set করো Annotated[ pd.DataFrame, "dataset_trn", ArtifactConfig( version="train-data-v2", # Custom version name run_metadata={"normalize": "True"}, # Metadata: কোন params? tags=["breast_cancer_train", "zenml_course"] # Tags ) ], Annotated[ pd.DataFrame, "dataset_tst", ArtifactConfig( version="test-data-v2", run_metadata={"normalize": "True"}, tags=["breast_cancer_test", "zenml_course"] ) ], Annotated[Pipeline, "preprocess_pipeline"], ]: # ... step code ...
# Pipeline চালাও python run.py --feature-pipeline # Output: # 1. Train Dataset - Name: dataset_trn, Version Name: train-data-v2 # 2. Test Dataset - Name: dataset_tst, Version Name: test-data-v2 # Custom versions দেখো zenml artifact version list --name='startswith:dataset_tst'

⚠️ সতর্কতা: Version name unique হতে হবে! একই name দুইবার দিলে error হবে। পুরনো version থাকলে নতুন name দাও।

কেন Docker Orchestrator?

Default stack এ pipeline local machine এ চলে। কিন্তু production এ বা team এ কাজ করতে হলে reproducible environment দরকার। Docker container এ চালালে সব machine এ same environment পাওয়া যায়।

ZenML এর default stack modify করা যায় না। নতুন stack তৈরি করতে হবে।
