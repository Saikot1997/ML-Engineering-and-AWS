Isolation ও Virtualization — কেন দরকার?

কল্পনা করো একটি কোম্পানির production server আছে। সেখানে একই সময়ে অনেকগুলো অ্যাপ চলে। কিন্তু প্রতিটি অ্যাপের আলাদা environment দরকার। এখানেই Isolation-এর প্রয়োজন।

// যে সমস্যার সমাধান করে Isolation

তিন ধরনের Virtualization তুলনা

💻
Virtual Machine (VM)
পুরো OS নকল করে। অনেক বেশি storage ও RAM লাগে। Hypervisor ব্যবহার করে। চালু হতে মিনিট লাগে।
🐳
Container (Docker) ⭐
Host OS-এর kernel ভাগ করে। হালকা, দ্রুত (সেকেন্ডে চালু)। কম resource লাগে। আমরা এটা শিখব।
🐍
Virtual Environment
শুধু Python-এর জন্য। Library আলাদা করে রাখে। OS level isolation করে না। venv, conda।

VM বনাম Container — মূল পার্থক্য

// স্তর কাঠামোর পার্থক্য

Image = Class, Container = Object

💡
Programming-এর ভাষায় বোঝো
Image হলো একটি blueprint বা ছাঁচ — যেমন OOP-তে Class।
Container হলো সেই ছাঁচ থেকে তৈরি চলমান কপি — যেমন Object/Instance।

একটি Image থেকে অনেকগুলো Container চালানো যায়, ঠিক যেমন একটি Class থেকে অনেক Object তৈরি করা যায়।

Cloud provider-এ এটিকে বলে AMI (AWS), Dockerfile-ই Image তৈরির নির্দেশিকা।

Container চালানো — সব গুরুত্বপূর্ণ Flag

bashdocker container run — সব উপায়
# সাধারণভাবে চালাও
docker container run ubuntu:latest
# কোনো command না দিলে default command চলে, তারপর বন্ধ হয়

# Interactive mode — ভেতরে ঢুকে কাজ করো
docker container run -it ubuntu:latest bash
# -it = --interactive --tty (keyboard input + terminal)
# bash = container-এর ভেতরে bash shell চালাও

# Background (detached) mode
docker container run -d ubuntu:latest bash
# terminal দখল করে না, পেছনে চলে

# নাম দিয়ে চালাও
docker container run -d --name my_ubuntu ubuntu:latest bash

# বন্ধ হলে স্বয়ংক্রিয়ভাবে মুছে ফেলো
docker container run --rm ubuntu:latest echo "hello"

# Environment variable দিয়ে চালাও
docker container run -it --rm -e "MY_VAR=hello" ubuntu:latest bash
# container-এর ভেতরে: echo $MY_VAR → hello

# Port forward করে চালাও (host:container)
docker container run -p 8080:80 nginx
# host-এর 8080 port → container-এর 80 port

# সব একসাথে
docker container run \
    -d \
    --rm \
    --name my_web \
    -p 8080:80 \
    -e "ENV=production" \
    nginx:latest

⚠️
IP address স্থায়ী নয়!
Container বন্ধ হলে তার IP address পরিবর্তন হতে পারে। তাই IP-র বদলে container-এর নাম ব্যবহার করো। একই network-এ থাকলে নাম domain-এর মতো কাজ করে।

তিন ধরনের Network

Networkবৈশিষ্ট্যকখন ব্যবহার
bridgeDefault। Container গুলো নিজস্ব subnet-এ থাকে। Container গুলো পরস্পর কথা বলতে পারে।বেশিরভাগ সময়

Data Persistence — ডেটা স্থায়িত্ব

Docker container বন্ধ হলে তার ভেতরের সব ডেটা মুছে যায়। ডেটা ধরে রাখতে Volume ব্যবহার করতে হয়।

🚨
সতর্কতা! Container মুছলে ডেটা যায়!
Container-এ ফাইল তৈরি করলে → Container বন্ধ ও মুছে ফেললে → নতুন Container-এ সেই ফাইল নেই।
Database-এ data রাখলে → Container মুছলে সব data চলে যাবে।
সমাধান: Volume ব্যবহার করো।
// Volume কীভাবে কাজ করে

Volume তৈরি ও ব্যবহার

bash
# Volume তৈরি করো
docker volume create my_volume

# Volume তালিকা দেখো
docker volume ls

# Volume কোথায় আছে ও বিস্তারিত দেখো
docker volume inspect my_volume
[{
    "Name": "my_volume",
    "Driver": "local",
    "Mountpoint": "/var/lib/docker/volumes/my_volume/_data",
    ...
}]

# Volume সহ container চালাও
# --mount type=volume,src=volume_নাম,dst=container_এর_path
docker container run -it --rm --name my_ubuntu \
    --mount type=volume,src=my_volume,dst=/home/my_folder \
    ubuntu:latest bash

# ভেতরে ফাইল তৈরি করো
root@container:/# echo "hello from Docker" > /home/my_folder/test.txt
root@container:/# exit

# নতুন container-এও ডেটা থাকবে!
docker container run -it --rm \
    --mount type=volume,src=my_volume,dst=/home/data \
    ubuntu:latest bash
root@container:/# cat /home/data/test.txt
hello from Docker   ← ডেটা আছে! ✅

# Volume মুছো (ডেটাও মুছে যাবে!)
docker volume rm my_volume

Host Folder Mount — সহজ পদ্ধতি

bash
# --volume host_path:container_path
# $HOME = /home/ubuntu (তোমার home folder)
docker container run -it --rm --name my_ubuntu \
    --volume $HOME:/home/my_folder \
    ubuntu:latest bash

# container-এর ভেতরে তোমার home folder দেখতে পাবে!
root@container:/# ls /home/my_folder
# তোমার host machine-এর home folder-এর সব ফাইল দেখাবে

# পার্থক্য:
# Volume: Docker পরিচালনা করে, নিরাপদ, root access লাগে host থেকে
# --volume: সরাসরি host folder, সহজ, কম নিরাপদ

Flask Server সহ Image — Step by Step

১
Folder ও ফাইল তৈরি করো
mkdir my_docker_image && cd my_docker_image
২
server.py তৈরি করো
pythonserver.py
from flask import Flask

server = Flask('my_server')

@server.route('/')
def index():
    return 'Hello World from a containerized server'

if __name__ == '__main__':
    server.run(host='0.0.0.0', port=5000)
# host='0.0.0.0' গুরুত্বপূর্ণ — container বাইরে থেকে access-এর জন্য
৩
Dockerfile লেখো
dockerfileDockerfile
# Step 1: কোন base image ব্যবহার করব?
FROM ubuntu:18.04

# Step 2: Python ও Flask ইনস্টল করো
# && দিয়ে chain করা হয়েছে → একটি RUN layer = ছোট image
RUN apt-get update \
    && apt-get install python3-pip -y \
    && pip3 install flask==2.0.0

# Step 3: আমাদের Python ফাইল image-এ কপি করো
# ADD local_file image_এর_path
ADD server.py /my_server/server.py

# Step 4: কাজের directory পরিবর্তন করো (cd এর মতো)
WORKDIR /my_server/

# Step 5: port 5000 বাইরে থেকে accessible ঘোষণা করো
EXPOSE 5000

# Step 6: Container চালু হলে এই command চলবে
CMD python3 server.py

Image ভাগ করার পদ্ধতি

docker login

docker image push myusername/my_flask_app:1.0

# যেকেউ pull করতে পারবে

YAML = "YAML Ain't Markup Language"। একটি সহজ text format যা configuration লিখতে ব্যবহার হয়। Indentation (ফাঁকা জায়গা) দিয়ে কাঠামো বোঝানো হয়। ফাইলের নাম হয় docker-compose.yml।

সহজতম docker-compose.yml

yamldocker-compose.yml — শুধু দুটো service
version: '3.9'

services:
  jupyter:
    image: jupyter/minimal-notebook:ubuntu-18.04

  elasticsearch:
    image: elasticsearch:7.2.0
    environment:
      discovery.type: single-node

পূর্ণ docker-compose.yml — সব features সহ

yamldocker-compose.yml — পূর্ণ উদাহরণ
version: '3.9'

services:
  # ── Service 1: Jupyter Notebook ──
  jupyter:
    image: jupyter/minimal-notebook:ubuntu-18.04
    container_name: my_jupyter     # container-এর নাম
    networks:
      - my_network                   # কোন network-এ থাকবে
    volumes:
      - .:/home/jovyan/work          # বর্তমান folder mount করো
    ports:
      - target: 8888                 # container-এর port
        published: 4444              # host-এর port
        protocol: tcp
        mode: host
    environment:
      JUPYTER_TOKEN: 'hello'        # Jupyter-এর password

  # ── Service 2: ElasticSearch ──
  elasticsearch:
    image: elasticsearch:7.2.0
    container_name: my_es
    networks:
      - my_network
    ports:
      - "9200:9200"                  # সহজ পদ্ধতি
      - "9300:9300"
    environment:
      discovery.type: single-node

# ── Network সংজ্ঞায়িত করো ──
networks:
  my_network:                        # compose নিজেই তৈরি করবে

Compose ব্যবহার করে Service-এর মধ্যে যোগাযোগ

import requests, json, pprint

# container-এর নাম দিয়ে address করো — IP দরকার নেই!

pprint.pprint(content)

Docker Compose কখন ব্যবহার করবে?
• একসাথে database + backend + frontend চালাতে
• CI/CD pipeline-এ automatic testing-এর জন্য
• Local development environment সহজ করতে
• একটি command-এ পুরো system চালু/বন্ধ করতে

⚠️ Docker Compose একটি machine-এ। একাধিক machine-এ চালাতে Docker Swarm বা Kubernetes ব্যবহার করো।

pythonPython দিয়ে Container পরিচালনা
from docker import DockerClient

# Docker daemon-এর সাথে connection তৈরি করো
client = DockerClient()

# Container চালাও
client.containers.run(
    image='ubuntu:latest',
    name='my_ubuntu_py',
    detach=True,
    auto_remove=True,
    ports={'80/tcp': 8080},
    network='bridge'
)

# সব চলমান container-এর নাম দেখাও
for c in client.containers.list():
    print(c.name, c.image)

# Image pull করো
client.images.pull('nginx:latest')

# Container বন্ধ করো
container = client.containers.get('my_ubuntu_py')
container.stop()

তিনটি Test Container তৈরি করতে হবে

pythontest_auth.py — Authentication Test
import os, requests

api_address = 'api'     # compose-এ api container-এর নাম
api_port = 8000

# Test ১: alice — সঠিক password (200 আসা উচিত)
r1 = requests.get(
    url=f'http://{api_address}:{api_port}/permissions',
    params={'username': 'alice', 'password': 'wonderland'}
)
# Test ২: bob — সঠিক password (200 আসা উচিত)
r2 = requests.get(
    url=f'http://{api_address}:{api_port}/permissions',
    params={'username': 'bob', 'password': 'builder'}
)
# Test ৩: ভুল password (403 আসা উচিত)
r3 = requests.get(
    url=f'http://{api_address}:{api_port}/permissions',
    params={'username': 'clementine', 'password': 'mandarine'}
)

output = f"""
============================
 Authentication Test
============================
alice/wonderland → {r1.status_code} ({'✅ SUCCESS' if r1.status_code==200 else '❌ FAILURE'})
bob/builder      → {r2.status_code} ({'✅ SUCCESS' if r2.status_code==200 else '❌ FAILURE'})
wrong/password   → {r3.status_code} ({'✅ SUCCESS' if r3.status_code==403 else '❌ FAILURE'})
"""
print(output)

# LOG=1 হলে ফাইলে লেখো
if os.environ.get('LOG') == '1':
    with open('api_test.log', 'a') as f:
        f.write(output)
