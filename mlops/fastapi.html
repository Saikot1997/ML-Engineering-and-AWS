API কী এবং কেন দরকার?

API মানে Application Programming Interface। সহজ কথায়, API হলো দুটো software-এর মধ্যে কথা বলার নিয়ম-কানুন। একটা application অন্যটাকে বলে "এই data দাও" বা "এই কাজটা করো" — এই যোগাযোগটাই API।

তুমি রেস্তোরাঁয় গেছ। রান্নাঘরে সরাসরি ঢুকতে পারবে না। একজন ওয়েটার আছেন — তুমি তাকে বলো "বিরিয়ানি চাই", সে রান্নাঘরে গিয়ে order দেয় এবং খাবার নিয়ে আসে। API হলো এই ওয়েটারের মতো — তুমি সরাসরি server-এর ভেতরে না গিয়ে API-কে request করো, সে কাজ করে result দেয়।

HTTP Request-এর উপাদান

HTTP (HyperText Transfer Protocol) হলো ইন্টারনেটের ভাষা। এটা দিয়ে browser server-কে "কথা" বলে। HTTPS হলো এর encrypted নিরাপদ version।

HTTP Request ও Response-এর সম্পূর্ণ গঠন
URI কী? Uniform Resource Identifier — ইন্টারনেটে কোনো কিছুর ঠিকানা। যেমন https://api.example.com/users
https কী? Protocol — যোগাযোগের নিয়ম। http = সাধারণ, https = encrypted নিরাপদ।
Headers কী? Request-এর metadata — মূল data না, কিন্তু গুরুত্বপূর্ণ। যেমন কে পাঠাচ্ছে, কী ধরনের data।
Body কী? Request-এর মূল data — POST/PUT-এ পাঠানো হয়। GET-এ body থাকে না।
JSON কী? JavaScript Object Notation — data লেখার format। {"key": "value"} আকারে। Python-এর dict-এর মতোই দেখতে।

URI-এর অংশগুলো

URI বিশ্লেষণ
https://api.example.com/users?age=25&city=dhaka ↑ ↑ ↑ ↑ Protocol Domain Endpoint Query Parameters # ? দিয়ে Query Parameters শুরু, & দিয়ে আলাদা করা ?age=25 # key=value &city=dhaka # আরেকটা parameter

HTTP Methods ও Status Codes

HTTP Methods — কী করতে চাইছ?

Methodঅর্থউদাহরণ
GETData পড়া / খোঁজাসব user-এর list দেখাও
POSTনতুন data যোগনতুন user তৈরি করো
PUTপুরো data replaceuser-এর সব তথ্য বদলাও
PATCHআংশিক updateশুধু user-এর নাম বদলাও
DELETEData মুছে ফেলাuser মুছে দাও
Library-র সাথে তুলনা:
GET = বই পড়া   POST = নতুন বই যোগ   PUT = পুরো বই বদলানো   PATCH = কয়েক পাতা সংশোধন   DELETE = বই সরানো

HTTP Status Codes — কী হলো?

2xx — সফল ✅
3xx — Redirect ↗
4xx — তোমার ভুল ❌
5xx — Server-এর ভুল 💥
Codeনামমানে
200OKসব ঠিকঠাক ✅
201Createdনতুন data তৈরি হয়েছে (POST-এর পর)
400Bad Requestতোমার request-এ ভুল আছে
401UnauthorizedLogin করোনি — কে তুমি জানি না
403ForbiddenLogin করেছ কিন্তু permission নেই
404Not Foundভুল address — এই resource নেই
422Unprocessable EntityData format ভুল (FastAPI-তে common)
500Internal Server ErrorServer-এ bug আছে
401 vs 403 পার্থক্য: 401 = "কে তুমি জানি না" (login করোনি), 403 = "জানি তুমি কে, কিন্তু দেওয়া যাবে না" (permission নেই)।

cURL — Terminal থেকে সরাসরি

cURL উদাহরণ
# GET request curl -X GET https://jsonplaceholder.typicode.com/posts/1 # Headers সহ দেখো (-i = include headers) curl -X GET -i https://jsonplaceholder.typicode.com/posts/1 # POST request — body পাঠাও curl -X POST \ -H "Content-Type: application/json" \ -d '{"title": "test post", "body": "বিষয়বস্তু"}' \ https://jsonplaceholder.typicode.com/posts
-X কী? Method specify করে — GET, POST, PUT ইত্যাদি
-H কী? Header যোগ করো (যেমন Content-Type বলছে body-তে JSON আছে)
-d কী? Data/Body — যা পাঠাতে চাও
\ (backslash) কী? Line continuation — একটা লম্বা command কয়েক লাইনে ভেঙে পড়তে সুবিধা। Terminal মনে করে সব একটাই command।

Python requests library

Python দিয়ে API call
# প্রথমে install করো: pip install requests import requests # GET request r = requests.get('https://jsonplaceholder.typicode.com/posts/1') # Response-এর বিভিন্ন অংশ data = r.json() # ← json() — brackets লাগবে! এটা একটা function call headers = r.headers # Response headers dict status = r.status_code # 200, 404 ইত্যাদি integer print(status) # 200 print(data) # {'userId': 1, 'id': 1, 'title': '...'} # POST request r = requests.post( url='https://jsonplaceholder.typicode.com/posts', json={"title": "test", "body": "লেখা"} # json= দিলে Content-Type auto set হয় ) print(r.status_code) # 201 Created

REST Standard — API-এর নিয়মকানুন

REST (Representational State Transfer) হলো API তৈরির একটা জনপ্রিয় architecture।

Client-Server
Client আর Server আলাদা। একটা বদলালে অন্যটায় কোনো প্রভাব নেই।
Stateless
প্রতিটা request স্বাধীন। Server আগের request মনে রাখে না — প্রতিবার নতুন।
Uniform Interface
Endpoint = object, Method = কাজ। GET /users = সব user পড়া।
Cacheable
Response cache করা যায় — বারবার একই request না পাঠিয়ে saved data ব্যবহার।
REST Endpoint Naming Convention — উদাহরণ

Dynamic Routing — URL-এ variable

/users/5 মানে ID=5 এর user। এই 5 টা variable — এটাই Dynamic Routing।

Dynamic Routing
# {itemid} curly braces-এ যা লিখবে সেটা function parameter হবে @api.get('/item/{itemid}') def get_item(itemid): return {'itemid': itemid} # Type annotation দিয়ে — শুধু integer accept করবে @api.get('/product/{pid}') def get_product(pid: int): # ← : int মানে integer হতে হবে return {'pid': pid, 'type': 'integer'} # curl /product/1234 → {"pid": 1234, "type": "integer"} # curl /product/abc → 422 Error — "abc" integer না! # একাধিক variable @api.get('/item/{itemid}/desc/{lang}') def get_item_lang(itemid: int, lang: str): if lang == 'bn': return {'desc': 'একটি বস্তু'} return {'desc': 'an object'}

users_api.py
from fastapi import FastAPI api = FastAPI(title='User API') users_db = [ {'user_id': 1, 'name': 'Alice', 'subscription': 'free'}, {'user_id': 2, 'name': 'Bob', 'subscription': 'premium'}, {'user_id': 3, 'name': 'রহিম', 'subscription': 'free'}, ] @api.get('/') def index(): return {'message': 'স্বাগতম!'} @api.get('/users') def get_users(): return users_db @api.get('/users/{userid}') def get_user(userid: int): result = [u for u in users_db if u['user_id'] == userid] return result[0] if result else {} # পাওয়া গেলে → প্রথম result, না পেলে → খালি dict {}

Query String — URL-এ filter করা

URL-এর ? চিহ্নের পরে যা থাকে তাই Query String। যেমন: /search?keyword=python&limit=10

Query String
from fastapi import FastAPI from typing import Optional api = FastAPI() # URL path-এ না থাকা parameter → query string হয় automatically @api.get('/') def get_index(argument1: str): # required return {'data': argument1} # curl /?argument1=hello → {"data": "hello"} # curl / → 422 Error — argument1 দিতেই হবে! # Optional[int] = None মানে দেওয়া নাও দেওয়া যায়, default None @api.get('/search') def search(keyword: str, limit: Optional[int] = 10): return {'keyword': keyword, 'limit': limit} # curl /search?keyword=python → limit=10 (default) # curl /search?keyword=python&limit=5 → limit=5
Query string হলো যেন Google-এ search: google.com/search?q=python — এখানে q=python হলো query parameter।

Request Body — Pydantic BaseModel

নতুন user তৈরি করতে অনেক data দরকার — URL-এ দেওয়া সম্ভব না। তাই Request Body ব্যবহার হয়। FastAPI-তে Body-র জন্য Pydantic-এর BaseModel ব্যবহার করতে হয়।

Pydantic কী? Python-এর data validation library। class User(BaseModel) লিখলে FastAPI বুঝতে পারে এটা body — query parameter না।
BaseModel থেকে inherit মানে? User class-টা BaseModel-এর সব feature নিয়ে নিল। এটা OOP-এর ধারণা — parent class-এর সব কিছু child-এ চলে আসে।
Request Body
from fastapi import FastAPI from pydantic import BaseModel from typing import Optional api = FastAPI() class User(BaseModel): name: str # required, string age: int # required, integer email: Optional[str] = None # optional, default None is_active: bool = True # optional, default True @api.post('/users') def create_user(user: User): # ← annotation User → FastAPI জানে এটা body return {'message': f'{user.name} তৈরি হয়েছে', 'user': user}
cURL দিয়ে POST test
# সঠিক request curl -X POST http://127.0.0.1:8000/users \ -H "Content-Type: application/json" \ -d '{"name": "করিম", "age": 25}' {"message":"করিম তৈরি হয়েছে","user":{"name":"করিম","age":25,"email":null,"is_active":true}} # ভুল — age নেই curl -X POST http://127.0.0.1:8000/users -d '{"name": "করিম"}' {"detail":[{"loc":["body","age"],"msg":"field required"}]} # 422 — age field missing!

Headers — Request-এ metadata পাঠানো

Headers হলো request-এর metadata। Authentication token, content type ইত্যাদি এখানে পাঠানো হয়।

Header পড়া
from fastapi import FastAPI, Header from typing import Optional api = FastAPI() @api.get('/headers') def get_headers(user_agent: Optional[str] = Header(None)): # Header(None) মানে এই header optional return {'User-Agent': user_agent} # curl -X GET http://127.0.0.1:8000/headers # → {"User-Agent": "curl/7.68.0"} # Authentication-এর জন্য header: @api.get('/protected') def protected(authorization: Optional[str] = Header(None)): if authorization == "Bearer my_secret_token": return {"message": "স্বাগতম!"} return {"error": "অনুমতি নেই"}

Performance ও Async — দ্রুততা

Sync vs Async — Timeline দিয়ে পার্থক্য (প্রতিটা request ১০ সেকেন্ড নেয়)
async/await উদাহরণ
from fastapi import FastAPI import asyncio, time api = FastAPI() # Synchronous — একটা শেষ না হলে পরেরটা আটকে থাকে @api.get('/sync') def get_sync(): time.sleep(5) # পুরো server ৫ সেকেন্ড আটকে থাকে! return {'type': 'sync'} # Asynchronous — অপেক্ষার সময় অন্য request চলতে পারে @api.get('/async') async def get_async(): # ← async def লিখতে হবে await asyncio.sleep(5) # ← await = "অপেক্ষা করো, কিন্তু block করো না" return {'type': 'async'}
Sync = একজন cashier যে একজনের transaction শেষ না হওয়া পর্যন্ত পরের জনকে দেখে না। সবাই queue-তে।

Async = একজন cashier যে card machine-এ process হওয়ার অপেক্ষায় না থেকে পরের customer-এর order নেওয়া শুরু করে।
async def কী? এই function asynchronous — অপেক্ষার সময় অন্য কাজ করতে পারে।
await কী? "এখানে অপেক্ষা করো, কিন্তু server-কে block করো না।" await শুধু async function-এর ভেতরে ব্যবহার করা যায়।
asyncio.sleep কী? async version-এর sleep। সাধারণ time.sleep পুরো server block করে দেয়, কিন্তু asyncio.sleep শুধু এই function-কে wait করায়।
FastAPI-তে যেখানে database query, file read, network call আছে — সেখানে সবসময় async def ও await ব্যবহার করো।
