ধরো তুমি একটা বিশাল অনলাইন শপে কাজ করছো — লাখো পণ্য আছে। কেউ search box-এ "লাল জামা" লিখলো। মাত্র ০.০১ সেকেন্ডে হাজারো ফলাফল আসলো। এই অসাধারণ দ্রুত খোঁজার কাজটা কীভাবে হয়? উত্তর: Elasticsearch।

MongoDB ভালো সাধারণ data storage-এ। Elasticsearch ভালো text search আর analytics-এ। অনেক system দুটোই একসাথে ব্যবহার করে!

Architecture — Node, Shard, Replication

Elasticsearch একটা distributed system — মানে অনেক machine মিলে কাজ করে। এই concept গুলো ঠিকমতো না বুঝলে production-এ সমস্যা হবে।

Node — একটা ES Instance

Node হলো একটা Elasticsearch-এর instance — মানে একটা চলমান ES প্রোগ্রাম।

মনে রাখো: Node = ES instance, Machine নয়! একটা machine-এ অনেকগুলো Node চালানো যায়।

Sharding — ডেটা ভাগ করা

কল্পনা করো তোমার কাছে ১ TB ডেটা আছে কিন্তু প্রতিটা node-এ মাত্র ৫০০ GB জায়গা। সমস্যা!

Sharding হলো সমাধান — Index-কে ছোট ছোট টুকরায় ভাগ করো, প্রতিটা টুকরা আলাদা node-এ রাখো।

Shard-এর সীমা: একটা Shard-এ সর্বোচ্চ প্রায় ২০০ কোটি Document রাখা যায়। Default-এ একটা Index একটাই Shard-এ থাকে — প্রয়োজনে Index তৈরির সময় বাড়ানো যায়।

Replication — Backup কপি রাখো

Shard তৈরি করলেই কি নিরাপদ? না! কারণ যদি সেই node বন্ধ হয়ে যায় — ডেটা হারিয়ে যাবে। সমাধান: Replication।

গুরুত্বপূর্ণ নিয়ম: Replica Shard কখনো Primary-র same Node-এ থাকে না। তাই একটা Node মরলেও — অন্য Node-এ Replica আছে, ডেটা নিরাপদ!

Optimistic Concurrency Control — সমান্তরাল নিরাপত্তা

কল্পনা করো একসাথে দুজন user একই product কিনছে। দুজনেই stock কমাতে চায়। কিন্তু দ্বিতীয়জন প্রথমজনের update জানে না — তাই ভুল মান সেট হয়ে যায়!

সমাধান: _seq_no + _primary_term ব্যবহার করো

উদাহরণ
# প্রথমে document পড়ো — seq_no আর primary_term নোট করো
GET /products/_doc/2
// Response: { "_seq_no": 13, "_primary_term": 1, ... }

# এই values দিয়ে update করো — যদি মিলে তবেই update হবে
POST /products/_update/2?if_primary_term=1&if_seq_no=13
{
  "doc": { "stock": 8 }
}

# যদি কেউ এর মধ্যে update করে থাকে — Error আসবে:
// "version_conflict_engine_exception"
// এটা দেখেই বুঝবে — পুনরায় চেষ্টা করতে হবে নতুন seq_no দিয়ে

Text Mapping — ডেটার ধরন নির্ধারণ

Mapping হলো ES-কে বলা — কোন field কী ধরনের ডেটা রাখবে। MongoDB-তে এটা flexible ছিল, কিন্তু ES-এ Mapping গুরুত্বপূর্ণ কারণ এটা search-এর performance নির্ধারণ করে।

Data Types — ডেটার ধরন

Typeকী রাখেউদাহরণ
textসাধারণ লেখা — analyzer দিয়ে প্রসেস হয়product description, review
keywordহুবহু মেলাতে হবে এমন — analyzer নেইproduct ID, ইমেইল, ট্যাগ
integerপূর্ণ সংখ্যাstock count, age
floatদশমিক সংখ্যাprice, rating
dateতারিখ/সময়published_date
booleantrue/falseis_available
text vs keyword পার্থক্য:
text = "The quick brown fox" → ["the", "quick", "brown", "fox"] — আলাদা শব্দে ভাগ হয়, search-এ প্রতিটা শব্দ খোঁজা যায়
keyword = "The quick brown fox" → পুরোটাই একটা unit — শুধু exact match কাজ করে

Explicit Mapping তৈরি করো

Index তৈরির সময় Mapping দাও
PUT /masterclass
{
  "mappings": {
    "properties": {
      "theme": { "type": "text" },       // সাধারণ লেখা
      "duration": { "type": "integer" },  // পূর্ণ সংখ্যা
      "level": { "type": "text" },
      "animator": {                      // nested object
        "properties": {
          "first_name": { "type": "text" },
          "last_name": { "type": "text" },
          "email": { "type": "keyword" }  // exact match
        }
      }
    }
  }
}

Reindexing — Mapping বদলাতে হলে

ES-এ একবার Mapping দিলে পরে বদলানো যায় না (যেমন int থেকে text করা)। কারণ:

  1. সব ডেটা আবার re-index করতে হবে
  2. Shard routing system নষ্ট হয়ে যায়
  3. Production-এ সাময়িক অচলাবস্থা হয়

সমাধান: নতুন mapping দিয়ে নতুন Index তৈরি করো, তারপর ডেটা সেখানে copy করো:

Reindex Command
# পুরনো "reviews" থেকে নতুন "new_reviews"-এ copy করো
POST _reindex?wait_for_completion=false
{
  "source": { "index": "reviews" },
  "dest": { "index": "new_reviews" }
}

# Task-এর progress দেখো
GET _tasks?actions=*reindex&detailed

# পুরনো Index মুছো
DELETE /reviews

Python দিয়ে Bulk Import

bulk_script.py
from elasticsearch import Elasticsearch, helpers
import csv

# ES-এ connection করো
es = Elasticsearch(hosts="http://@localhost:9200")

# CSV পড়ো এবং bulk-এ import করো
with open('EmployerReviews.csv', encoding='utf-8') as f:
  reader = csv.DictReader(f)         # CSV-কে dictionary-র মতো পড়ো
  helpers.bulk(es, reader, index='reviews')  # bulk-এ পাঠাও

# মাত্র কয়েক লাইনে ২ লাখ+ row import হয়ে গেলো!

Analyzer — টেক্সট প্রসেস করার যন্ত্র

Elasticsearch-এর সবচেয়ে শক্তিশালী দিক হলো text search। কিন্তু "Quick" আর "quick" কি এক? "পড়ছি" আর "পড়া" কি সম্পর্কিত? এই জটিলতা সামলায় Analyzer।

তিনটি অংশ বিস্তারিত

🔤 Char Filters — অক্ষর পরিবর্তন

টেক্সট ঢোকার আগেই অক্ষর পরিবর্তন করে। যেমন: HTML tag সরানো, বিশেষ চিহ্ন রূপান্তর।

উদাহরণ
"Hello <b>World</b>" → "Hello World"  (HTML strip)

✂️ Tokenizer — শব্দে ভাগ করো

লেখাকে আলাদা শব্দে ভাগ করে। একটাই Tokenizer থাকে।

উদাহরণ
"Welcome to Datascientest!"
→ ["Welcome", "to", "Datascientest"]  (space tokenizer)

🔧 Token Filters — token পরিবর্তন

Token-এ আরো পরিবর্তন। lowercase, stopword বাদ দেওয়া, synonym যোগ।

উদাহরণ
["Welcome", "to", "Datascientest"]
→ ["welcome", "datascientest"]  ("to" stopword বাদ গেলো, lowercase হলো)

Built-in Analyzer পরীক্ষা করো

Analyzer test করো
POST /_analyze
{
  "text": ["Welcome to the GREAT world of Datascience!"],
  "analyzer": "standard"
}
// ফলাফল: ["welcome", "to", "the", "great", "world", "of", "datascience"]
// Standard analyzer: lowercase করে, punctuation সরায়

Custom Analyzer তৈরি করো

সম্পূর্ণ কাস্টম analyzer
PUT /custom_analyzer
{
  "settings": {
    "analysis": {
      "char_filter": {
        "chinese_mapping": {
          "type": "mapping",
          "mappings": ["数据科学 => datascience"]  // চীনা → English
        }
      },
      "filter": {
        "custom_stop": {
          "type": "stop",
          "stopwords": ["apprendre"],   // এই শব্দ সরিয়ে দাও
          "ignore_case": true
        }
      },
      "analyzer": {
        "my_custom_analyzer": {
          "type": "custom",
          "char_filter": ["html_strip", "chinese_mapping"],
          "tokenizer": "standard",
          "filter": ["lowercase", "custom_stop", "asciifolding"]
        }
      }
    }
  }
}
asciifolding কী? এটা non-ASCII character-কে ASCII-তে রূপান্তর করে। যেমন: é → e, ü → u। বিদেশী ভাষার অক্ষর normalize করতে কাজে লাগে।

Search — ডেটা খোঁজা

Elasticsearch-এর মূল কাজ search। এটা করা হয় DSL (Domain Specific Language) দিয়ে — JSON format-এ query লেখো।

Index Alias — সহজ নাম দাও

Alias তৈরি করো
# "new_reviews" কে "rev" নামে ডাকবো
POST _aliases
{
  "actions": [{
    "add": {
      "index": "new_reviews",
      "alias": "rev"
    }
  }]
}

# এখন এভাবে ব্যবহার করো
GET /rev/_search { "query": { "match_all": {} } }

১. Text Search (match) — বিশ্লেষণ করে খোঁজে

match query
# CompleteReview-এ "Great place to work" খোঁজো

match vs match_phrase:

match_phrase: শব্দগুলো এই ক্রমেই পাশাপাশি থাকতে হবে

৩. Boolean Query — শর্ত মিলিয়ে খোঁজো

সবচেয়ে শক্তিশালী search type — একাধিক শর্ত একসাথে ব্যবহার করো:

ClauseকাজScore-এ প্রভাব
mustঅবশ্যই থাকতে হবেScore বাড়ায়
must_notকখনো থাকবে নাবাদ দেয়
shouldথাকলে ভালো, না থাকলেও চলেScore বাড়ায়
filterঅবশ্যই থাকতে হবেScore-এ প্রভাব নেই
bool query উদাহরণ
# 2014 সালের horrible review — good/great শব্দ ছাড়া
GET /rev/_search
{
  "query": {
    "bool": {
      "must": [{
        "match": { "CompleteReview": "horrible" }
      }],
      "must_not": [{
        "terms": {
          "CompleteReview": ["good", "great"]
        }
      }],
      "filter": [{
        "range": {
          "Date": {
            "gte": "01-01-2014",
            "lte": "31-12-2014"
          }
        }
      }]
    }
  }
}

Score কী? — Relevance বোঝো

ES প্রতিটা ফলাফলে একটা _score দেয়। এটা বলে — এই document কতটা "relevant"।

Score গণনা হয় TF/IDF দিয়ে:
• TF (Term Frequency) = document-এ শব্দটা কতবার আছে (বেশি হলে বেশি relevant)
• IDF (Inverse Document Frequency) = সব document-এ শব্দটা কতটা বিরল (বিরল হলে বেশি important)

Python দিয়ে ES ব্যবহার

eval_elastic.py কাঠামো
from elasticsearch import Elasticsearch
import json

# Connection করো
client = Elasticsearch(hosts="http://@localhost:9200")

# Query লেখো (Kibana-র মতোই, GET statement ছাড়া)
query = {
  "query": { "match_all": {} }
}

# Search করো
response = client.search(index="eval", body=query)

# ফলাফল JSON ফাইলে save করো
with open("result.json", "w") as f:
  json.dump(dict(response), f, indent=2)

# Mapping দেখো
mapping = client.indices.get_mapping(index="eval")
with open("mapping.json", "w") as f:
  json.dump(dict(mapping), f, indent=2)
