🏗️ SAA পরীক্ষায় Architecture কীভাবে চিন্তা করবে?
SAA পরীক্ষায় scenario দেবে — তোমাকে সবচেয়ে ভালো solution বেছে নিতে হবে। চিন্তার framework:

1️⃣ Availability requirement — HA চাই না FT? SLA কত?
2️⃣ Scalability — Traffic কি বাড়বে-কমবে? Horizontal নাকি Vertical?
3️⃣ Cost — "Least expensive" কি requirement?
4️⃣ Operational overhead — "Least operational overhead" মানে managed service prefer করো
5️⃣ Security — Least privilege, encryption, private subnet

✅ SAA Key Architecture Patterns — Exam এ বারবার আসে

  • Multi-tier (3-tier) — Web (public subnet) → App (private) → DB (private)। Separation of concerns।
  • Microservices — Loosely coupled services। Lambda, ECS, API Gateway। Independent scaling।
  • Event-driven — SQS/SNS → Lambda। Decoupled। Async processing।
  • CQRS — Command/Query separation। Write DB আলাদা, Read DB আলাদা।
  • Disaster Recovery — Pilot Light, Warm Standby, Multi-Site, Backup & Restore।
PatternRTORPOCostUse Case
Backup & RestoreHoursHours💲 সস্তাNon-critical data
Pilot Lightমিনিটমিনিট💲💲Core systems

💡

Exam Tip: RTO = Recovery Time Objective (কত দ্রুত recover করবে)। RPO = Recovery Point Objective (কতটুকু data loss acceptable)। "Lowest RTO/RPO" = Multi-Site। "Lowest cost DR" = Backup & Restore।

🖥️ EC2 Instance Types — Family Mnemonics
General Purpose (t, m) — Balance compute/memory/network। Web servers, dev environments।
Compute Optimized (c) — CPU-intensive: Batch processing, HPC, gaming servers।
Memory Optimized (r, x, z) — Large RAM: In-memory databases, real-time analytics।
Storage Optimized (i, d, h) — High I/O: OLTP, data warehousing, Hadoop।
Accelerated (p, g, inf) — GPU: Machine learning, video rendering।

📦 EC2 Placement Groups EXAM
Cluster — একই rack এ instances। Ultra-low latency, high throughput। HPC, ML training।
🔴 Risk: Rack fail → সব fail।

Spread — আলাদা hardware এ instances (max 7 per AZ)। Critical applications। High isolation।

Partition — Groups of instances, আলাদা partitions। Hadoop, Cassandra, Kafka। Partition failure একটিতেই isolate।

📌 Exam: "Low latency inter-node communication" → Cluster। "Isolate hardware failures" → Spread

✅ EC2 Exam Must-Know Facts

  • User Data — Bootstrap script। Instance launch এর সময় একবার run। Install software, update configs।
  • Instance Metadata — http://169.254.169.254/latest/meta-data/ — instance info (IP, IAM role name)।
  • Hibernate — RAM এর contents EBS এ save। Fast restart। RAM ≤150GB। EBS encrypt করা থাকতে হবে।
  • Instance Store — Physically attached। Ephemeral (stop/terminate করলে data হারায়)। Very fast I/O।
  • ENI — Elastic Network Interface। একাধিক ENI attach করা যায়। Failover এ ENI move করা যায়।
💡

Exam Tip: Spot Instances ব্যবহার করতে পারবে এমন workloads: Batch processing, Big Data, CI/CD testing, image rendering। Spot block = specific duration। Spot Fleet = mix of Spot + On-Demand।

📈 Auto Scaling Policies
Target Tracking — সবচেয়ে সহজ। "CPU 50% তে রাখো" — AWS নিজেই scale করে। Recommended।

Step Scaling — CloudWatch alarm triggers করলে steps এ scale। "CPU 70% → +1, CPU 90% → +3"।

Simple Scaling — একটি alarm → একটি action। Cooldown শেষ হওয়ার পর পরবর্তী action।

Scheduled Scaling — Known patterns এর জন্য। "প্রতি সকাল ৯টায় ১০টি instances"।

Predictive Scaling — ML দিয়ে future traffic predict। Proactive scaling। Load pattern analyze করে।

✅ ASG Key Concepts — Exam এ আসে

  • Launch Template — AMI, instance type, SG, User Data সব একসাথে। Launch Configuration এর modern replacement।
  • Health Checks — EC2 health check (default) বা ELB health check। Unhealthy → terminate ও replace।
  • Lifecycle Hooks — Scale-out/in এ custom actions। "instance চালু হওয়ার আগে software install করো"।
  • Warm-up time — নতুন instance fully ready হতে কতক্ষণ। এই সময় scaling metrics এ count হয় না।
  • Termination Policy — Scale-in এ কোন instance আগে terminate? Default: oldest Launch Config থেকে।
💡

Exam Tip: ASG সবসময় Multi-AZ deploy করো — AZ failure এ instances অন্য AZ তে launch হবে। ELB এর সাথে integrate করলে health check automatically হয়।

🎯 ELB Key Features EXAM
SSL/TLS Termination — ALB/NLB SSL certificates manage করে। ACM (free) বা IAM certificates। Backend HTTP এ pass করে।

Sticky Sessions — Same user সবসময় same target এ যায়। Cookie-based। ALB এ "AWSALB" cookie।

Cross-Zone Load Balancing — ALB তে default on। NLB তে default off। সব AZ এর instances এ evenly distribute।

Connection Draining (Deregistration Delay) — Instance unhealthy হলে existing connections finish করতে দেয়। Default 300s।

Health Checks — Unhealthy instances কে automatically routing থেকে remove করে।

✅ NLB এ Static IP কেন দরকার?

  • NLB এ Elastic IP assign করা যায় — firewall rules এ whitelist করা যায়।
  • ALB এর IP dynamic (DNS দিয়ে access করতে হয়)।
  • Exam: "Static IP দরকার for load balancer" → NLB।
  • Exam: "Layer 7, microservices, path routing" → ALB।
💡

Exam Tip: ALB = microservices, path-based routing, HTTP/HTTPS। NLB = TCP, UDP, ultra-low latency, static IP needed। GWLB = third-party security appliances (Palo Alto, Fortinet)।
